访存多拍，前递源的生命周期要重算
DCache：16 行 × 4 字（512 字节），写穿不分配

取指有了缓存，访存这一集跟上。数据缓存一接上，访存就从"组合出数"变成"可能占住 MEM 多拍"——流水线的冻结范围要重画，前递源的生命周期要重新界定：停在 EX 的消费者手里那份 ID 拍的锁存值，可能比源还老。另有两件新事：store 的语义（写穿 + miss 不分配）与"一笔在途事务"的握手。

数据侧的三件事

指令侧只需要"读"，数据侧要复杂得多：写、原子读改写、设备访问。所以缓存口径先定死三句话（设计稿第 3、4 节的原文口径）：

prismwhitebow/iu/dcache.prism · 头注节选
// 语义口径（设计稿 docs/whitebow-dcache-design.md 第 3、4 节）：
//   写穿 + store miss 不分配 + 无 store buffer。缓存侧只做三件事：命中组合出字、
//   store/AMO 命中时边沿改线、load miss 时逐字填充。写穿那一下（dm_wen）在 LSU
//   手里，不在这里——内存与线在同拍更新，一致性靠"同拍"而不是靠 clean。
一句注释漂移，照实指出 头注这句"无 store buffer"是旧口径——代码里已经有一项 store buffer（掩盖 store miss 的读改写延迟），注释没跟上。判据按代码算，注释与代码的这处偏差登记在案。

地址口径与指令侧同款但单位不同：64 位字索引（PA[39:3]），三段互不重叠——标签 [36:6]、行号 [5:2]、行内字 [1:0]。

一次 load miss：检出拍就拉 busy

填充还是四拍取一行；容易看漏的是第一拍——load miss 的检出拍就要拉 busy：那拍序列器还在 IDLE，只按"填充中"算会让检出拍的沿上 EX/MEM 放行，load 会在填充完成前就离开 MEM。

prismwhitebow/iu/dcache.prism · 序列器、命中与起手
    fsm ctrl {
        states : IDLE, F0, F1, F2, F3
        reset  : IDLE

        IDLE: start -> F0           // load miss 才起手（命中 / store / 设备不拉 start）
        F0:   _ -> F1
        F1:   _ -> F2
        F2:   _ -> F3
        F3:   _ -> IDLE             // 一行取齐，valid 已在 F3 沿落位
    }

    // ---- 地址分解 ----
    wire index : u4  = cpu_addr[5:2]
    wire tag   : u31 = cpu_addr[36:6]
    wire word  : u2  = cpu_addr[1:0]

    // ---- 命中判定 ----
    wire entry : u32 = tags[index]
    wire hit   : u1  = ctrl.is(IDLE) & !cpu_nc & entry[31:31] & (entry[30:0] == tag)
    wire filling : u1 = !ctrl.is(IDLE)
    // load miss 的检出拍就要拉 busy：那拍 fsm 还在 IDLE，只取 filling 会让
    // 检出拍的沿上 EX/MEM 放行，load 在填充完成前离开 MEM。
    wire start : u1  = ctrl.is(IDLE) & cpu_req & !cpu_nc & cpu_ren & !cpu_wen & !hit

占用的形状与多拍除法器同款、整体差一级（第 13 集那张表里"dcache 占用"一行）：冻 PC / IF-ID / ID-EX，EX/MEM 保持（load 就在里面等填充），MEM/WB 也保持——原因见下一节。

前递源的生命周期：源必须比消费者留存更久

这是这一集真正的易错点，也是修完之后写进代码的纪律：

prismwhitebow/iu/hazard.prism · 占用与前递源生命周期
//   dcache 占用：load 在 MEM 未命中要占到填充完。冻 PC/IF-ID/ID-EX，EX/MEM **保持**
//             （load 就在里面等填充），MEM/WB 也**保持**——不往它灌气泡：要等的东西在
//             MEM 里，它前面那条正被 EX 里那条消费，一旦被气泡顶掉，释放沿就没有前递
//             源了，EX 只能退回它在 ID 拍锁存的陈旧操作数（div 占用没这个洞：它的消费者
//             还在 IF/ID 里，每拍重读寄存器堆）。提交侧由 MemWb 的 commit 脉冲保证冻
//             多少拍也只退休一次。与 trap 同拍时 hold_exmem 让位（= (src_dmiss |
//             src_mmiss) & !src_trap）：hold 会压掉同拍的 kill，而 trap 必须杀 EX/MEM 才能精确异常。
//
// 前递优先级：EX/MEM（更年轻）压 MEM/WB。前递的数据是"已选好的写回值"
// （顶层从 mem_wb_data 取，load 的读数据也在其中）；load-use 停顿保证消费者
// 进 EX 那一拍 load 已到 MEM/WB，这条路径只负责寄存器结果的分发。
// 前递源**活得比消费者久**是这条路径的隐含前提：占用级停顿（dcache）一旦只冻到自己
// 那一级、而让 MEM/WB 继续被气泡顶掉，停在 EX 的消费者就没有源可取了——它手里那个
// ID 拍的锁存值可能来自更早的一次写。所以占用期 MEM/WB 保持，提交交给 commit 脉冲。

探针把这件事钉成两发反证，数字都是手算的：

  • 反证① 摘掉 MEM/WB 的冻结：检出拍的下一沿它就被气泡顶掉，释放沿只能退回 ID 拍锁的陈旧值——探针里 x15 实得 99，手算期望 7。
  • 反证② 把提交脉冲退化成"条目在场"：冻结期间同一条指令反复退休。

两发反证有个共同的阴险之处：同源 cosim 全部无感——golden 与 RTL 读的是同一条判据，一起错。只有按镜像手算的期望值才能暴露这类错误，这也是这一集把"前递的账"单独立一节的原因。

写与直达：写穿、不分配、nc 旁路

写侧的三个决定各有明确的替代品，选它们的理由也各有来处：

  • 写穿：store 命中时"边沿改线"，同一拍后备内存也更新（那一下 dm_wen 在 LSU 手里）——一致性靠"同拍"，缓存里没有 clean/dirty 这一套状态。
  • store miss 不分配：store 未命中不去填行，直走后备口读改写——省一次只有一半用处的填充。
  • 设备直达（nc）：cpu_nc=1 时"不查、不填、不写线"，后备读数据原样透出——外设寄存器的读写语义不允许被缓存改写。
prismwhitebow/iu/dcache.prism · 组合输出与写口
    // Store Buffer 前递：load 命中 SB 地址时直接取缓冲数据（store miss 时不进 SB，
    // 避免读改写拿到新值而非旧值）。SB 仅在非写请求时前递。
    wire sb_hit    : u1  = sb_valid & (sb_addr == cpu_addr) & !cpu_wen
    lsu_rdata = sb_hit ? sb_data : (hit ? line_word : mem_rdata)
    busy      = start | filling
    // 后备读口三种开法：填充逐字；设备访问全程旁路；可缓存的 store/AMO miss
    // 要读改写旧值。load miss 的检出拍不开——填充从下一拍起逐字读，不重复取。
    // store/AMO 命中不开：旧值从线里组合读。SB 命中时也不开后备口。
    mem_ren   = filling | (cpu_ren & (cpu_nc | (!hit & !sb_hit & cpu_wen & !filling)))
    mem_addr  = filling ? r_addr : cpu_addr

一笔在途事务：握手的口径是"属于谁"，不是"忙不忙"

缓存还有第二个发起方：页表走查（PTW）与数据通路共享这颗缓存。两个发起方轮着用，就必须记录"这笔事务属于谁"。握手的三个信号把口径钉死：

prismwhitebow/iu/dcache.prism · 事务握手
    // ---- 事务握手 ----
    // serving=本拍缓存手里有一笔发起方还认账的事务（刚 grant，或在途且 req 仍举着）；
    // 发起方撤 req 就是撤事务——被冲刷掉的那条访存不该再收到 rvalid。
    // answerable=这一拍该事务能闭合的三种情形：命中出数、设备旁路出数、写（含字节
    // 车道的读改写）落地。load miss 不属于任何一种，它要等填充回到 IDLE 命中那一拍。
    wire free       : u1 = ctrl.is(IDLE) & !own
    wire gnt        : u1 = cpu_req & free
    wire serving    : u1 = gnt | (own & cpu_req)
    wire answerable : u1 = hit | cpu_nc | cpu_wen
    cpu_gnt    = gnt
    cpu_rvalid = serving & answerable

为什么值得这样啰嗦：rvalid 如果退化成"本拍看起来不忙"，会有一处极窄的隐患——翻译落定那一拍，缓存刚从 PTE 填充回到 IDLE，!busy 短暂成立、却对应上一笔的地址，把 PTE 残值当操作数收下。用"属于 grant 过的那笔"做口径，这个坑在结构上不可能出现。

判据：44 拍 × 6 列，四发反证 + 两发核级探针

验收台 44 拍 × 6 列，六条判据都手算进行内期望：冷 miss 逐字填、行内换字全命中、store 命中改线、store miss 不分配、冲突换行、nc 旁路；后两列是握手的 gnt / rvalid 拍序。

读表指路：拍 8–12 冷 miss——检出拍（8）就拉 busy，四拍逐字填充（9–11），第 12 拍 rvalid 出数；拍 13–15 行内换字全命中；拍 16–17 store 命中改线——写那一拍 lsu_rdata 交回旧值 8738，下一拍再读已是新值（写穿：线同拍更新）；拍 30–33 设备旁路——nc=1 时 mem_ren 开着直通后备，rvalid 当拍闭合、全程无 busy。

验收台之外另有四发反证，各打一根承重柱：store 命中不写线（改线那一根断）、命中丢掉 valid 位（半行也被当命中）、rvalid 退化成"看着不忙"（未 grant 也置起 rvalid）、gnt 丢掉在途所有权（同一笔 grant 两次）。再加核级探针两发（前递源与提交脉冲，见上一节）。

小结

  • 数据缓存：16 行 × 4 字（512 字节）直接映射；命中组合出字，load miss 逐字填充一行，检出拍即拉 busy。
  • 写侧口径：写穿（同拍更新内存与线）、store miss 不分配、nc 旁路；另有一项 store buffer 前递。
  • 前递源必须活过消费者：占用期 MEM/WB 保持 + 提交走 commit 脉冲——两发反证（陈旧值 99 vs 7、反复退休）证明这两根柱子各自承重。
  • 握手的口径是"属于谁"：serving & answerable，不是"看着不忙"——为 PTW 与数据共享缓存留出结构性安全。
  • 判据：44 拍 × 6 列行内全等 + 同源 cosim 全等 + 反证四发 + 核级探针两发。
