取指不再等存储器
ICache：16 行 × 4 字的直接映射

第五日开工。取指原来每拍直接穿到指令 SRAM——取指的节奏被存储器绑着。这一集加一层 16 行 × 4 字（256 字节）的直接映射缓存：命中在本地小阵列上组合出数，miss 只补一行四字，失效只由 fence.i 触发——规范里那条"取指看到的指令变了"的扳机，不做猜测式失效。

为什么给取指加一层缓存

取指口原来直连指令 SRAM：每一拍一次完整的存储访问，地址进去、数据出来。单口 SRAM、访问时间、以及后面要接的更宽取指与更远的后备，全都直接压在这条链上。加一层小的本地缓存之后：命中只碰本地阵列（256 字节，组合读出、同拍出数）；miss 一次取回一整行（4 个字，供四条指令用）；取指的节奏与后备存储器的节奏解耦。

形态是直接映射，三个字段各管一段：

prismwhitebow/iu/icache.prism · 头注节选
// =============================================================================
// icache.prism — 指令缓存（直接映射，16 行 × 每行 4 字）
//
// 容量 64 字 = 256 字节；行大小 4 字（16 字节，装得下 4 条标准指令或 8 条 RVC）；
// 直接映射，无替换策略；命中组合读出（同拍出，与 im 的 1RW 口径一致）。
字段位段宽度管什么
标签 tagcpu_paddr[37:6]32 位这一行属于哪个物理块（比较的对象）
行号 indexcpu_paddr[5:2]4 位落进 16 行里的哪一行
行内字 wordcpu_paddr[1:0]2 位这一行 4 个字里的第几个

两个决定：标签存物理页号、读口恒开

头注里把两个决定写得很直白——它们决定了缓存与翻译、与上游的边界：

prismwhitebow/iu/icache.prism · 读口与交接
// 读口恒开（组合读无副作用），写口只在填充期开：一拍取一行里的一个字，
// 四个沿走完 F0..F3 把 4 个字逐个落进 data，最后一个沿才置 valid——
// 半行的数据永远不会被当成命中读走。
//
// 与 IFU 的交接：cpu_ready 为 0 就是 miss，IFU 用它冻住 pc 与 IF/ID，
// 所以 miss 期间 cpu_paddr 保持不变，填完回到 IDLE 时同一个地址必然命中。
  • 标签存物理页号，不是虚页号：sfence.vma / 写 satp 不必清本缓存——行属于哪个物理块是明确的，翻译改了那份指令字没变；会变的是"这条虚地址能不能取指"，那是 ITLB 的事（与 C910 一样，把 TLB 失效与缓存失效解耦）。失效只剩一个扳机：fence.i。
  • 索引落在页内偏移里（整缓存 256B < 4KiB）：同一物理块永远落同一行，不存在"两个虚页映射到同一物理块却各存一份"的别名问题。
  • 地址口收 PA 全宽（u38 的 32 位字索引 = PA[39:2]）：高位不许被悄悄折回低地址——这条在实测中暴露过，见下面的判据 ④。

一次 miss：四拍取一行

控制序列器六个状态：空闲、四拍填充、失效扫描。

prismwhitebow/iu/icache.prism · 控制序列器
    fsm ctrl {
        states : IDLE, F0, F1, F2, F3, CLR
        reset  : IDLE

        IDLE: flush -> CLR    // 失效优先于取指（含命中拍）
        IDLE: !hit  -> F0     // miss：起手取该行第 0 个字
        F0:   flush -> CLR
        F0:   _     -> F1
        F1:   flush -> CLR
        F1:   _     -> F2
        F2:   flush -> CLR
        F2:   _     -> F3
        F3:   flush -> CLR
        F3:   _     -> IDLE   // 一行取齐，valid 已在 F3 沿落位
        CLR:  clr_last -> IDLE   // 16 行走完
    }

填充期里 cpu_ready 恒 0——上游（IFU）据此冻住 pc 与 IF/ID，所以 cpu_paddr 在整个 miss 期间保持不变，填完回到 IDLE 时同一个地址必然命中。命中判定卡得很死：

prismwhitebow/iu/icache.prism · 命中与写口
    // ---- 命中判定 ----
    // 只有 IDLE 才算命中：填充/失效中途 tags[index] 正在被改写，
    // 而 pc 冻在 miss 的那个地址上，此时给出去的是半行的数据。
    wire entry    : u33 = tags[index]
    wire hit      : u1  = ctrl.is(IDLE) & entry[32:32] & (entry[31:0] == tag)
    wire filling  : u1  = !ctrl.is(IDLE) & !flushing

    // ---- 单一写口：地址二选一，数据在写点处 mux ----
    wire wa       : u4  = flushing ? r_clr : r_line

一个写口：填充与失效在入口 mux

两个阵列各自只有一个写口：data 只在填充期写；tags 由填充末拍与失效扫描共用——在入口 mux 成同一根地址。这条纪律的一个直接后果是"一行四字齐了才置 valid"：

prismwhitebow/iu/icache.prism · 时序节选
        // 单一写口：一行四字齐了才置 valid；失效扫描按 r_clr 逐行清 0
        if (ctrl.is(F3) | flushing) {
            tags'[wa] = flushing ? 0 : (0x100000000 | r_tag)
        }
        if (ctrl.is(F3)) {
            r_off' = 0
        }
        // 失效：进门先归零，随后每拍走一行，16 拍走完
        if (flush & !flushing) {
            r_clr' = 0
        }
        if (flushing) {
            r_clr' = r_clr + 1
        }

还有一条容易忽略的纪律：tags 与 data 都带全 0 初值。无初值的 mem 复位不装载，上电第一拍读 valid 位拿到 x，命中判定跟着变 x，序列器守卫也是 x——缓存根本起不来。全 0 就是"所有行都无效"。

fence.i：唯一扳机，16 拍扫描

自修改代码、换镜像、写内存再跳过去——这些场景里"取指看到的指令变了"这件事，规范用一个显式扳机来通知：fence.i。本集把它落成一条 16 拍的全清扫描：进门先归零，随后每拍清一行，失效优先级最高（包括填充中途）——填一半的行被清掉，半有效的块永远不会被读走。扫描期间 cpu_ready 恒 0，上游随之冻结。

为什么不做"猜"：缓存里存的是指令字，它们只可能被"写到同一物理地址"改掉；那件事发生时，软件有义务发一次 fence.i。硬件顺着猜（比如嗅探所有写）要付出通路的代价，而收益取决于软件并不存在的习惯。判据先立，扳机后说：写这一集时"失效路径按 B 落地"就是这条纪律的另一个名字。

判据：三条承重，一条不承重

验收台把 ICache 接上一颗带程序镜像的 SRAM；期望值按镜像手算（词 0..3 与 64..67），不是从模块转录。行内期望 28 拍 × 3 列：

读表要按三种情景看：拍 0–4 冷 miss 正好 4 拍不 Ready（F0..F3 取齐一行），第 5 拍命中；拍 5–7 同一行内换行内字，全部命中——一次填充供四条指令；拍 8–12 pc=0x40（行号 16 → 下标 0、标签 1）顶掉标签 0 的那行，拍 13 起回手再取 pc=0 必须重新 miss——valid 真的按行归属；拍 23–27 是判据 ④：0x4000_0000 与 0x0000 行下标相同、只差 tag 里的一位，必须 miss 填自己的行（地址口收窄过一次，这十拍就是那一刀的证据）。

两条表都配了同源 cosim（golden vs RTL：28 拍 × 6 列、37 拍 × 3 列全等），另有三条各自承重的反证注入（沙箱副本，真源码未改）：

反证注入必须红在哪
nofill填充末拍不置 valid（去掉 0x1_0000_0000 那一项）永远不命中——ready 一列
hitag_aliastag 切到 PA[29:6]（收窄地址口）0x4000_0000 直接命中、拿走低地址那行的字——④ 那十拍
shortfillF3 那拍不写（少走一拍）行末那个字永远不落——行内字与跨字窗口读成 0
一条刻意不列为判据的边界（诚实注记） 命中判定里 ctrl.is(IDLE) 那一项没有列进反证——两个样本都打不出红：填充/扫描期间 pc 冻在 miss 的地址上，旧行的标签必然对不上，掐掉这一项行为不变。要让它暴露需要"填充中途被重定向到一个恰好有效的行"，现有激励没有这种形状；把它当判据就是假覆盖。判据宁可少一条，不可以有一条不承重。

小结

  • 取指加一层 16 行 × 4 字的直接映射缓存：命中同拍出数；miss 四拍补一行，供四条指令。
  • 标签存物理页号 ⇒ sfence.vma 不清缓存；失效唯一扳机是 fence.i（16 拍扫描，优先级高于取指与填充）。
  • 两个阵列各一个写口；一行四字齐了才置 valid；tags/data 带全 0 初值（否则上电读 x，缓存起不来）。
  • 判据：28 拍 × 3 列 + 37 拍 × 1 列行内全等、同源 cosim 全等、三条反证各红自己的列——外加一条"不承重就不列"的边界注记。
