把两拍惩罚藏起来
BTB + BHT：按 PC 预测，取指段不解码

分支在 EX 段定案——从 IF 追到 EX 之间的两拍，猜不猜都要罚。这一集把"猜"搬进取指段：两张大表（各 2048 项）按 PC 查，取指段不掺译码。怎么养表、误预测怎么算、以及为什么索引粒度必须是 2 字节（一条 RVC 分支事故）——全在代码里。

两拍代价：不预测也要付，误预测才翻倍

第 14 集留下的结构是这样：分支/JAL 在 EX 段才算出方向与目标，而取指在 IF——中间隔着 ID。等结果出来，已经多取了两条指令：固定两拍惩罚。不预测，这两拍照样付出；误预测则翻倍（还要冲掉多取的两条）。

把"猜"搬到 IF 段，就是要在这两拍里先按预测走。收入对照在同一窗口里量过：OpenSBI 固定 600 拍窗，开着预测退休 472 条，关掉预测只有 408 条（IPC 0.787 vs 0.680）。

两件事分开存：目标与方向

头注把表结构写得很直：

prismwhitebow/iu/bpredictor.prism · 头注节选
// bpredictor.prism — 分支预测器（BTB + BHT，按 PC 预测，取指段不解码）
//
// 两件事分开存，都是 2048 项、按 PC 索引：
//   BTB 回答"这个 PC 上有没有一条要跳的指令、跳到哪儿"——方向为 taken 的前提；
//   BHT 回答"这条分支上次跳没跳"——2 位饱和计数器，[1]=1 预测 taken。
// 取指段只用 PC 查表，不需要知道当前取的是不是分支：表项是分支**定案时**按自己的
// PC 写进去的，下次再取到同一个 PC 就直接照表跳。所以 IF 段不掺译码，译码仍在 ID。
//
// 索引与标签（PC 是字节地址）：
//   index = pc[11:1]（11 位，2048 项，2 字节粒度）  tag = pc[31:12]（20 位）
// 只比 index 会让 4KB 之外的两个 PC 撞进同一项，所以命中必须连 tag 一起判。
// 粒度按 2 字节：RVC 让两条指令能挤在同一个字里，按字索引会把它们并成一项——
// 实测那条 c.bnez 命中了邻居 c.beqz 的表项，带着错误目标把 PC 甩了出去。
// index+tag 合起来覆盖 pc[31:1]（除恒零的 bit0 之外全是身份），所以同一台机器里
// 不存在"别的 PC 冒充这一项"；表项内容会过期只剩一种可能：那个 PC 上的指令被改了。
// 那件事由 EX 比对预测目标兜住（见 exu 的 mispredict），不靠这个巧合。

三条纪律顺着头注读出来：命中（BTB）与方向（BHT）是两张表的判断——"表里有这条分支但上次没跳"必然是预测不跳，BHT 不是装饰；命中必须连 tag 一起判（只比 index 会让 4KB 之外的两个 PC 蹭同一项）；过期只可能来自"那个 PC 上的指令被改"，那件事由 EX 比对预测目标兜住，不靠索引覆盖做巧合。

怎么养表

prismwhitebow/iu/bpredictor.prism · 表怎么养
// 表怎么养：
//   - 条件分支：跳 +1、不跳 -1，饱和在 0/3；复位值 00（强不跳），冷启动一律预测不跳，
//     同一条分支要连跳两次才翻到"预测跳"；
//   - JAL：恒跳，定案时直接把计数器按到 3；
//   - JALR：不进表——它的目标来自寄存器，PC 学不出来，要靠返回栈才能预测，
//     调用方当拍就不要拉 upd_en。

2 位饱和计数器的意义都在"连跳两次才翻向"上：复位值 00（强不跳），跳 +1、不跳 -1，顶在 11、底在 00。冷启动一律预测不跳——第一次遇到就猜跳，十有八九要赔。JAL 是恒跳，定案时一次按到 11；JALR 则自知学不出来：它的目标来自寄存器，PC 上没有任何规律可背，要靠返回栈才能预测——所以调用方当拍干脆不拉 upd_en。

交接：IF 查表、EX 定案、误预测走 src_br

prismwhitebow/iu/bpredictor.prism · 与流水线的交接
// 与流水线的交接（调用方的责任）：
//   IF 段：pred_taken 且取指就绪时把 PC 装载成 pred_target，并把 pred_taken 与
//          pred_target 一起随这条指令带进 ID/EX；
//   EX 段：实际方向与预测不符，或预测跳而目标与算出来的不符，就是误预测，
//          交 hazard 的 src_br 冲刷。

误预测的定义有两半，缺一不可：方向与预测不符（该跳没跳、不该跳跳了），或者预测跳而目标与 EX 算出的不符。两者都并进 hazard 既有的 src_br——不新开冲刷通道，第 13 集那张十源表里的"冲刷源"就这么一位一位长齐的。

查询与写表：一段组合、一段沿后

prismwhitebow/iu/bpredictor.prism · 查询与定案写表
    wire f_idx     : u11 = fetch_pc[11:1]
    wire f_tag     : u20 = fetch_pc[31:12]
    wire f_ctr     : u2  = bht[f_idx]

    // ---- 定案写表 ----
    wire u_idx     : u11 = upd_pc[11:1]
    wire u_tag     : u20 = upd_pc[31:12]
    wire u_ctr     : u2  = bht[u_idx]

    // ================= 对外端口赋值 =================
    // 命中 = valid 且标签对得上；方向再由计数器给。两张表分开判，所以"表里有这条
    // 分支但上次没跳"必然是预测不跳——BHT 不是装饰。
    pred_taken  = btb_v[f_idx] & (btb_tag[f_idx] == f_tag) & f_ctr[1:1]
    pred_target = btb_tgt[f_idx]

    // ================= 时序 =================
    on clock {
        if (upd_en) {
            btb_v'[u_idx]   = 1
            btb_tag'[u_idx] = u_tag
            btb_tgt'[u_idx] = upd_target
            // 计数器饱和：跳 +1、不跳 -1，顶在 11 底在 00；JAL 恒跳，一次按到 11。
            bht'[u_idx] = match {
                !upd_is_br                 => 3,
                (upd_taken & (u_ctr < 3))  => (u_ctr + 1)[1:0],
                (!upd_taken & (u_ctr > 0)) => (u_ctr - 1)[1:0],
                _                          => u_ctr,
            }
        }
    }
}

查询侧一行看全：pred_taken = btb_v[f_idx] & (btb_tag[f_idx] == f_tag) & f_ctr[1:1]——valid、标签、方向三个条件全就位才预测跳。写侧跟表里读到的旧值比（u_ctr），饱和靠 match 的四条臂兜住，没有回卷。

那条 RVC 分支事故：粒度为什么是 2 字节

最先的版本按字索引。RVC 一进来就出事：两条指令能挤在同一个 32 位字里，按字索引就把它们并成同一项——实测里 c.bnez 命中了邻居 c.beqz 的表项，带着错误目标把 PC 甩了出去。改成按 2 字节索引（pc[11:1]）之后，相邻的压缩分支各占一项。

这条事故后来变成判据 ⑦ 的形状：养 0x1002 连跳两次，回手读 0x1000 必须仍是它自己的旧状态（方向 00、目标 0x8000）——按字索引会让这两条并项。粒度这件事不靠"大厂怎么写"背书：它是这颗核的回归判据。

判据：21 拍七条各自承重

行内期望 21 拍 × 2 列（方向、目标），表里是沿后值——拉 upd_en 那一拍读到的还是旧表，下一拍才看见新养成的项：

对着表读七条：拍 0 冷项不跳、目标也是 0；拍 1–2 连跳两次才翻向（00→01 不跳，01→10 才跳）；拍 3–5 顶到 11 后仍钉在 11；拍 6 同 index 不同 tag（0x1000000 与 0x1000 都落在 index 0）必须 miss——而且要在这一项是 taken 时查，否则摘掉比较也读不出差别；拍 8–12 连撤两次翻回不跳、但 BTB 仍命中、目标照给；撤到 00 后再撤仍钉在 00（若回卷成 11，第 12 拍就会预测跳）；拍 13–15 JAL 定案一次按到 11；拍 16–20 相邻压缩 PC 0x1002 与 0x1000 各占一项。

三发反证打三根柱子：拿掉饱和守卫（计数器回卷）、拿掉标签比较（4KB 之外二次命中）、查询索引退回按字（相邻 RVC 并项）。三发都判在行内期望上——同源 cosim 一律无感，只有手算期望才能暴露它。cosim 侧另有 21 拍 × 4 列全等。

小结

  • 两拍代价：不预测也要付两拍，误预测翻倍——预测搬进 IF 段（不掺译码）；600 拍窗实测 472 vs 408 条退休。
  • BTB 管目标与命中、BHT 管方向（2 位饱和，复位 00）；命中与方向分开判；JALR 不进表（目标学不出来）。
  • 索引粒度 2 字节是那条 RVC 事故的判决：c.bnez 蹭了 c.beqz 的表项——粒度是回归判据。
  • 误预测 = 方向不符 ∨ 预测目标不符，并进 src_br；判据 21 拍七条 + 反证三发，全部落在手算行内期望上。
