S / U 能访问哪段物理内存
PMP：16 个条目的区间与权限寄存器面

上一集虚拟地址成立了——但"翻到哪"与"许不许翻"是两件事。进 M 态之外，每一笔取指与访存都该先过一道物理内存保护：16 个条目，每条一段区间加一组权限。这一集先把寄存器面装上：两条 pmpcfg、16 条 pmpaddr、按条目的锁定与 WARL——匹配判决的接线边界，照实讲在最后一节。

"也要管理地上各样行动的活物。" —— 《创世记》 1:28

谁需要这道门

MMU 管的是"虚拟地址翻到哪个物理地址"——它翻译，但不挑拣。真正回答"S 态与 U 态能访问哪段物理内存"的是另一套机构：PMP（物理内存保护）。规则的形状很朴素：16 个条目，每条给一段区间与一组 R/W/X 权限；M 态默认全通，M 之外的访问先过它——连页表遍历也算（按 S 的访问裁决）。

头注把规范口径逐行摆开（本集交付的是它的寄存器面，见最后一节）：

prismwhitebow/iu/pmp.prism · 规范口径
// 规范口径（§3.7）：
//   pmpcfg 位段   bit7=L，[6:5] 保留读零，[4:3]=A，bit2=X，bit1=W，bit0=R
//   RV64 只有偶号 pmpcfg0（条目 0-7）、pmpcfg2（条目 8-15）…，**奇号是非法 CSR**
//   条目数        实现可选 0/16/64，本核 16；低位条目必须先实现
//   保留组合      R=0 而 W=1 不允许存在 ⇒ 写入时清掉 W
//   L 锁定        置 1 后该条目（cfg 与 addr 都算）在本条目内不可再改，直到复位
//   pmpaddr       RV64 存 PA[55:2]；本核 PA=40 位 ⇒ WARL 只收 [37:0]，其余位读零
//   匹配          OFF 不匹配；TOR = 上界（下界＝前一条目的 addr，条目 0 下界 0）；
//                 NA4/NAPOT 都是 4 字节粒度（pmpaddr 低位连续 1 的个数定区域大小）
//   生效特权      <M 的访问才查（含页表遍历，按 S 算）；M 态默认全通（MMWP/MML 属
//                 mseccfg＝Smepmp，本步不做）
//   违例           取指 cause 1 / load cause 5 / store·AMO cause 7，精确定位

16 个条目怎么放：两个标量、一张阵列

存储形态的选择被写口数量逼出来了：一次 pmpcfg0 写要同时动 8 个条目——那是 8 个写口，mem 只有一个，所以 cfg 只能放标量 reg（一份 64 位里逐字节并行落位）；pmpaddr 一拍最多写一项，放阵列里——反正匹配侧要 16 路并行组合读，阵列读是免费的。

prismwhitebow/iu/pmp.prism · 号→存储只译一次
    // ---- CSR 侧：号→存储单元只在这里译一次 ----
    in  csr_addr  : Signal<u12>
    in  csr_wen   : Signal<u1>      // csr 已把"这条 CSR 指令真的该写"算好（含特权门与 rs1≠0）
    in  csr_wdata : Signal<u64>
    out csr_rdata : Signal<u64>
    out is_pmp    : Signal<u1>      // 这个 CSR 号归 PMP（csr 用它上白名单，不再列第二份号表）

    // 一次 pmpcfg0 写要同时动 8 个条目＝8 个写口 ⇒ cfg 只能放标量 reg（mem 一个写口）；
    // pmpaddr 一拍最多写一项 ⇒ 放阵列里，匹配侧要 16 路并行组合读，阵列读是免费的。
    reg  r_pmpcfg0 : u64 = 0
    reg  r_pmpcfg2 : u64 = 0
    mem  r_pmpaddr : [16] u64 = 0

    wire is_cfg0  : u1 = csr_addr == 0x3A0
    wire is_cfg2  : u1 = csr_addr == 0x3A2
    wire is_paddr : u1 = (csr_addr >= 0x3B0) & (csr_addr <= 0x3BF)
    is_pmp    = is_cfg0 | is_cfg2 | is_paddr
    csr_rdata = is_cfg0 ? r_pmpcfg0 : (is_cfg2 ? r_pmpcfg2 : (is_paddr ? r_pmpaddr[csr_addr[3:0]] : 0))

这段代码还有一个结构性决定：号表单点化。号→存储的译码、白名单的手续全在 pmp 体内，对外只报一根 is_pmp；CSR 的白名单直接引用它，不再列第二份号表——号只译一次，白名单与存储就不会分叉。

cfg 落位的两条纪律，用位并行写

prismwhitebow/iu/pmp.prism · cfg 写入
    // ---- cfg 写入的两条落位（一份 64 位里 8 个条目，逐条目并行算）----
    // 1) 每条目只收 L|A|X|W|R（0x9F）；R=0 而 W=1 是保留组合 ⇒ **W 只在 R=1 时保留**：
    //    先把所有 W 位清掉（~0x02 掩），再把"R 位左移一位"与原 W 位相与放回去。
    // 2) 锁定：只看**旧值**里 L=1 的条目（这一拍写进去的 L 当场生效、下一次才挡）⇒ 那一
    //    整字节保持不动，其余条目照写。故把每字节的 bit7 摊成整字节掩码，逐字节列开——
    //    乘 0xFF 会被推成 73 位积宽（截断虽无害但报得响），宁可写长一点也不留噪声告警。
    wire pmp_w_raw  : u64 = csr_wdata & 0x9F9F9F9F9F9F9F9F
    wire pmp_w_keep : u64 = pmp_w_raw & 0x0202020202020202 & ((pmp_w_raw & 0x0101010101010101) << 1)
    wire pmp_w_fix  : u64 = (pmp_w_raw & 0xFDFDFDFDFDFDFDFD) | pmp_w_keep
    wire pmp_keep0  : u64 = (r_pmpcfg0[7:7] ? 0xFF : 0) | (r_pmpcfg0[15:15] ? 0xFF00 : 0) | (r_pmpcfg0[23:23] ? 0xFF0000 : 0) | (r_pmpcfg0[31:31] ? 0xFF000000 : 0) | (r_pmpcfg0[39:39] ? 0xFF00000000 : 0) | (r_pmpcfg0[47:47] ? 0xFF0000000000 : 0) | (r_pmpcfg0[55:55] ? 0xFF000000000000 : 0) | (r_pmpcfg0[63:63] ? 0xFF00000000000000 : 0)
    wire pmp_keep2  : u64 = (r_pmpcfg2[7:7] ? 0xFF : 0) | (r_pmpcfg2[15:15] ? 0xFF00 : 0) | (r_pmpcfg2[23:23] ? 0xFF0000 : 0) | (r_pmpcfg2[31:31] ? 0xFF000000 : 0) | (r_pmpcfg2[39:39] ? 0xFF00000000 : 0) | (r_pmpcfg2[47:47] ? 0xFF0000000000 : 0) | (r_pmpcfg2[55:55] ? 0xFF000000000000 : 0) | (r_pmpcfg2[63:63] ? 0xFF00000000000000 : 0)
    wire pmpcfg0_nx : u64 = (r_pmpcfg0 & pmp_keep0) | (pmp_w_fix & ~pmp_keep0)
    wire pmpcfg2_nx : u64 = (r_pmpcfg2 & pmp_keep2) | (pmp_w_fix & ~pmp_keep2)

两条纪律逐条读：① 保留组合当场清——R=0 而 W=1 不允许存在，所以"W 只在 R=1 时保留"：先把所有 W 位清掉，再把"R 位左移一位"与原 W 位与回去。全程位并行，一拍落 8 个条目。② 锁定只看旧值——判定用的是 r_pmpcfg（旧值）里 L=1 的条目：这一拍写进去的 L 当场生效，下一次才挡人。

注释里还有一条真实的工程取舍：位掩码本可以乘 0xFF 展开，但那会被推成 73 位积宽（截断虽无害、报得响）——宁可把 8 个字节逐个列开，也不留噪声告警。判据面要干净，噪声也是一种债。

pmpaddr：按条目锁定与 WARL

prismwhitebow/iu/pmp.prism · addr 写入
    // ---- addr 写入：先判"被写的这一条"锁没锁 ----
    // 该条目的 cfg 字节挪到低位再取 bit7：pmp_idx 的低 3 位就是它在自己 cfg 寄存器里的
    // 字节号（8-15 段减 8 后同样落在低 3 位上，u4 相减不回绕出错）。
    wire pmp_wr     : u1  = csr_wen & is_paddr
    wire pmp_idx    : u4  = csr_addr[3:0]
    wire pmp_lane   : u3  = pmp_idx[2:0]
    wire pmp_sel2   : u64 = pmp_idx < 8 ? r_pmpcfg0 : r_pmpcfg2
    wire pmp_lane64 : u64 = pmp_sel2 >> (pmp_lane * 8)
    wire pmp_addr_lk: u1  = pmp_lane64[7:7]

    on clock {
        if (csr_wen & is_cfg0) { r_pmpcfg0' = pmpcfg0_nx }
        if (csr_wen & is_cfg2) { r_pmpcfg2' = pmpcfg2_nx }
        if (pmp_wr & !pmp_addr_lk) { r_pmpaddr'[pmp_idx] = csr_wdata & 0x0000003FFFFFFFFF }
    }
}

三点：锁是按条目的——要写 pmpaddrN，先看条目 N 自己的 cfg 字节 bit7（pmp_lane64 那两行把字节挪到低位再取；8–15 段减 8 后同样落在低 3 位，u4 相减不回绕）；WARL 截位——本核 PA 40 位，pmpaddr 只收 PA[39:2]（掩码 0x3FFFFFFFFF），其余位读零；RV64 只有偶号 pmpcfg——0x3A1 这类奇号不是号，写被白名单拦下。

对着表读：拍 0–1 复位后两条 cfg 与 pmpaddr0 都是 0；拍 2 向 pmpaddr0（0x3B0）写全 1，读回 0x3FFFFFFFFF——高位读零的 WARL 见证；拍 3–4 写 pmpcfg0=0x1F 读回同值（L=0、A=TOR、X/W/R 全开）；拍 5 写 0x02（R=0 而 W=1）读回 0——保留组合被清；拍 6–8 写条目 1、给条目 0 置 L、再写两条目——读回 0x180：已锁的条目 0 保持不动，条目 1 照写；拍 15 写 0x3A1（奇号）——csr_wen=0、读回 0，不是号就是写不进去。

四发反证打四根柱子（注入在 iu/pmp.prism，实例在 csr 体内——实现只有一份）：保留组合的 W、按条目的 L 锁定、pmpaddr 的位宽 WARL、锁定条目写不动；每条只让 csr_pmp 对应那一行判红，同源 cosim 依旧无感——十六拍的行内期望是唯一能暴露它的判据。

边界：寄存器面已落地，匹配判决还没接线

照实写：这一集交付的是寄存器面 头注里的匹配规则（OFF / TOR / NA4 / NAPOT 的区域判定、生效特权、违例 cause 1 / 5 / 7）是规范口径与设计稿（docs/pmp-design.md）；匹配判决本身与三个消费方（CSR 总线、IFU 取指、LSU 访存）的接线尚未落地——现在能跑的是：号与存储、WARL 与锁定、白名单引用、16 拍判据。判决接线按设计稿分步落地，何时接上，这一集不提前说。

为什么不把话说满：PMP 是本连载里少见的"寄存器面先行"件——寄存器面（号、存储、WARL、锁定）与判决（匹配、生效特权、违例）可以各自独立验收，前者的判据已经在套件里跑；后者一落地就得带上自己的判据（区域边界、TOR 的下界、NAPOT 的连续 1）。先交付能验收的那一半。

小结

  • PMP 回答"物理内存谁可碰"：16 条目、M 态默认全通、M 之外的访问先过它（含页表遍历按 S 算）——判决接线见边界节。
  • 存储形态由写口数决定：cfg 两个标量 reg（一拍 8 条目位并行落位）、pmpaddr 阵列（16 路并行组合读免费）。
  • 两条落位纪律：保留组合 R=0∧W=1 当场清；L 锁定只看旧值（当拍生效、下次才挡）。
  • 号表单点化（is_pmp）、RV64 偶号、pmpaddr 只收 PA[39:2]；判据 16 拍 × 7 列 + 四发反证。
