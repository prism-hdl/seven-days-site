同一颗电路，两层写法

Prism 的第一条设计线是分层：module 只写"做什么"（数据流函数），@schedule 才谈"怎么做"（位宽、流水、时钟、复位）。二者不共享语法，也不允许混。

module
算法层 · "做什么"
端口、组合表达式 x = expr、时序更新 on clock { x' = expr }、reg / mem / fsm 原语。像写数据流图。
@schedule
调度层 · "怎么做"
位宽、流水级数、时钟频率、复位极性、资源约束、延迟；存储与接口能推断，可省。只有它知道微架构——算法层不碰。

为什么必须分开？因为 RTL 与 TLM 要的信息量不对等：RTL 需要流水级、资源仲裁、握手 FSM 这些微架构；TLM（事务级）不需要。同源双出不是对称翻译，是一个"信息注入"问题——把微架构从算法里剥出来，编译器才能给一边注入、给另一边忽略。

module：一只盒子

一门语言先要能装东西。Prism 的容器是 module——一只盒子：皮是端口（数据进出的孔），里是线（中间的值）和状态（跨拍的记忆）。盒子外面只通过端口说话——里面怎么算，是它自己的事。

皮上三种孔：in 进、out 出、both 双向；里有两样东西：具名的线——wire，中间算出来的值可以起名字、随取随用；状态——reg，带时钟沿的小方块，记住上一拍。第一集那颗加法器里 sum = a + b 算出的值落在出口上；给它起个中间名字，就成了盒子里的一条 wire。第二日的器官、整颗 CPU，到头来都是这样的盒子一层层装起来。

写之前还有三件小事：注释只有 // 一种，没有块注释；换行是标点——一条语句写一行、块内条目靠换行分隔；标识符里不许出现连续两个 __（那是编译器代起名的段分隔符——w__<实例>__<端口>，用户占用会撞名，词法层直接拒）。

顺着这只盒子，本集往下走：端口（皮）、类型（线上流什么）、表达式（线怎么算）、on clock 与 fsm（状态怎么记）。先看皮——端口。（下面几节的代码都是算法层片段——module 体内；完整可跑的模块在最后的"装起来"一节。）

端口：in / out / both

端口 = 2 种数据类型（Signal 电平 / Stream 握手流）× 3 种方向（in / out / both）。方向是显式写的——不靠"有没有被赋值"倒推。本集先讲电平这一族——把上图那只盒子写成源码，六根端口一根不差：

prism mixed_ports · 上图那只盒子 
module mixed_ports {
    in  a      : Signal<u8>        // 电平输入
    in  b      : Signal<u8>        // 电平输入
    out sum    : Signal<u8>        // 电平输出
    out full   : Signal<bit>       // 电平输出
    both bus  : Signal<u8>        // 双向（三态）总线
    in  bus_en : Signal<bit>       // 驱动使能

    wire step : u8 = a + b          // 盒内的线（见上图）
    reg  c : u8 = 0               // 盒内的状态（见上图）

    sum  = step + c                  // out 端口直接赋值：组合驱动
    full = (sum == 15) ? 1 : 0
    bus  = bus_en ? step : 1'bz    // both 的赋值必须含高阻
}
  • Signal<T> 是电平——组合逻辑，每拍有效；裸引用即取值，sum = step + c 这种对 out 端口的直接赋值就是合法驱动形态。
  • both 是双向三态——赋值必须含高阻（bus_en ? step : 1'bz）；读回的是整条总线的分辨率，不是自己那一路的驱动值（无驱动源时读到高阻，两个不同的确定值同时驱动读到未知）；高阻只整值出现，不与实数据混位。
  • Stream<T> 是握手流——valid + data 的信号束，带反压写成 Stream<T, ready>；第二日的流水线会重度使用它，今天先知道门牌。

类型：位宽的账在这里算清

Prism 没有动态类型、没有字符串、没有递归——信号域里只有四个类型：

类型含义例子
bit1 位无符号Signal<bit>——控制位首选（写法也可以是 u1）
i<N>N 位有符号i32、i8——二补数
u<N>N 位无符号u8、u64
array<T, N>N 个 T 的定长数组array<i32, 4>

位宽的账有三条规矩，读完基本不会写错：

  • 端口位宽由声明钉死，不随表达式浮动；表达式只在落位处（赋值目标）按 2N 回绕，无饱和。
  • 中间算术按全精度算——加减带进位保护位、乘法按两操作数位宽之和——不会半路丢位。
  • 只有真装不下才报：右值比目标宽时，先去掉不承载数据的位（进位保护位、非负字面量的符号位），去完还装不下才报错，且带上行号与右值原文。

要改符号性视角（不是改值），用类型转换——语义是位模式不动，只换视角：

  • u<N>(x) / i<N>(x)——带位宽，要求两侧等宽；
  • u(x) / i(x)——不写位宽，取操作数的位宽，泛型模块里就这么写；
  • 截断写切片 x[31:0]，扩位写复制拼接——转换不管位宽。
prism typ_demo · 类型与转换 
module typ_demo {
    in  a   : Signal<i8>
    in  b   : Signal<i8>
    in  x   : Signal<u8>
    in  n   : Signal<u3>
    out sum : Signal<i16>
    out lsr : Signal<i8>
    out lt  : Signal<u1>

    sum = a + b                // 全精度求值：和不会半路丢位
    lsr = i8(u(a) >> n)     // 逻辑右移：先换无符号视角，再换回来
    lt  = u(a) < u(x)      // 无符号比较：位模式不动，只换视角
}

表达式：一张运算符表，四种取值分支

组合世界的一切都写成表达式——x = expr，输入一变输出立刻跟着变。运算符按优先级排一张表：

层运算符说明
多路分支match主表达式级，结合比任何二元运算符都紧
位选择x[hi:lo] · x[i] · {a, b} · {N{x}}切片 / 索引 / 拼接 / 复制
一元- ~ !取负 / 按位取反 / 逻辑非
乘除* / %标量算术
加减+ -按全精度算，落位处回绕
移位<< >>行为由操作数类型决定：u 补 0、i 算术（保号）
关系== != < > <= >=有 / 无符号由操作数类型决定
成员x in [a, b] · x in lo..hi集合内判定，结果 1 位
位与& ^ |逐位运算
逻辑&& ||仅布尔语境（guard / 条件）
三元cond ? a : b两路选择，链式右结合

三种位操作先看一遍——切片、拼接、复制：

prism expr_demo · 取位三式 
module expr_demo {
    in  hi     : Signal<u8>
    in  lo     : Signal<u8>
    in  instr  : Signal<u32>
    out pair   : Signal<u16>
    out funct3 : Signal<u3>
    out sext   : Signal<i32>

    pair   = {hi, lo}                        // 拼接：16 位，结果无符号
    funct3 = instr[14:12]               // 切片：边界是编译期常量
    sext   = {{20{instr[31:31]}}, instr[31:20]}  // 复制拼接：符号扩展成 32 位
}

取值分支有四种，按"几路、在哪一级"分工，每种都有自己的位置：

prism choose_demo · 四种分支里的表达式侧 
    pick  = sel ? x : y                                     // 两路：三元
    disp  = match op { 0 => x, 1 => y, 2 => x + y, _ => 0 }   // 多路（常量式）
    combo = match { sel & (x == 0) => x, sel => y, _ => 0 }      // 多路（条件式）
    shift = op in 3..5                                     // 集合判定
  • 三元 cond ? a : b——两路取值；链式右结合：c1 ? e1 : c2 ? e2 : e3 就是一个两级 mux，无需括号。
  • match 两种形态——常量式带 scrutinee（match op { … }，模式是两两互斥的整数字面量）；条件式不带（match { is_lui => … }，模式是任意布尔表达式，重叠时书写顺序即优先级）。两形态的默认分支 _ 都必填，语义都下降为嵌套三元。
  • in 是集合判定——op in 3..5 是闭区间，op in [5, 6, 8] 是枚举列表；元素只能是编译期常量。取反要连整个判定一起括；布尔判定取反用 ! 不用 ~——~(x in 0..3) 高位全 1，进 if 条件就是恒真。
~ 的口径：操作数说了算

对定宽值（reg / 端口 / 切片）取反，按操作数自己的位宽来、不越位：reg x : u8 时 (~x) + 1 得 256，不是全精度二补数的 0；字面量和复合表达式不钉宽，走全精度（~255 参与运算时是 -256）。

还有一条贯穿全部四种分支的分工——一根寄存器两路取值写三元，一组寄存器整体切换写 if/else；按值给一个目标选结果用 match，一个模式下要更新多个目标就用语句级的 switch。后两者入口都在 on clock 里，下一节看。

时序：on clock 是唯一的写法

跨拍状态用 reg 声明，更新只写在 on clock 里，用 prime 记号 '：等号右边读的是本拍值，左边写的是下一拍值。这就是 Prism 里唯一的时序写法——没有"阻塞 / 非阻塞"，没有别的语法能碰时序。

prism seq_demo · 条件更新与多路分支 
module seq_demo {
    in  en   : Signal<bit>
    in  clr  : Signal<bit>
    in  mode : Signal<u2>
    out cnt  : Signal<u8>

    reg c : u8 = 0

    on clock {
        if (clr) {
            c' = 0                        // 条件更新：不满足就保持
        } else if (en) {
            switch mode {
                0 => { c' = c + 1 }
                1 => { c' = c - 1 }
                _ => { c' = c }       // 默认分支必填
            }
        }
    }

    cnt = c
}
  • if 条件带圆括号：if (cond) { … }；else 是补集条件——else if (d) 的条件是 !c & d，臂与臂互斥、首匹配生效；一路里还要分岔就把 if 嵌进体内。
  • 没出现在任何臂里的寄存器保持原值（与不带 else 的 if 同一口径）；空臂合法，就是"这一路不更新"。
  • switch 是语句级多路——switch mode { 0 => { … } _ => { … } }：模式是整数字面量或 _，_ 必填且写最后，重复模式报错；语义等于一串互斥的 if，首个匹配者生效。
  • 体内可任意互嵌——更新、if/else、switch、for 谁都能装谁；缩进和换行只是排版，不承载语义。

重复更新写 for——循环变量在体内是编译期常量，展开出的并列语句和手写完全等价：

prism for_demo · 展开成常量 
    on clock {
        for k in 0..3 {
            if (sel == k) {
                acc' = k + 1       // 展开成 4 条并列更新：命中的那条生效
            }
        }
    }
时钟与复位：都不用手写

clk / rst_n 是编译器在顶层网表自动生成的端口——不出现在任何端口表，也不需要任何声明。复位方式与极性归 @schedule reset（本集是 async_low）；复位优先：rst_n 有效期间所有 reg 无视更新、装载声明时的初值（初值必须是编译期常量）。

状态机：fsm 原语

状态机的语义写在算法层的一张转移表里——态: 谓词 -> 目标态；编码交给调度层。最熟的例子其实是操作系统：一个进程的一生（你在 ps / top 里天天见到的那几个状态），一张表就能写完：

prism proc · 进程的一生 
    fsm proc {
        states  : NEW, READY, RUN, BLOCKED, EXIT
        reset   : NEW
        enc     : one_hot                  // 编码：binary | one_hot | gray
        illegal : hold                     // 非法编码：hold | to_reset | compile_error
        latency : { BLOCKED: 2 }           // 进 BLOCKED 后至少驻留 2 拍

        NEW:     admit    -> READY
        READY:   dispatch -> RUN
        RUN:     io_req   -> BLOCKED   // 发起 I/O：从 CPU 上让出来
        RUN:     preempt  -> READY     // 时间片到：被换下
        RUN:     yield    -> READY     // 主动让出
        RUN:     fin      -> EXIT
        BLOCKED: io_done  -> READY     // I/O 完成：回就绪队列
        // 自环可以不写：没写的转移 = 停在本态（EXIT 一行不写，就永远停着）
    }

    on_cpu     = proc.is(RUN)                      // 本拍在不在 CPU 上
    next_on    = proc.will(RUN)                    // 组合量：下一个沿会进 RUN
    first_tick = proc.is(RUN) & !proc.was(RUN)     // 刚被调度的第一拍

同一张表的图形版——操作系统教材里那张经典的进程状态转换图（自环省掉，缺省保持）：

  • 四个谓词，一个读法——proc.is(S) 本拍在 S、proc.was(S) 上一拍在 S、proc.will(S) 下一个沿会进 S（组合量）、proc.state 编码值（只读）。三个谓词可以出现在任何表达式位置；will 不许进 guard（会成组合环）。
  • 转移恒为同步——当前态 + guard → 下一态，每拍一次；同一源态多条转移，书写顺序即优先级；从 reset 不可达的态报错。
  • 转移表里永不出现编码字样——怎么编、编几位只写在 enc 属性行：改编码不动转移表。这就是"状态与编码分开"。
  • 不手写编码——禁止用 on clock 去写态寄存器、禁止拿 proc.state 的数值当转移条件；写转移表，别写 if 链。

自环可以不写。上面这张表把所有"原地等待"的行都省掉了——admit 没来就停在 NEW，io_done 没来就停在 BLOCKED；EXIT 一行都没有，就是永远停着。缺省语义就是保持当前态：只有当你要离开一个态时，那条转移才需要写出来。想显式写也行（_ -> 自己 仍然合法）；要兜底到别的态就写 _ -> 目标态、放在该态最后。省掉自环之后，一张表里剩下的全是"什么时候走"。

也看"装起来"那节 ProcSwitch 的最后一拍：进程已经停在 EXIT（一条转移都不动），clr 落下，cpu_time 照样归零——清零走的是数据通路，与 FSM 无关：控制管"什么时候"，数据管"哪个值"，各管各的。

为什么 proc.is(RUN) 而不是 proc.state == 4？

proc.is(RUN) 是编码无关谓词——它读的是"态"，不是"态的编码值"（one_hot 下 RUN 是 4，改回 binary 就变 2）。换 enc 不动源码一个字。这是分层带来的第一个红利。

proc.state 也不是不能用——它是只读的编码值：拿它当条件会被拦（fsm 'proc' 第 36 行的 guard 引用了 proc.state 的数值——态数值属编码，不可比较；条件转移请用 'proc.is(态名)'）；拿它对外报告本拍是哪个态就正当，下面"装起来"那颗就是 state = proc.state，并把 enc : binary 明写在表里——序号与声明同序这件事，从此由语言机制担保，不再靠五行 match 复述。

调度层：六行说清微架构

同一颗模块的算法写完，微架构还没着落。下面这六行把它补上——一行不多，一行不少：

字段说什么本集取值
bitwidth数据通路位宽（可用什么精度算）{ data:16 } — 16 位
pipeline几级流水1 stage — 一拍算完
reset复位极性async_low — 低电平异步复位
clock时钟频率与域100 MHz, domain = single
resource资源约束（对 PPA 有影响）none
latency声明延迟1 cycle

还有两个字段没出现在这六行里：storage（哪些信号真的是寄存器、几位宽）与 interface（端口绑定什么协议）。它们能从模块体推断——算法层写了 reg count : u4，那就是 4 个触发器；端口本来就在模块头上——所以整条可以省略，语言自己推。真需要钉死微架构的时候，再写。

装起来：一颗进程调度单元

把这一集的零件装成一颗完整的模块。需求挑一个程序员都熟的：进程调度——管一个进程的五态一生（NEW / READY / RUN / BLOCKED / EXIT，你天天在 ps / top 里见的那几个），顺带记它在 CPU 上花了多少拍、时间片还剩多少。事件全部从端口进；cpu_bus 是共享三态总线——在 CPU 上时挂出 pid，否则让出。对照着读——每一种写法都在前面某一节出现过。

prism proc_switch.prism · 算法层 
module ProcSwitch {
    // —— 事件（调度器与定时器给的）——
    in  admit     : Signal<bit>       // 新进程被接纳
    in  dispatch  : Signal<bit>       // 调度器选中它，上 CPU
    in  preempt   : Signal<bit>       // 时间片到：被换下
    in  yield     : Signal<bit>       // 主动让出
    in  io_req    : Signal<bit>       // 发起 I/O → 阻塞
    in  io_done   : Signal<bit>       // I/O 完成
    in  fin       : Signal<bit>       // 退出

    // —— 数据与观测 ——
    in  pid       : Signal<u8>        // 进程号：上 CPU 时挂到总线
    in  prio      : Signal<u2>        // 优先级：0 最高，用来定时间片
    in  clr       : Signal<bit>       // 清零统计（与 FSM 无关）
    out state     : Signal<u3>        // 五态序号（NEW..EXIT = 0..4）
    out on_cpu    : Signal<bit>       // 本拍在不在 CPU 上
    out cpu_time  : Signal<u16>       // 累计在 CPU 上的拍数
    out slice_end : Signal<bit>       // 时间片用完（喂给调度器去触发 preempt）
    both cpu_bus  : Signal<u8>        // 共享总线：在 CPU 上驱动 pid，否则高阻

    fsm proc {
        states : NEW, READY, RUN, BLOCKED, EXIT
        reset  : NEW
        enc    : binary

        NEW:     admit    -> READY
        READY:   dispatch -> RUN
        RUN:     io_req   -> BLOCKED
        RUN:     preempt  -> READY
        RUN:     yield    -> READY
        RUN:     fin      -> EXIT
        BLOCKED: io_done  -> READY
    }

    wire running : u1 = proc.is(RUN)          // 具名线：本拍在不在 CPU 上
    reg  spent   : u16 = 0                    // 累计 CPU 拍数
    reg  left    : u4  = 0                    // 本时间片剩余拍数

    on clock {
        if (clr) {
            spent' = 0
            left'  = 0
        } else {
            if (running) {
                spent' = spent + 1            // 在 CPU 上：拍数 +1
            }
            if (dispatch) {
                switch prio {                 // 按优先级装载时间片
                    0 => { left' = 8 }
                    1 => { left' = 4 }
                    _ => { left' = 2 }
                }
            } else if (running & (left != 0)) {
                left' = left - 1
            }
        }
    }

    state     = proc.state        // 组合量：随态即时变——enc 是 binary，序号就是声明序
    on_cpu    = running
    cpu_time  = spent
    slice_end = running & (left == 0)
    cpu_bus   = running ? pid : 1'bz
}

对一遍零件与来路：三种端口 in / out / both（"端口"那节）、类型（"类型"节）、match 与三元（"表达式"节）、if / switch 与 on clock（"时序"节）、fsm 转移表（"状态机"节）、@schedule（"调度层"节）——全在这六十行里。跑起来——激励表 10 列输入 + 4 列期望，每一行都是手算的：

接错一支箭会怎样：I/O 完成回哪

把 io_done 的箭头接到 RUN——单看这一支也讲得通："I/O 回来了，接着跑"：

prism 反例（只改这一行） 
    RUN:     io_req   -> BLOCKED
    BLOCKED: io_done  -> RUN   // ❌ 应该回 READY：先去就绪队列，等调度

编译照过、跑也照跑——直到第 14 拍对不上：io_done 拉着的那拍，state 期望 1（READY）实得 2（RUN），on_cpu 也提前回到 1。更隐蔽的是后面三拍：它没经调度器就私自上了 CPU，cpu_time 跟着漂——15 / 16 / 17 三拍全多了 1。

教训：状态图就是需求——每支箭头都有原因

BLOCKED 出去的那支箭头只回 READY：I/O 完成的身份是"就绪"，不是"在跑"——上不上 CPU 由调度器说了算（dispatch 说了算）。一支箭头指错目标态，表里连着两列、连着三拍都跟着错——所以转移表要与状态图逐支对读，别凭"接着跑"的直觉接。

mem：把格子排成一排

reg 是一格。mem 是把同样的格子排成一排，一个下标选一格——而读与写各走各的手续：读挂在组合路径上（地址一稳，那一格就出来），写挂在时钟边上。第 6 集那句"异步读 / 同步写"，语法出处就在这里。

prism mem_image.prism · 阵列 
module Blk {
    in  addr  : Signal<u2>      // 读写共用这一个地址：一块存储就一个地址
    in  wen   : Signal<u1>      // 写使能
    in  wdata : Signal<u64>     // 写数据
    out rdata : Signal<u64>     // 异步读口

    mem blk : [4] u64 = 0       // 4 格 × 64 位 = 32 字节，复位值 0

    rdata = blk[addr]

    // 全部逻辑就这一条写语句：不要写就把旧值原样搬回去
    on clock {
        blk'[addr] = wen ? wdata : blk[addr]
    }
}

声明一行写三段：深度 [4]、元素类型 u64、初值 = 0。四件事都要量过：

  • 初值决定上电是不是一个确定的数。标量 = 0 把每格铺成 0，逐格 = [10, 20, 30, 40] 各给各的；不写初值，那一格上电就是 x（未定）——同一份激励实测：表里 r 列是 x，期望写 0 就当场红。阵列里但凡有必须从 0 起算的（寄存器堆的 32 格、存储器的整块阵列），初值那一格就得写。
  • 读是组合的。rdata = blk[addr] 没有 on clock：地址一变，输出跟着变。单周期核靠这一条才能"同一拍取到数"。
  • 写只许一条语句。要不要写、写什么，全折进右值那个三目里。再加第二条写语句，Blk: memory 'blk' 有 2 条写端口赋值——当前语言只支持单写口；用 for 逐下标写四格也一样拒（"有 4 条写端口赋值"）。这不是语法洁癖：一颗存储宏就一个写端口，多个下标同拍写=要多个端口=另一颗器件。
  • 地址宽度是电路事实，不是风格。4 格配 u2：00..11 恰好取遍，"越界"在类型上不可表示。把端口换成 u3（多出 4 个阵列外面的地址）实测：同一笔越界读，golden 给 0、RTL 仿真给 x——两侧口径本来就不该拿来当设计依据。写在源码里的下标则是编译期就拦：expose 'dut.blk[4]'：索引越界 （mem 深度 4）。

阵列里的值要从外面看见，就在 design 里逐格 expose——写口写的、下面 image 装的，都在这里现形：

prism mem_image.prism · 观测 
design BlkTop {
    dut : Blk

    // 整块阵列一格一根线引出来：写口写的、image 装的，都在这里现形
    expose dut.blk[0] as w0
    expose dut.blk[1] as w1
    expose dut.blk[2] as w2
    expose dut.blk[3] as w3
}

多大、几读几写、长成寄存器堆还是 SRAM，都不在这一层——那是 @schedule 的 storage 一行，第 6 集整集就在用这个分别把同一份 ram 摆成指令侧与数据侧。

给阵列装数据：image、@load 与 --image

一块阵列的供值路一共三条：声明里的初值（上电就是它）、时钟边沿上的写口（跑起来一格一格写）、测试台的 image 段（开机前整块灌进去）。第三条是给"别人给你的产物"留的门——固件、引导镜像、编译器输出的裸二进制，都不属于芯片源码，却要在仿真里落到某块存储的某一段上。

prism mem_image.prism · 两个 image run 
// ③ 内联表：哪块存储（dut.blk）、从第几字节起（0）、装多少（32）。
// 币种是字节：32 字节 ÷ 每格 8 字节 = 4 格，正好铺满，所以四列都是表里的值。
run fill of BlkTop {
    image : {
        seed : dut.blk[0:32] = [1, 2, 4, 8]
    }
    stim : { addr, wen, wdata = { 0, 0, 0 } }
    until : for 1 cycles
    show  : { w0, w1, w2, w3 }
}

// ③ 外部镜像：偏移 16 字节 = 从第 2 格起；字节数省掉（`[16:]`），由文件量出来。
// 命令行 `--image img=<另一份文件>` 只换文件——落点与窗口仍是源码里的事实。
run boot of BlkTop {
    image : {
        img : dut.blk[16:] = @load("boot.bin")
    }
    stim : { addr, wen, wdata = { 0, 0, 0 } }
    until : for 1 cycles
    show  : { w0, w1, w2, w3 }
}

一条装载声明四个信息：别名（seed / img）、哪块存储（dut.blk）、从第几字节起、装多少字节。跑出来是这两张表：

▸ 两条 run 的实测输出（golden 直跑）

  • 币种是字节。窗口写 [16:]，不是"第 16 格"：16 字节在一块 8 字节/格的阵列上就是第 2 格起。零点也不是芯片的地址图，而是这块 mem 的起点——装载偏移与译码器算出的窗口内偏移因此是同一个数。
  • 字节数可以省，只有一种省法：[偏移:]。省下的长度由值侧量出来——文件就是文件长度，内联表就是项数 × 每字字节数。
  • 别名是命令行的把手。--image 只换文件，落点与窗口仍是源码里的事实：

装错地方是装不进去的，四条都响亮拒绝（都是实测原文）：

  • 文件不存在——'dut.blk' 的 @load 文件不存在：/tmp/mi/nope.bin（相对主文件解析）；路径可以绝对，也可以相对主文件；
  • 装不下——'dut.blk' 的 @load 文件 16 B（2 字）装不进 [16:8]（窗口容 1 字，多 1 字）：静默截断等于把程序砍掉尾巴还报告成功；
  • 越过深度——窗口 [16:32]（字节）占到第 6 字，超过 mem 'dut.blk' 的深度 4 字（多 2 字）；
  • 两个窗口交叠——image 'seed' 与 'ov' 在 'dut.blk' 上窗口交叠：[0:32] 与 [16:16]（字节）——哪个赢会取决于发射次序，不是装载语义。

装载发生在复位释放之后、第一个被采样的拍之前——所以 fill 那张表第 0 拍看见的就是灌完的值，没有"先读出一遍 0 再慢慢装"的中间态。这一套手续到第二日照样用：cpu.prism 的 image 把程序灌进 im、把数据灌进 dm，换的永远是镜像，不是芯片。

泛型：把位宽和深度做成参数

泛型让同一段源码长出多个版本——<T: bits> 是位宽形参，例化时代入：

prism Adder · 泛型 
module Adder<T: bits> {
    in  a   : Signal<T>
    in  b   : Signal<T>
    out sum : Signal<T>

    sum = a + b
}

design AdderTop {
    dut : Adder<T = i32>          // 32 位版本；换 T = i64 就是 64 位
}

形参收的不只位宽，也收深度：mem blk : [4] u64 里那个 4 同样可以写成 [SIZE]。第 6 集那颗 RAM<SIZE: int, W: bits, A: bits> 就是同一份源码长出两个实例——im 取 W = u32（指令字恒 32 位），dm 取 W = i64（数据 64 位），差别只在实例参数一行上。反过来，只有一个宽度样本的就别留形参：第 5–7 集的 pc / regfile / alu 把位数直接钉在声明里——泛型要有第二个实例才有意义。

小结 · 第一日的语法到此讲完

这一集只做一件事：把语法骨架摆完。回头看每一件：

  • 盒子——module：皮是端口，里是线与状态；顺带三件小事：注释一种、换行是标点、__ 是禁地；
  • 端口——in / out / both，方向显式，电平与握手流两族；
  • 类型——bit / i<N> / u<N>；位宽由声明钉死、回绕在落位处、转换只换视角；
  • 分支——表达式级：两路三元、多路 match、集合 in；语句级：一组寄存器整体切换写 if/else、按值多路写 switch；
  • 时序——唯一写法 on clock + prime；时钟与复位由编译器生成；
  • 状态——fsm 写转移表（自环可省：缺省=保持），谓词编码无关，编码归调度层；
  • 阵列——mem：初值定上电是不是一个确定的数，读组合、写同步且只许一条写语句，地址宽度就是"取遍几格"这件电路事实；
  • 供值——上电内容走 run 的 image：窗口三个数（哪块存储 / 字节偏移 / 字节数），@load 接别人的产物，--image 只换文件不换落点；
  • 分层——module 说"做什么"，@schedule 说"怎么做"——本集的名字。
