FPU（F / D）
一半是算术，一半是特权

第 22 集的启动报告早就广告了 rv64imafdc，核里却少这两门。补上它们，算术只是其中一半——另一半是 mstatus.FS 的三态、由硬件置的 Dirty、派生出来的 SD、以及 FS=Off 时整族判非法。内核按 sstatus.FS 决定要不要保存浮点上下文：这一半做错，代价是上下文切换时静默丢寄存器，不 trap、不报错、结果错。

广告与能力必须一致：为什么这一日补 F / D

第 22 集 OpenSBI 的启动报告里那一行 Base ISA : rv64imafdc 当时就注明是编译期口径——固件按 rv64imafdc 编出来，核里却只有 I · M · A · C。设备树写的是同一件事：

dtsfw/sbi.dts · 内核据此决定要不要保存浮点上下文
riscv,isa = "rv64imafdc_zicsr_zifencei_sstc";

内核的 has_fpu() 读的就是这份设备树。于是两种不一致各有各的坏法：广告了而硬件没有，浮点指令变成非法指令，用户程序收一发信号，至少看得见；硬件有了而状态位不置，内核按 sstatus.FS 判断"这一版上下文没有浮点要存"，于是不 trap、不报错、结果错。后一种坏法写在 ext/csr.prism 的注释里，是这一集真正要防的那件事：

prismwhitebow/ext/csr.prism · 为什么 Dirty 必须由硬件置
        } else if (fp_state_wen) {
            // 硬件置 Dirty 的第二支：f 寄存器写回。这支是内核 save_fp 的依据——Linux 读
            // sstatus.FS 决定要不要存浮点上下文，我们不置 Dirty，上下文切换就**静默丢**
            // 浮点寄存器（不 trap、不报错、结果错）。
            // 口径（写死，别被"顺手补全"）：只有**写**浮点状态才置 Dirty。FSW/FSD 只读
            // f 寄存器、FMV.X.F / FCVT.X.F / FCLASS 的结果进整数 rd，都不算浮点状态写入，
            // 生产方（lsu.fp_wen）不许把它们算进来；trap/mret/sret 三档都不动 FS[14:13]
            // （掩码 0x1888/0x122 都绕开这两位），所以它们抢走那一拍时 Dirty 轮不到。
            // 不看 FS 现值：Off 状态下这一拍本不该出现（②的指令门会先把浮点指令判非法），
            // 真出现了说明有人在 Off 下写了 f 寄存器，此时报 Dirty 才是如实。
            r_mstatus' = r_mstatus | 0x6000        // FS ← Dirty（写 f 寄存器）

用户态是不是真用浮点，也不用猜。initramfs 里第一个跑起来的 linuxrc 在保存例程里发出 c.fsd——压缩编码，展开器的激励表把这条记成了"真机崩过的那条"。所以本集要交付的是两半：算术通路（FPU 与浮点寄存器堆）和特权义务（mstatus.FS 三态、硬件置 Dirty、SD 派生、fflags 累积、FS=Off 时整族判非法）。

算术这一半：一条统一宽通路，两种精度

单精度与双精度最常见的两种写法是"两个定宽单元并排"或"一个 64 位单元加一堆截断"。这里选的是第三种——一条统一宽通路同时服务两种精度，形状照 C910 的标量浮加：

prismwhitebow/ext/fpu.prism · 单元形状
// 形状照 openc910 的标量浮加（vfalu/ct_fadd_double_dp.v）：**一条统一宽通路**同时服务
// 两种精度，不是两个定宽单元并排。single 不占独立算术硬件，只靠
//   ① 解包时各写一套**固定切片**再按 fmt 选（`fmt ? a[62:52] : {3{0}, a[30:23]}`）；
//   ② 有效数字**左对齐到同一个隐含位**（bit55）——double 的 53 位天然如此，single 的
//      24 位放在高位、下面补零（C910 的 `{29'b0, frac}` 是同一手法）；
//   ③ 舍入与打包按 fmt 取同一条通路的**不同抽头**（double 取 [54:3]、single 取 [54:32]）。
// 代价落在"几十处 fmt 与或 mux"上，算术通路只有一份。

三条手法合起来是一件事：精度差异全部挪到"抽哪几位"上，算术本身只有一份。代价也在这里——几十处按 fmt 的与或选择器。窗口口径全流程只有一份，这是能在一张表里同时验两种精度的前提：

prismwhitebow/ext/fpu.prism · 窗口口径
// 窗口口径（全流程一份）：value = W × 2^(E-55)，W 的隐含位在 bit55，[54:3] 是小数位，
// [2:0] 是 G/R/S 舍入道。右移挤出去的位不提前归约：整段留在窗口里，最后一并 OR 进 sticky
// （C910 也把移出位整体带走、到舍入时才算 sticky）。

流水上分两档。加减乘与融合在 EX 级内联，一拍出结果；FDIV / FSQRT 是多拍迭代档，double 31 拍、single 17 拍：

prismwhitebow/ext/fpu.prism · @schedule
@schedule FPU {
    bitwidth  : { data:64 }
    pipeline  : 1 stage
    reset     : async_low
    clock     : 100 MHz, domain = single
    resource  : none
    latency   : 31 cycles        // 组合档 1 拍；迭代档（FDIV/FSQRT）double 31 拍、single 17 拍

迭代档占用的这一拍里，流水线怎么办？用的是第 24 集已经立起来的占用协议：hazard 出 div_start 起手，把 EX 冻到 done，消费者在 ID 被冻住、释放沿才放行。所以浮点除法没有引入新的停顿种类——它新增的是十源表里那一根 src_fdiv。

特殊值：规范给的三条，各归一处

浮点最容易出错的地方从来不是加减乘，是边角：NaN、无穷、零的符号、次正规、以及 FLEN=64 装单精度时的"箱"。头注把这些逐行钉住：

prismwhitebow/ext/fpu.prism · 特殊值口径
// 流水：算术部分是 EX 级内联的一拍出结果（C910 标量 FADD 3 拍、FMUL/FMADD 5 拍，把它
// 按拍切开是后续步骤）；FDIV/FSQRT 是⑤的多拍状态机，double 31 拍、single 17 拍（C910 走
// SRT radix-16 的 14/7 次迭代），占用期由 hazard 把 EX 冻到 done。
//
// 特殊值（IEEE 754-2019 + RISC-V F/D 章）：
//   NaN  指数全 1 且尾数非 0。sNaN 参与运算置 NV。运算结果只要是 NaN 就是 **canonical
//        NaN**（§6.1.3 "Except when otherwise stated, if the result of a floating-point
//        operation is NaN, it is the canonical NaN"）——载荷传播是被点名否掉的非标准选项，
//        只有 FLW/FSW/FLD/FSD/FMV.* 这类搬运才保载荷；min/max 取非 NaN 那一侧。

三条规范义务分别落在三个模块里，没有一条在浮点寄存器堆里——这是这一节的关键分工：

义务规范原文的位置落在哪个模块
窄结果写回时高位补全 1（NaN-boxing）"must write all 1s to the uppermost FLEN-n bits"写侧：顶层按指令的 fmt 拼，fregfile 照单存
读出后判断是不是有效窄值，坏箱当 canonical NaN"otherwise the input value is treated as an n-bit canonical NaN"用侧：pipe/exu.prism 验箱
搬运类不改被搬的位FLW / FSW / FLD / FSD / FMV.*LSU：装载补箱、存储只取低 32 位，都不验箱
prismwhitebow/pipe/exu.prism · 验箱在前递之后还是之前
    // FLEN=64，单精度值靠 NaN-box 表达，所以用侧必须**验箱**："check if the input
    // operands are correctly NaN-boxed, i.e., all upper FLEN-n bits are 1. If so, the
    // n least-significant bits of the input are used as the input value, otherwise the
    // input value is treated as an n-bit canonical NaN."（0x7FC00000 就是 32 位
    // canonical NaN）验箱属这条"用"的路——FSW 那条转移路不验，只取低 32 位。
    // 两级前递按年龄优先：MEM（生产者刚算出结果/取回数据）盖过 WB，都比锁存值新。
    // 前递插在验箱**之前**：递来的就是成箱值，箱坏了照样判成 canonical NaN。

最后那一句是判据的形状：前递插在验箱之前。如果反过来（先验锁存值再前递），一次坏箱会被前递来的好值掩盖，测试就看不出箱逻辑坏在哪一级。

浮点寄存器堆：与整数堆对称，但没有硬连线零

fregfile 与 regfile 的端口形状一样（三读一写、组合读出），差别在两处：宽度是 FLEN=64 且不分档，以及f0 是一个普通寄存器。整数那一族 x0 有硬连线零，浮点没有对应物——f0 是 ABI 里的 ft0，编译器真会拿它当临时寄存器用。

prismwhitebow/iu/fregfile.prism · 宽度由编码约定决定，不由本模块决定
// FLEN=64 之后，寄存器里放的可能是单精度也可能是双精度，区分它们的是**编码约定**
// 而不是本模块的状态，规范（riscv-norm-rules）那三条：
//   · "valid values of narrower n-bit types, n<FLEN, are represented in the lower
//     n bits of an FLEN-bit NaN value, in a process termed NaN-boxing. The upper
//     bits of a valid NaN-boxed value must be all 1s." —— 窄值叫 NaN-boxed。
//   · "Any operation that writes a narrower result to an f register must write
//     all 1s to the uppermost FLEN-n bits" —— 窄结果写回时高位补全 1：这件事归
//     **写侧**（顶层按指令的 fmt 拼），不在寄存器堆里做，本模块只照单存。

阵列自己的判据只有 6 拍，钉的是"三口不串、f0 可写、写使能门控有效、高半不被截"：

"f0 可写"这一条在核级另有一发：fadd.s f0, f5, f7 岔开两拍再用 fsw→lw 回读，必须拿到 3.0f 的位型。整数侧那根 rd != 0 门控如果被乘回浮点写使能，这一发不仅写不进阵列——前递也一起断，红在两处而不是一个值。

特权这一半：FS 三态、Dirty 由硬件置、SD 是派生读值

mstatus.FS 在规范的 RV64 位图里是 bit[14:13]，三态：Off(00) / Initial(01) / Clean(10) / Dirty(11)。本集把位段搬正到规范位置，并让这三态真的起作用。第一件事是门：FS=Off 时整族浮点指令判非法。

prismwhitebow/ext/csr.prism · Off 的门限只有一份
    // FS=Off(00) 时浮点状态不可访问——规范把这条给**所有特权级**（含 M）：它不是特权门，
    // 而是浮点单元整个被关掉这件事本身。本核只白名单了 fcsr(0x003)（fflags/frm 折进它），
    // 所以这一档先在 fcsr 上生效；浮点指令（fadd/FLW/FSW…）那一档在 decoder/trap 里合 cause 2。
    wire fs_off  : u1 = r_mstatus[14:13] == 0
    wire fp_gate : u1 = !(is_fcsr & fs_off)
    wire priv_ok      : u1 = (r_priv >= csr_priv_req) & ctr_gate & fp_gate
    csr_illegal_priv = csr_exec & is_supported & !priv_ok
    // FS 关着这件事交给 TRAP 去合 cause 2：门限只有这一份（r_mstatus[14:13]==0），下游拿
    // 译码器带进 MEM 的 is_fp 一并判定，别在 EX/MEM 再拼一遍位段。
    // 采样点定在 MEM：更早的 `csrw mstatus` 到这一拍已经落了，紧跟其后的浮点指令因此
    // 看到的是新值——在 ID 采就会把"先开 FS 再用 FP"的合法序列误判成非法。
    fp_off = fs_off

门限只算一次、只交一根线出去，剩下的合并交给陷阱那一集立起来的裁决表：is_fp 与 fp_off 相与，落进 cause = 2。

prismwhitebow/pipe/trap.prism · Off 下的浮点指令并入 cause 2
    //          OR FS=Off 时的任何浮点指令（csr.fp_off × 译码器的 is_fp——含只读浮点状态
    //          那一族与浮点访存；规范给所有特权级，含 M）
    // 缺页/访问错（LSU 翻译定案给出）排在未对齐之前：有 MMU 时先翻译、物理访问在后，
    // 一个既未对齐又缺页的访问按实现选缺页（规范允许二者择一）。cause 12/13/15
    // 都可经 medeleg 委派给 S（与未对齐同走下面的 to_s 判据）。cause 7 同理可委派。
    // 取指缺页排最前，压过 illegal：这条指令**根本没取到字**，ID 拿的是废值、
    // mem_is_illegal 很可能顺带成立——让它先报就成了 cause 2 + 指令字当 mtval，两样都错。
    mem_trap_cause = match {
        // 中断优先于异常：cause = (1 << 63) | interrupt_number
        (mem_valid & mem_interrupt_pending)                   => (1 << 63) | mem_interrupt_cause,
        (mem_valid & mem_if_pf)                               => 12,
        (mem_valid & (mem_is_illegal | csr.csr_illegal_priv | mem_priv_bad | (mem_is_fp & csr.fp_off))) => 2,

注释里"采样点在 MEM 不在 ID"这一句值得单独看：在 ID 采会把"先开 FS 再用浮点"的合法序列误判成非法——写 mstatus 的那条指令自己还没提交。

第二件事是 SD。它是 FS==Dirty 的派生读值，不是一个可以写的状态位：

prismwhitebow/ext/csr.prism · SD 不进 reg
    // SD[63] 不是软件可写的状态位，是 FS 的派生读值：FS=Dirty(11) ⇒ 1，其余 0。
    // 规范里 SD 是 read-only，"= 1 if the FS, XS, or VS field is Dirty"——本核没有 XS/VS，
    // 所以只跟 FS 一路。把它存进 reg 就与 FS 成了两套口径，一定会漂。

"存进 reg 就与 FS 成了两套口径，一定会漂"——这一句是硬件设计里通用的判据：同一个事实只许有一个存储来源。csr_fs 那 16 拍钉的就是派生关系：写 FS=11 之后读出口 SD[63]=1，写 0 之后 SD 归 0 而两个只读位 SXL/UXL 照在。

第三件事是 Dirty 的两支来源：写浮点状态 CSR（fcsr）与写 f 寄存器。两支都由硬件自己置，软件只负责写 Clean/Initial。哪些指令不算写浮点状态，口径写死在生产方：

prismwhitebow/iu/decoder.prism · 两支判据的分工
    out  is_fp_wr_x    : Signal<u1>     // 1=浮点源、整数目的（FEQ/FLE/FLT/FCLASS/FMV.X/FCVT.*.S|D）
    out  is_fp_load    : Signal<u1>     // FLW/FLD（opcode 0x07, f3=2/3）
    out  is_fp_store   : Signal<u1>     // FSW/FSD（opcode 0x27, f3=2/3）
    out  is_fp         : Signal<u1>     // 1=浮点家族总判据（mstatus.FS==Off 时整族判非法，见 pipe/trap.prism）
    out  is_fp_op      : Signal<u1>     // 1=真过 FPU 的那两支（写 f 的运算 + 浮点源整数目的）——fflags 只在这些指令上算数
prismwhitebow/iu/decoder.prism · is_fp 四支与 is_fp_op 两支
    is_fp_load    = (opcode == 0x07) & (funct3 in [2, 3])          // FLW/FLD
    is_fp_store   = (opcode == 0x27) & (funct3 in [2, 3])          // FSW/FSD
    // 两类目的分账：写 f 寄存器的（算术 + 整数→浮点 + 互转 + 装载）与写整数 rd 的
    // （比较/分类/FMV.X/浮点→整数）——整数那一支要进 reg_write_eff 与 wb_sel。
    is_farith     = is_fadd | is_fsub | is_fmul | is_fdiv | is_fsqrt | is_fsgnj | is_fminmax | is_fcvt_i2f | is_fcvt_swap | is_fmv_fx | is_fmadd | is_fmsub | is_fnmsub | is_fnmadd
    is_fp_wr_x    = is_fcmp | is_fclass | is_fmv_x | is_fcvt_f2i
    // 浮点家族总判据：写 f 的、读 f 写整数的、装载的、存储的四支都算。规范口径是
    // "FS=Off 时任何浮点指令都是非法指令"（含只读浮点状态那一族与浮点访存），所以这一份
    // 判据归译码器独家拥有——trap 侧只认这根线，别在 MEM 拿 opcode 再拼一遍。
    is_fp         = is_farith | is_fp_wr_x | is_fp_load | is_fp_store
    // 浮点**运算**判据（比 is_fp 少装载/存储两支）：FLW/FSW/FLD/FSD 是搬运，规范明说
    // "The transfer instructions do not modify the exception flags"，所以 fflags 只能从
    // 这一支取——否则装载那一拍的 FPU 输出（op 位段是译码默认值）会当成标志灌进 fcsr。
    is_fp_op      = is_farith | is_fp_wr_x

is_fp 与 is_fp_op 差的那两支正是 FLW / FSW / FLD / FSD：搬运读浮点状态或写浮点状态，但不产生标志。规范对搬运类明说不改 fflags，所以 fflags 的门控用 is_fp_op；而 FS=Off 挡整族用 is_fp——装载与存储也在挡的范围里。这两套判据不能合成一根线，合成之后 Off 状态下搬运能过、或者运算乱置标志，两种错各占一半。

核级那六拍（⑧–⑬）钉的就是这一半：

//   ⑧ FS←Dirty（写 f 寄存器那一支）：程序跑到这里已经有一串指令往 f 寄存器写
//      （flw/fld/算术/融合/开方），`csrrs x27, mstatus, x0` 读回来必须是 FS=Dirty(11)

//   ⑨ 只读浮点状态不许置 Dirty：先 `csrw mstatus` 把 FS 显式写成 Clean(10)，再 `fsw`

//   ⑩ 装载算写浮点状态：`flw f20` 之后 `csrrs x30` 必须看到 Dirty(11)——内核 _restore_fp

//   ⑫ rs3 那一级的浮点前递（结构性那一发）：`fdiv.s f23`（多拍占到 done）紧跟
//      `fmadd.s f24, f23, f7, f23`——占用协议把消费者冻在 ID 直到生产者离开 EX，放行那一拍
//      生产者恰在 MEM，所以 rs3 只有 MEM/WB 前递这一条路；断掉它 f24 拿到的是阵列里的旧值
//      （未初始化＝坏箱＝canonical NaN），绝不是 13.5f。

//      不置；`csrrs x6` 必须等于 x5 再 OR 上 DZ（粘滞是累加），再来一发 `fsw`（搬运类，
//      规范说不改标志）之后 `csrrs x7` 必须与 x6 相同——这一条同时钉住门控（装载/存储那两拍
//      不许把 FPU 组合面的残值当标志灌进去）与"只 OR 不覆盖"。

压缩臂：四条 D 搬运，RV64C 没有压缩单精度

第 17 集立过一条口径：压缩码是别名，不是新语义。浮点这一族的压缩臂照整数孪生的位段做，四条：

算术值归向量账，通路归核级。fp_probe 十三档各钉一条边，档号就是源码注释里的编号：

档钉什么断了会怎样
①FLW→FSW→LW 回路 + 背靠背两级前递存 0；且存储类的 rd 位段被当整数写回，x8/x24 被写成访存地址
②双精度宽回路：同址 ld 与 fld 读到同一个值u64 数据面或宽操作数前递断一支
②bfsw 走 4 字节车道合并整字 8 字节都写下去，邻车道被踩坏
③FMV 双向整份搬 64 位内核存浮点上下文用的就是这一对，断则存丢
④算术写回补箱 + 经内存回路自证写侧补箱丢，或 wb_sel 少一支
⑤FMADD 家族的 rs3 通路与前递背靠背融合拿到阵列旧值：7.0 变 2.0
⑥FCVT 双向，含动态 rm 与整数符号1.5 在 RNE 下不给 2；-1 不给 -1.0
⑦迭代档占用协议与结果可被前递退休序出现重复条目，或消费者读到旧值
⑧一串 f 写回之后 FS=Dirty、SD=1内核 save_fp 不存浮点——静默丢
⑨只读浮点状态的一发 fsw 不许置 DirtyFS 恒 Dirty，每次切换都白存一遍浮点
⑩flw 算写浮点状态，必须置 Dirty_restore_fp 恢复完又被下一次切换跳过保存
⑪写 f0 要落进阵列整数那支 rd != 0 门控乘回浮点，写回与前递一起断
⑫多拍除法的产出当 rs3（结构钉法）拿到坏箱 → canonical NaN，绝不是 13.5f
⑬除零置 DZ、粘滞只 OR、搬运类不许碰标志存储那一拍 FPU 组合面的残值灌进 fflags，多出 NV

常驻套件里这一族共 89 项：正例与结构 38 项，反证 17 发、每发三条断言＝51 项。十七发各打一条边，分三组：阵列三发、通路九发、浮点状态五发。两处细节值得单独说：

  • 通路那一组的第 ③ 发换过靶。原先拿"两条背靠背的 fmadd"当靶，红不红取决于两拍之间有没有气泡——而气泡随 PC 走，镜像里加两条指令就能把它顶成假通过。现在的靶是"fdiv.s f23 紧跟 fmadd.s f24, f23, f7, f23"：占用协议保证消费者放行那一拍生产者恰在 MEM，阵列里还没有值，rs3 只有前递这一条路。这是结构上必然红，不是碰巧红。
  • 第 ④ 发是"两路都错但错得不一样"那一类。把 IDU 的 fwen 退回引用译码器内部线，checker 与 golden 都不报"未定义引用"：golden 读成 0、RTL 落成 x。所以这一发不按"同源 cosim 无感"登记，而按分歧登记——分歧报告只打前 20 行且按列名排序，判据取分歧行的形状，不取某个列名。

其余各发的同源 cosim 一律无感：golden 与 RTL 读同一份表达式，错得一致。红只能由这份独立的退休表来判——这条口径第 24 集立过一次，浮点这一族把它用得更狠。

小结

  • 浮点这一族分两半：算术通路一条统一宽档（精度差只体现在抽位上），特权义务四件（FS 三态、硬件置 Dirty、SD 派生、fflags 累积）。
  • 三条规范义务各归一处：补箱在写侧、验箱在用侧、搬运不改位也不验箱——fregfile 自己不判宽度。
  • 两套判据不许合成一根线：is_fp（Off 挡整族，含装载存储）与 is_fp_op（只有运算才产生标志）。
  • 迭代档复用第 24 集的占用协议，新增的是 src_fdiv 这一根源，不是新的停顿种类。
  • 压缩臂补四条 D 搬运，保留编码不展开成合法指令；misa 与设备树与硬件能力三处同改。
  • 判据：向量账 335 拍（期望出自独立实现并与 Python 对拍）、核级十三档通路探针、阵列 6 拍、压缩 70 拍、CSR 16 拍；反证十七发。
边界照实写

① 算术部分现在是 EX 级内联的一拍出结果，C910 的标量 FADD 是 3 拍、FMUL/FMADD 是 5 拍——把它按拍切开是后续步骤，本集不宣称达到。② FS=Off 对 CSR 那一支只挡 fcsr（fp_gate），别的号不受它影响。③ 单精度不占独立算术硬件，所以面积上省了一份加法器，代价是几十处 fmt 选择器——这一笔没有逐项实测。
