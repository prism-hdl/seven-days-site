差在五处
五级顺序单发射 vs 现代高性能核

前六日沿一条五级、单发射、按序的观察路径建立了白虹的 ISA、特权、存储与整机契约；这些契约在终版中保持不变，执行它们的微架构则采用乱序、多发射、深流水、非阻塞访存与分层预测。本集把五个结构面放在同一张总图里，并给出贯穿终版验收的三个观测量。

体例说明：前六日按功能边界讲清白虹“必须做对什么”，第七日按微架构边界解释终版“为什么这样实现”。第 33–37 集分别展开年龄、宽度、级距、访存与预测；第 38 集用统一事件流和同口径负载收口。

顺序观察路径揭示的三处结构性限制

前六日用五级、单发射、按序执行路径承载完整系统行为：它适合逐拍解释 ISA、异常、MMU、PMP、缓存与外设契约，也把性能瓶颈暴露得足够清楚。终版没有改写这些架构语义，而是用更大的在途窗口和更细的流水级距执行同一套语义。

设计口径与实现证据分开

本日的 12 级主干、3/3/4/3 宽度、ROB64、32 项 uTLB 和四件套预测器是 Whitebow 终版设计候选口径；它们不自动等同于当前仓库已经接通并通过整核验收的实现。参数来源与实现状态见 docs/whitebow-design-parameters.json。

① 吞吐上限：每拍最多一条指令

译码段每拍只处理一条指令，五级之间各一颗边界寄存器；节拍写在 @schedule 里：

prismwhitebow/whitebow.prism · 节拍
@schedule WhitebowCpu {
    bitwidth  : { data:64 }
    pipeline  : 5 stage
    reset     : async_low
    clock     : 100 MHz, domain = single
    resource  : none
    latency   : 5 cycle
}

无论流水线里有多少条已就绪的指令，每拍最多进入一条、退休一条——IPC 的理论上限是 1.0。单发射窗口中的观测值为 0.787；它用于说明一宽出口的上限，而不是终版性能结论。终版把取指、译码、重命名和提交分别定宽，由最窄的持续供给级决定长期吞吐。

② 顺序等待：一条指令等数据，后续指令全部阻塞

冒险裁决列出十个停顿/冲刷源；其中八类停顿合成一根前端冻结信号 hold_fe——任意一类有效，PC 与 IF/ID 一并冻结：

prismwhitebow/iu/hazard.prism · 停顿与冲刷的十个源
    src_fetch = icache_miss
    src_load  = load_use
    src_div   = div_hold
    src_fdiv  = fdiv_hold
    src_dmiss = dcache_miss       // 可缓存 load 未命中 ∨ 填充中（含检出拍，见 dcache.prism 的 busy）
    src_mmiss = mmu_miss          // MMU 走表未定案：与 dcache 占用同款形状（load/store 就站在 EX/MEM 里等翻译）
    src_amo   = amo_miss          // AMO 读/写相位未走完：同款形状（读交付前/写落地前都要占住）
    src_mis   = mis_miss          // 未对齐拆两笔：第一笔只拿到半个操作数，第二笔落地前放走就是拿半字当全字
    src_br    = ex_redirect
    src_trap  = mem_except
prismwhitebow/iu/hazard.prism · 前端冻结
    hold_fe   = (src_fetch | src_load | src_div | src_fdiv | src_dmiss | src_mmiss | src_amo | src_mis) & !redirect

后果很直接：一条 load 等待 miss（几十到上百拍）、一条除法等待 35 拍，这期间后续指令即使与它完全无关，也一条都不能执行。在用于说明停顿来源的 600 拍窗口中，128 拍（21.3%）没有退休；这组局部数据只承担“等待会连坐”的证据。终版保留按序提交，却允许就绪的年轻指令先执行并把结果保存起来。

按序的约束还体现在前递上：操作数按"在流水里的位置"分两级取——位置即年龄：

prismwhitebow/iu/hazard.prism · 两级前递
    fwd_a = match {
        (mem_reg_wen & (mem_rd != 0) & (mem_rd == ex_rs1)) => 1,
        (wb_reg_wen  & (wb_rd  != 0) & (wb_rd  == ex_rs1)) => 2,
        _                                                  => 0,
    }

这条规则的成立同样依赖"流水线严格按序"；年龄改用唯一编号（tag）之后，前递匹配方式一并更换（第 33 集）。

③ 频率上限：一拍内的组合路径过长

缓存与存储器按组合逻辑读：命中在当拍返回数据——

prismwhitebow/iu/icache.prism · 头注
// =============================================================================
// icache.prism — 指令缓存（直接映射，16 行 × 每行 4 字）
//
// 容量 64 字 = 256 字节；行大小 4 字（16 字节，装得下 4 条标准指令或 8 条 RVC）；
// 直接映射，无替换策略；命中组合读出（同拍出，与 im 的 1RW 口径一致）。

时钟周期不能短于一拍内最长的组合路径。取指这一拍里串着完整的 SRAM 读出，访存那一拍同样；切成五段之后每段仍然很长，主频因此受限。要提高频率，必须先把"读"移出当拍（改为在拍沿寄存），再细分流水段（第 35 集）。

另有两处问题被上面的结构放大

访存延迟：停顿表里 dmiss / mmiss / amo 三项都来自访存，且一次缺失就冻结整条流水线——它是空拍的最大单一来源，需要把访存改为非阻塞（第 36 集）。误预测代价：一旦流水线加深（③ 的解法），同样一次猜错要冲刷的级数更多，预测准确率的价值随之放大（第 37 集）。

对症的五种技术：各自的引入条件

上面三处限制与两处放大问题，逐一对应五种技术。每一种都有明确的引入条件与前置依赖——不是"越多越好"，而是针对哪类瓶颈、在什么前提下才成立：

要解决的问题技术引入条件前置依赖
② 顺序等待：一条等数据，后续全部阻塞乱序执行：重命名 + ROB + 发射队列 + 访存队列等待事件的时间远大于指令本身（miss 几十到上百拍、除法 35 拍），且等待点之后有足够多独立指令可执行每条指令有唯一编号（tag）；前递与唤醒从"按位置"改为"按 tag"
① 吞吐上限：IPC 逼近 1.0多发射：取指 / 译码 / 重命名 / 提交加宽单发射成为下一瓶颈：等待类停顿被处理之后，流水线中仍有可并行的指令流寄存器堆多端口、旁路网络按 tag 匹配、提交口支持一拍多条
③ 组合路径限制主频深流水 + 同步读瓶颈是频率而不是每拍条数时（组合路径无法再压缩）各级输入必须"上一拍就绪"——缓存与寄存器堆先改同步读，前端拆分流水级并加指令缓冲
访存延迟冻结整条流水线非阻塞访存 + 私有 L2 + 总线事务接口miss 是空拍的最大来源，且乱序已能承接"流水线继续执行"在途登记（地址表 + 填充表）；收益由乱序兑现
深流水放大误预测代价预测升级：返回地址栈 + 四件套预测器流水线加深之后，或分支密集负载上冲刷损失占比上升时无（可独立生效）；收益判据只能落在计数器上

依赖关系决定改动顺序：终版乱序与多发射共用生产者 tag 与重命名（并非所有多发射机器都要求乱序）；同步读是深流水的前提；终版以乱序窗口兑现非阻塞访存的执行重叠（非阻塞缓存本身与乱序并非同一能力）；预测升级是对深流水的回应。顺序不是任意的：先备好地基（同步读、tag），再做宽度与深度上的加法。

三个可自证的度量

判断"性能差"与"改动有效"，需要独立于实现的度量。三个量互相独立：总量（每拍退休条数）、构成（空拍按源归因）、重叠能力（miss 期间独立年轻指令的接纳与完成数）。

度量① 每拍退休条数（IPC）

顺序观察窗口固定为 600 拍：退休 472 条、128 拍零退休，IPC 为 0.787。它是终版比较中的基线窗口；终版成绩必须另以相同镜像、输入和计时区间重新记录。

度量② 空拍率与按源归因

128 拍空拍占 600 拍的 21.3%。关键不是这个百分比，而是每一拍零退休都必须有可复查的周期类别——归因要闭合：按"或"覆盖，不许有对不上的一拍；对不上就按拍打印十个源的取值，直接点名缺了哪一类。判据要写成"什么情况下它会红"——"覆盖率 ≥95%"那种写法永远不会红。这组计数器已有硬件对应：十个源 + 两个缓存起手在 csr 里各有计数器（事件计数的复位映射与可写选择由 CSR 语义定义），第 38 集把它接到跑分上。

度量③ miss 期间，独立年轻指令完成了几条

从目标 load miss 接受到数据交付，记录比它年轻且不依赖它的指令是否被接纳、执行并保存结果。若老 load 尚未完成，年轻指令不能越过它退休；期间出现退休也可能只是更老指令排空，不能据此证明非阻塞。第 36 集用带年龄身份的完成事件验证重叠，退休事件另行核对。

三个量怎么用 ①②描述瓶颈落在哪一类资源，③描述终版是否真的形成执行重叠。三者共同约束最终解释：吞吐、空拍归因与重叠事件必须能互相对账。

小结

  • 三处结构性限制：每拍一条（吞吐上限）、等待连坐（顺序语义）、组合路径限制主频；另有两处被放大：访存延迟冻结流水线、深流水放大误预测代价。
  • 五种技术各有引入条件与前置依赖；改动顺序由依赖决定：先备同步读与 tag 这两块地基，再做宽度与深度上的加法。
  • 三个可自证的度量：IPC 0.787（600 拍窗口）、空拍 21.3% 且逐拍可归因、miss 期间独立年轻指令的完成数（不等于退休数）。
  • 后五集分别展开这五个结构面；它们共用同一套年龄、完成、提交与归因定义。
