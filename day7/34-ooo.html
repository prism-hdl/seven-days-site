乱序
把"位置即年龄"换成"tag 即年龄"

上一集那条前递规则"EX/MEM 里的更年轻"，靠的全是按序——按序时，"在哪儿"就是"什么时候来的"。乱序让这条等式不再成立：同一拍里可以站着年龄相差几十条的指令。这一集把"年龄"重新立起来——重命名、ROB、发射队列、访存队列，四件一起上；恢复靠一次整表写回，不做快照。

位置为什么不能当年龄

第 33 集抽出的那条前递规则——"同一条操作数挂在两处时，先选 EX/MEM 里的那条"——成立的前提只有一个：指令严格按序流过每一级。按序时，"在哪儿"唯一确定"什么时候进来的"；位置就是一座时钟。

乱序把这座时钟拆了：级变成了共享资源。同一拍里，执行单元上可能同时站着一条等了两拍的旧 load 和一条刚发射出来的年轻人——它们在不同的发射队列里排了不同的队，先后由就绪时间决定，不再由位置决定。位置还在，但"位置最新"不再等于"年龄最小"。

年龄要另立一套坐标：每条指令在译码之后领一个编号（tag），编号的大小就是它的年龄——从领到手的那一刻起，这个坐标就定死了，不随它跑多快、被谁插队而变。这一集把让 tag 成立的四件东西一起上：重命名、ROB、发射队列、访存队列。

重命名：从 32 个架构寄存器到 96 个物理寄存器

先看问题。x1 只是一个名字，但后来的指令会反复复用它："读 x1"与"写 x1"里，一半以上的等待根本不用发生——后写 x1 与前读 x1 之间（WAR）、两次写 x1 之间（WAW），只要把名字换掉就能并行。乱序核要做的第一件事：让同名不再同格。

机制照一手参照落成四个数：物理寄存器 96 个（整数侧，preg0 恒零；浮点侧另有 64 个），一拍进 4 条（dispatch 宽 4）。自由表决定"新写分配给哪一个"，有两条纪律：

  • 分配 = 预取 + 掩码：每个 dispatch 槽配一个预取寄存器（共 4 个），下一拍要分配的物理寄存器提前算好；释放信息是一张 96 位掩码——物理寄存器随最后读者退休而置位，分配器对掩码做最低位优先编码取项。不是环形表、不是年龄矩阵：没有 head+N、没有回绕判断，代价是编码器只有一级。
  • 恢复 = 整表写回：反向表 32 × 7 = 224 bit 在需要时一次性送回译码侧，ROB 里不存自由表快照——没有 checkpoint，就没有 checkpoint 可错。

以三条指令为例，看物理寄存器的分配与释放：

拍指令映射变化物理寄存器
0add x1, x2, x3x1 → p5分配 p5；由这次写占用
0sub x1, x4, x5x1 → p6分配 p6；p5 暂不释放——可能尚有更早的读者在引用
3（写 p5 的那条退休）—p5 进入释放掩码（置位），供后续分配
7（写 p6 的那条退休）—p6 释放；回读 x1 仍按最新映射取物理寄存器
释放时机由最后一个读者决定 一个物理寄存器要等到引用它的最后一条指令退休才释放——释放早了，尚未完成的读者会读到不该看到的新值；释放晚了只是少一个可用寄存器。判据用反证：把释放提前一拍，某个读者必须读到本不该读到的写值（红）；不红说明这条逻辑没有覆盖读者这一维。

重命名的对外承诺只有一句：架构上只看得到 32 个名字——退休流里不存在 p5、p6。名字与物理寄存器的对应关系是纯内部状态。

ROB 64：提交的账本

执行可以乱，提交不能乱：异常要精确到某一条，中断要落在程序序的一个点上——所以乱序核仍然只保留一个按序的出口。这个出口由 ROB 把守，照一手参照落成：

  • 64 项（每项 40 bit，编号 iid 7 bit）；提交宽 3——一拍最多退三条。
  • 完成与异常一律按 iid 比对，不按"项在表里的位置"：执行单元报完成时只报出编号，编号独立于指针、每拍 +4（宽的代价都在这里）。
  • 分配指针是 64 位 one-hot 循环移位，不用计数器——"下一项"就是把那一位转一格。
  • 异常不铺满表：全表只留一条 70 bit 的 holding 寄存器 + 一个小状态机——任意位置出现异常，都归到这一处集中处理，不给每一项挂异常位。

账本的时间线（最简三行）：

iid指令状态提交
7lw a0, 0(a1)等待（miss）不动——最老的还没好，谁都别想先走
8add a2, a3, a4已完成等：iid 8 在 iid 7 后面
9xor t0, t1, t2已完成等：同上
7lw a0, 0(a1)数据到7→8→9 一拍退三条，按序、成组

第二、三行是这个形状的全部意义：完成得快不能先走，完成得慢也不许被越过——内部的快慢被出口抹平，外面看起来仍然像一台按序机器。

发射队列：26 项起步，编号唤醒

指令在提交前先住进发射队列——按去处分队：整数 ALU 4+4、分支 6、访存 6、store-data 6，共 26 项起步（对照核满配 52；我们把起点砍半，往哪边加由第 33 集那张归因表说了算）。三条纪律：

  • 唤醒按 tag 广播：执行单元报"我产出了 p17"，各队列用 CAM 找"谁在等 p17"——不再查寄存器堆，也不看位置。这正是第 33 集那条两级前递的替换物：按位置分档 → 按编号匹配。
  • 长延迟单元不铺队列：除法器单 entry + 忙/写回停顿回压 + 在创建侧屏蔽——忙的时候干脆不让新除法进来，而不是给它排一条长队。
  • 完成时复制广播：结果编号复制 5 份，同时喂给各队列的 CAM——一份一份送，晚到的队列就要多等拍。
队列深度是设计参数，不是判据 "26 项"写成判据会出现"参数没调到"也报红的假判据。判据是跑分与归因表：窗口要跨过多大的误预测与多少次 miss，由数据反推，不照抄满配。

访存队列：LQ 16 / SQ 12

访存有两件事天生不同步：store 的地址先算出来，数据可能晚好几拍才到；load 又允许被"更老但还没落地的 store"喂数据（前递）。所以访存单独排队：加载队列 16 项、存储队列 12 项（存储侧另有 8 项写合并缓冲，留到第 37 集展开）。

队列还要管一件事：推测访存的回滚。分支猜错时，被冲掉的 load 不得改状态、被冲掉的 store 不得落地——它们从队列里整段消失，像没发生过。第 37 集会在这条队列上再叠一层：等存储器的时候，队列后面的指令照常退休（按序核在这个窗口里的可退休拍数恒为 0，那一集把 0 变成正数）。

判据怎么钉

  • 总判据一条：退休序与程序序逐条一致——乱序是内部自由，出口必须像按序。这条判据从五级时代立到今天，一字没改，也是后面每一集复用的底账。
  • 归因表复跑：同一张十源表，改动前后各跑一遍——乱序该消掉的是"等"的拍数，不该把停顿换个名字藏起来。
  • 反证三发：释放提前一拍（读者读错值）、提交越过一条（序错）、唤醒匹配错一个 tag（用错操作数）——各自必须红，且红在点名的那一列。

小结

  • 位置是顺序核的时钟；乱序里，年龄改用 tag 记——从分配起定死，不受插队影响。
  • 四件一起上：重命名（96 个物理寄存器、自由表最低位优先、恢复整表写回、无 checkpoint）、ROB 64（iid 比对、one-hot 指针、一条 holding 收异常）、发射队列（26 项起步、tag 广播、长延迟单 entry）、访存队列（LQ 16 / SQ 12）。
  • 对外的承诺只有一条：退休序与程序序逐条一致。内部多自由，出口就多收敛。
  • 下一集加宽：一拍从一条到三条——先动的不是执行单元，是端口、旁路与提交口。
