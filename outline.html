        七日大纲
        已定 22 集

        一个软件工程师，七天，从"发明一门语言"开始，造出能跑操作系统的 RISC-V 处理器。第一日四集讲完工具箱全景——不抠细节，只让读者看见这门语言能造芯片；从第二日起，造物。

        ← 返回落地页 从第 1 集开始
        DAY 1 光 4 集 · 已写完
        "神说，要有光，就有了光。神看光是好的，就把光暗分开了。"—— 《创世记》 1:3–4

        黑暗不是没有工具——硬件开发有两条割裂的路：RTL（周期精确、可综合，但算法与微架构缠在一起），SystemC / TLM（事务级、快，但不可综合）。两条路描述同一个硬件、要各写一遍，行为等价靠人盯。HLS 只补了"算法 → RTL"这一半，输入还得是可综合子集，产不出用于架构探索的 TLM 快模型。

        Prism 的答案：一份源码，同时下降为 RTL + TLM + 独立 Python golden，三方 cosim 闭环逐拍对撞。名字（棱镜）就是这张图——一束算法折射出两道光谱，第三个棱面独立验收。

        第一日不逐条讲语法——四集把整门语言铺开一次，让读者先看全景，知道"这门东西真能做一颗 CPU"。

        EP 1
        一道裂缝：为什么要有 Prism
        RTL 与 TLM 两条路各写一遍的痛（结构层），加上"语言本身不像在想电路"（表达层）。Prism 的答案：一束光、三道棱面。最小示例是一颗加法器——它会在第 7 集改造成 ALU；20 分钟三下降全绿。
        EP 2
        分层与语法骨架
        module 只写"做什么"，@schedule 才补"怎么做"。这一集从一只盒子讲起（端口 / 线 / 状态），把语法面一次讲全：端口 in/out/both、类型、四种分支、on clock、fsm、mem 阵列与 run 的 image 装载（@load 外部镜像、--image 只换文件）、泛型形参——一颗进程调度单元（进程五态 + 时间片）把骨架装起来。
        EP 3
        聚在一处：组装与抽象
        design 的装配规矩展开（connect / wire / expose + 顶层端口推导）；再把零件多起来之后的 interface（契约）/ composer（封装，展平透明）/ import（分文件）逐一展开。全篇按"遇到什么麻烦、于是有什么手段"的因果写法展开——第一日不出现整机。
        EP 4
        让光打出去：工具箱全开
        不写新代码：先重贴 mini_cpu.prism 全文；静态四件（check / typecheck / keywords / dump-ast）全量输出逐段解读；gen-rtl / gen-tlm 展示完整产物（154 行 SV + 230 行 SystemC）；run 三档各跑一遍、cosim 摆到同一张桌上对撞。工具这半边到此为止。
        DAY 2 空气与水 7 集 · 已写完
        "神说，诸水之间要有空气，将水分为上下。"—— 《创世记》 1:6

        一台 CPU 里流着两条水——数据（值）与控制（决定值什么时候被允许流过）。每一颗器官都在自己内部把这两条水分开一次：pc 分"当前值"与"下一步"，regfile 分"读写数据"与"写使能 / 地址"，ALU 分"操作数"与"选路"，decoder 干脆整颗就是一束控制位。这一天把最小 RV64I 处理器（64 位数据通路）的所有原料讲完——每颗各自能测；最后原料合体，跑一段冒泡排序：先有零件，再谈身体——然后让它做事。

        EP 5
        PC — 下一步
        reg + on clock，全部决策就在 load ? target : pc + 4 这一个三目里。顺行走 +4、跳走用 target——用 bne x2, x0, loop 那段真循环讲清：-8 来自 B 型立即数，不是 pc 自己有的数。宽度钉死 64，不留泛型。
        EP 6
        记忆：regfile / ram / im / dm
        寄存器堆 32 项 2 读 1 写、x0 由它自己保证恒零（读侧给 0 + 写侧丢弃）；字阵列异步读 + 同步写——单周期核必须这个形状。哈佛 = 同一份源码例化两次。
        EP 7
        ALU — 活动
        第一集那颗加法器在这里成年——十条路一张 match 表，写起来是表，长出来是十个并列运算加一个多路选择器。三条边界：不掩移位量、不产生标志位、不做多周期的事。
        EP 8
        decoder — 理解世界
        整颗纯组合表达式：字段切片、五种立即数格式、控制位分派。理解 = 把外界字符串翻译成内部动作，理解不了就说"我不懂"。
        EP 9
        cpu_top：一具身体
        四颗器官一行不改地从 examples/day2/ import 进来（唯一缺口是顶层要替分支补一列 alu_op_b）；im / dm 是同一颗 ram 的两个实例（W = u32 / W = i64）；程序写在 run 的 image 段；27 跑出 x1 = 15，另有三列各自见证分支没跳、W 后处理、LD/SD 往返。golden / RTL / SystemC 三条腿逐拍全等。
        EP 10
        跑一段真程序 · 从 C 到裸镜像
        芯片一行不改，机器码也不用手抄：sort.c 交给 riscv64-elf-gcc，sort.ld 定地址图，objcopy 拆出 .text（20 条）与 .data（六个数），image 的 @load 分别灌进 im 与 dm。20 条编码全在第 8 集那本字典里——一条线都不用加。181 拍排成形；判据读的是 dm 里那六个字，不是程序自报的完工位——写反比较它就不成立，换成数拍子它立刻放行。
        EP 11
        第四方对撞：官方 sail 模型
        三条腿（golden / RTL / TLM）是同一棵 AST 下降出来的——前端共有的 bug 三家一起错。请 RISC-V 官方规范的可执行模型进场：sail_riscv_sim，独立实现、能吐退休序。用法四件：--sail-mem 实例.mem 取设计里的镜像；五根约定列 retire_*；逐条比 pc/rd/写回值，缺列拒绝降级；对齐靠一颗一拍延迟的观测寄存器。反证：摘掉 W 型后处理，golden 与 RTL 自比仍全等，sail 一条抓到 idx21。
        DAY 3 天上光体，定节律 · 白虹立起来 4 集已写完
        "天上要有光体，可以分昼夜、作记号、定节令、日子、年岁。"—— 《创世记》 1:14

        这一日立一个 flag，并把它的第一层节拍搭起来。第二日那颗核是真的——它排过序、三条通路逐拍对撞过——但五条差距每一条都指得到具体代码：一拍做完取指·运算·访存·写回（那条组合路径就是周期的下限）；im 1KB / dm 2KB、取指只切 pc.addr[9:2]；只有 M 态、没有陷阱通路；没有 timer 也没有外部中断线；访存只认双字一条路。这一日的目标：造一颗能跑 Linux 的处理器，并给它一个正式的名字——白虹（Whitebow）。典出《战国策·魏策》"聂政刺韩傀，白虹贯日"：白色虹霓直冲太阳，本身就是光的折射现象，正合 Prism（棱镜）的立命之本；而刺客一剑破日的杀伐气，正合"用 Prism 写 CPU 是硬仗"。

        验收口径也在这一日立起来，后面每一日都按它交卷。三层测试台：核内（tests/test_cpu.py——31 个用例、411 次断言，形态是"run 表的行内期望自判 + golden / RTL 双通路 + 变异反证"）、整机（tests/test_soc.py——镜像装载、交棒、控制台）、外设（uart 与宿主对端）。跑什么由 --image 决定，芯片一个字不改。

        EP 12
        立 flag：缺的四样
        先把"跑不了"和"跑得慢"分开：流水、cache、指令密度是后者；MMU、S / U 态、异常处理、必须的指令面是前者。三样各点名 Linux 哪一步会踩空——S 态（ecall 的语义、护住内核、mret 的落点）、异常（缺页 / 时钟 / 系统调用都是正常路径，要 mtvec / mepc / mcause / mtval，还要冲掉比它年轻的指令）、MMU（没有页表就没有写时复制、没有约定地址、没有进程）。这四样谁也离不开谁：许可表里没有 opcode 0x73（SYSTEM：CSR 读写 + ecall + sfence.vma），Zicsr 是前三样的载体；A 与 D 同为硬门槛，M 与 C 不算。其余差距列成登记表各归各集。命名白虹。这一集不写新硬件。
        EP 13
        五级流水线数据通路
        whitebow/pipe/ 五颗 composer：IFU / IDU / EXU / LSU / TRAP；@schedule 把节拍钉成 pipeline : 5 stage + latency : 5 cycle + clock : 100 MHz。四颗边界寄存器 IfId（7 根）/ IdEx（30 根）/ ExMem（22 根）/ MemWb（11 根 + 一根 commit）按"谁写它的 d 侧，谁就也管它的 en / clear"分给四段——段寄存器不是公共财产。取指窗口是两个字（im_rdata + im_rdata_hi）：半字对齐靠 if_parcel 拼，if_step = if_is_rvc ? 2 : 4 由 IFU 报、pc.step 执行；ext/rvc.prism 纯组合展开，非法编码展开成 illegal 留给下一集。插槽先于内容：形参里的 csr 第 15 集才填，bp 与 frf 要到第五日才有货。判据：whitebow_cpu_demo 退休序 75 条逐条钉死。
        EP 14
        冒险：停顿、前递、冲刷
        裁决全收在 iu/hazard.prism 一处：八个占用源（src_fetch / src_load / src_div / src_dmiss / src_mmiss / src_amo / src_br / src_trap）合成四路 hold、三路 kill；hold=1 整级保持，kill=1 数据照装而 valid 清 0；MemWb 没有 kill，只有一根 commit——唯一的精确提交点在 MEM。Load-Use 就一行判据；前递两路 EX/MEM→EX 与 MEM/WB→EX，EX/MEM 压 MEM/WB，ID 级另有 wb→rs 旁路。分支误预测冲两级、固定 2 拍惩罚，异常冲三级。多拍：div / rem 由 Divider 整段占用 EX（五态、radix-4 每拍消 2 位商、latency : 35 cycles、握手 start / cancel / busy / done），mul 单拍组合，两者同收一根 is_word。判据：hazard_check 16 拍 × 8 列、divider_check 32/32。流水的代价全在这一集显形。
        EP 15
        CSR 与特权级
        ext/csr.prism 的 module CSR + design CsrTop，由核直接例化再注入 IFU / IDU / LSU / TRAP 四段——它是唯一跨段共享的状态。白名单 49 个号（M 36 + S 11 + U 2），M 那 36 个含 PMP 的 18 个：寄存器面先落，真正的过滤留到第五日。号表在 decoder 与 CSR 里各有一份，靠测试逐地址对账钉住不分叉。mstatus 的 WARL 三条常量：可写掩码 0xC19AA、SXL = 2 只读、MPP 撞非法编码向上取而 SPP 写不落。优先级就是一条 match 的顺序：中断 → 12 取指缺页 → 2 非法 → 3 ebreak → 11 / 9 / 8 ecall → 13 / 15 → 7 → 4 → 6；mtval 按 cause 分档（2 给指令、4 / 6 / 7 / 13 / 15 给地址、12 给 pc），mepc 写那条指令自己的 pc。中断：mip 的 hw 位 bit 3 / 5 / 7 / 11 一位一线合成，STIP 由 mtime >= stimecmp 自己比出来，mideleg 只收 0x222，MEI > MSI > MTI > STI，采样点在 MEM 提交级。判据：csr_check 54/54（80 拍 × 27 列）+ csr_msi 14 + csr_gate 21。CPU 会疼了。边界照实写：只有 M / S 两态（sret 恒回 S）、wfi 是 NOP——归第 20 集；satp 只存不译——归第五日。
        DAY 4 有生命的活物 · 跑起 OpenSBI 2 集已写完 · 5 集待定
        "地要生出活物来，各从其类。"—— 《创世记》 1:24
        EP 16
        中断：CLINT 与 PLIC
        soc/ip/clint.prism（msip 进 mip[3]、mtime 可读写、Sstc 的 stimecmp 比出 STIP）+ soc/ip/plic.prism（每源一位 gateway、claim 登记 in_service、threshold 只门控通知——照规范 §8）；优先级 MEI > MSI > MTI > STI。CPU 会躲了。
        EP 17
        指令面长大：M · A · C
        ext/mul.prism（一条 64×64 乘法器 + "补什么/取哪半"做出 mul / mulh / mulhsu / mulhu 与 mulw）、ext/amo.prism（LR/SC 预约与 AMO 读改写：判决与清除差一拍、rd 给写前旧值）、ext/rvc.prism（象限分派展开器，参照编码由工具链汇编给出）。跑 OpenSBI 要的 amo 与压缩指令都在这一集补齐；F / D 定在第六日 FPU 那一集。
        EP 18
        soc.prism：把核放进一片真芯片
        一颗 SoC = 一个 design：Whitebow + ROM + DDR + Uart8250 + CLINT + PLIC。地址图整个交给 MemoryMap——它收实例不收端口，译码、片选门控、读数据选择与不可缓存属性（dm_nc）都在它体内做完，顶层只剩中断路由那几根线。地址只有一套口径：字节物理地址，与 fw/sbi.dts 各节点的 reg 是同一批数；取指口 PA[39:2] 与数据口 PA[39:3] 先各自补零归一成 PA 再进窗口。命中判据是范围比较不是位选窗——位选窗会让高位别名进窗口。DDR 128MB 里是一张槽位表：OpenSBI、固件自己的运行区（scratch / 栈 / 堆，这一段不给任何镜像）、DTB、fw_dynamic_info、内核，每条窗口的终点正是下一条的起点。这一集之后，换程序就只剩换镜像这一件事。
        EP 19
        uart8250：让芯片开口说话
        一颗 IP 三层：UartTx / UartRx（8N1 引擎，分频 DIVISOR = CLOCK_FREQ / BAUD_RATE 是编译期常量、RX 在位中点采样）+ Uart8250Regs（8250 寄存器面）+ composer Uart8250。面是最小面：THR 写触发发送、RBR 读即消费、LSR 只给 DR(0) / FE(3) / THRE(5) / TEMT(6)、LCR[7] = DLAB；没有 IER / IIR / FCR，也没有 16 字节 FIFO，DLL / DLM 写了被忽略，其余寄存器读 0；寄存器号 = 字内字节偏移（64 位字 ⇒ 步长 8）。FE 是 sticky 的，读 LSR 才清——由 run 的行内期望逐拍抓住。引脚接宿主：host : { console = uart_8n1(tx = uart.tx_pin, rx = uart.rx_pin, divisor = 10) }，对端 --host console=stdio|pty|file:<前缀>；.tx 启动即清空、每解出一字节立刻落盘——百万拍长跑里唯一的实时进度。判据：until : console.tx.count >= 3，期望是"tx 内容与宿主喂进去的逐字节相同"。
        EP 20
        模式切换与系统调用
        ecall 按当前态报 cause 8 / 9 / 11（U / S / M）、ebreak 报 3；mret 回 mstatus.MPP，sret 恒回 S（源码注释：本核没有 U）——这一集把"谁能跳到哪一态"逐条画清楚，M / S 两态是这台机器此刻的真实边界。委托：medeleg 收全值不掩，mideleg 只收 0x222（SSIP / STIP / SEIP）。S 态面 stvec / sscratch / sepc / scause / stval 齐；satp 号在、只存不译，mmu_en / mmu_root_ppn / mmu_asid 三个消费出口留给第五日。计数器门按最小集落：mcounteren 只 TM 一位、scounteren / mcountinhibit 号在读零、menvcfg 只 STCE(bit63) 且复位即 1（Sstc 的 stimecmp 靠它）。wfi 现在译成 NOP——这台机器不睡，只是白等。
        EP 21
        Verilator 第二后端：跑得起百万拍
        --rtl --sim verilator：SV 编成 C++ 模型 + harness 成动态库，ctypes 加载直跑，跳开 vvp 的解释执行（run_soc.sh 记的实测：iverilog 四态约慢 26×）。DDR 走 storage : ram = host ⇒ 生成 import "DPI-C"，iverilog 13.0 连这句都不 parse——这条腿不是加速，是准入。--time 按时长封顶，换算读 @schedule 的 clock（100 MHz ⇒ 一拍 10 ns），不硬编码。别碰 verilator 的 --threads：实测 4 线程慢 1.7×、8 线程慢 2.7×，能并行的只有编译期 jobs。还有一坑必须写进正文：run --rtl 缺 @schedule 时只 warn 就照常打表，"RTL tb 跑完"可以是假的——gen-rtl / cosim 有硬门，run 腿没有。
        EP 22
        OpenSBI 起 banner 与交棒
        ROM 本体自带一段 Boot stub（soc/ip/rom.prism）：算好 a1 = DTB 0x80100000、a2 = fw_dynamic_info 0x80108000（magic 0x4942534F、next_addr = 0x80200000、next_mode = 1），末条 jalr 跳 0x80000000——它就是这颗芯片上的"上一个 booting stage"，a0（hartid）不设，交给 OpenSBI 自己按复位 pc 推。固件 / DTB / 内核三份数据全写在 run 的 image 段，换哪一份都是 --image，芯片一个字不动。三条真病因按时间排：AMO 同拍先写后读；DTB 槽位压在固件自己的栈区被踩 ⇒ libfdt 报 BADMAGIC（所以那条槽是算出来的，不是抄来的）；缺 scounteren / mcountinhibit 门。长跑 until : console.tx.count >= 16；banner 是百万拍级，所以常驻套件只把窗口封顶在 Boot stub 那几十拍，百万拍那一跑在套件之外手动做。第四日收在这里：机器会喊人了。
        DAY 5 照着形象造人 · 更快、更守规矩 条目待定
        "使他们管理海里的鱼、空中的鸟、地上的牲畜。"—— 《创世记》 1:26

        条目：ICACHE（18 拍 × 3 列认证、fence.i 扳机、失效按 B 落地）；DCache（占用期挤掉 EX 前递源那个洞——冻结 MEM/WB + 寄存提交脉冲）；分支预测（BTB + BHT 按 PC 预测、IF 不译码、误预测就是 src_br；OpenSBI IPC 0.787 vs 0.680）；MMU 与 Sv39（TLB、PTW、缺页号）；PMP（16 条目、cfg 落位与按条目 L 锁定、pmpaddr 的 WARL）。
