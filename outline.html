七日大纲
38 集

一个软件工程师，七天，从"发明一门语言"开始，造出能跑操作系统的 RISC-V 处理器。第一日四集讲清本书已经露面的语言规则与工具入口——不抠细节，只让读者看见这门语言能造芯片；从第二日起，造物。

DAY 1 光 4 集
"神说，要有光，就有了光。神看光是好的，就把光暗分开了。"—— 《创世记》 1:3–4

黑暗不是没有工具——硬件开发有两条割裂的路：RTL（周期精确、可综合，但算法与微架构缠在一起），SystemC / TLM（事务级、快，但不可综合）。两条路描述同一个硬件、要各写一遍，行为等价靠人盯。HLS 只补了"算法 → RTL"这一半，输入还得是可综合子集，产不出用于架构探索的 TLM 快模型。

Prism 的答案：一份源码，同时下降为 RTL + TLM + 独立 Python golden，三方 cosim 闭环逐拍对撞。名字（棱镜）就是这张图——一束算法折射出两道光谱，第三个棱面独立验收。

第一日不逐条讲语法——四集把本书已经露面的语言规则与工具入口讲完整，让读者先看全景，知道"这门东西真能做一颗 CPU"；它不是整门语言的完整参考手册。

第 1 集
一道裂缝：为什么要有 Prism
RTL 与 TLM 两条路各写一遍的痛（结构层），加上"语言本身不像在想电路"（表达层）。Prism 的答案：一束光、三道棱面。最小示例是一颗加法器——它会在第 7 集改造成 ALU；20 分钟三下降全绿。
第 2 集
分层与语法骨架
module 只写"做什么"，@schedule 才补"怎么做"。这一集从一只盒子讲起（端口 / 线 / 状态），讲完整模块内已经使用到的规则：Signal/Stream 方向、类型与转换、分支、on clock、fsm、mem 与 image 时相，以及 bits/int/type 泛型边界——一颗进程调度单元（进程五态 + 时间片）把骨架装起来。
第 3 集
聚在一处：组装与抽象
design 的装配规矩展开（connect / wire / expose + 顶层端口推导）；再把零件多起来之后的 interface（契约）/ composer（封装，展平透明）/ import（分文件）逐一展开。全篇按"遇到什么麻烦、于是有什么手段"的因果写法展开——第一日不出现整机。
第 4 集
让光打出去：工具箱全开
不写新代码：先重贴 mini_cpu.prism 全文；静态四件（check / typecheck / keywords / dump-ast）全量输出逐段解读；gen-rtl / gen-tlm 展示完整产物（154 行 SV + 230 行 SystemC）；run 三档各跑一遍、cosim 在同一份激励下对撞。工具这半边到此为止。
DAY 2 空气与水 7 集
"神说，诸水之间要有空气，将水分为上下。"—— 《创世记》 1:6

一台 CPU 里流着两条水——数据（值）与控制（决定值什么时候被允许流过）。每一颗器官都在自己内部把这两条水分开一次：pc 分"当前值"与"下一步"，regfile 分"读写数据"与"写使能 / 地址"，ALU 分"操作数"与"选路"，decoder 干脆整颗就是一束控制位。这一天把RV64I 教学子集处理器（64 位数据通路）所需的原料讲完——每颗各自能测；最后原料组装成顶层，跑一段真程序：先有零件，再谈整机——然后让它做事。

第 5 集
PC — 下一步
reg + on clock，全部决策就在 load ? target : pc + 4 这一个三目里。顺行走 +4、跳走用 target——用 bne x2, x0, loop 那段真循环讲清：-8 来自 B 型立即数，不是 pc 自己有的数。宽度钉死 64，不留泛型。
第 6 集
记忆：regfile / ram / im / dm
寄存器堆 32 项 2 读 1 写、x0 由它自己保证恒零（读侧给 0 + 写侧丢弃）；字阵列异步读 + 同步写——单周期核必须这个形状。哈佛 = 同一份源码例化两次。
第 7 集
ALU — 活动
第一集那颗加法器在这一集补齐——十条路一张 match 表，写起来是表，综合出来是十个并列运算加一个多路选择器。三条边界：不掩移位量、不产生标志位、不做多周期的事。
第 8 集
decoder — 理解世界
整颗纯组合表达式：字段切片、五种立即数格式、控制位分派。理解 = 把指令编码翻译成内部动作，非法编码报 illegal。
第 9 集
CpuTop：一具身体
四颗器官一行不改地从 examples/day2/ import 进来（唯一缺口是顶层要替分支补一列 alu_op_b）；im / dm 是同一颗 ram 的两个实例（W = u32 / W = i64）；程序写在 run 的 image 段；27 跑出 x1 = 15，另有三列各自见证分支没跳、W 后处理、LD/SD 往返。golden / RTL / SystemC 三条腿逐拍全等。
第 10 集
跑一段真程序 · 从 C 到裸镜像
芯片一行不改，机器码也不用手抄：sort.c 交给 riscv64-elf-gcc，sort.ld 定地址图，objcopy 拆出 .text（20 条）与 .data（六个数），image 的 @load 分别灌进 im 与 dm。20 条编码全在第 8 集那本字典里——一条线都不用加。181 拍排成形；判据读的是 dm 里那六个字，不是程序自报的完工位——写反比较它就不成立，换成数拍子它立刻放行。
第 11 集
第四方对撞：官方 sail 模型
三条腿（golden / RTL / TLM）是同一棵 AST 下降出来的——前端共有的 bug 三家一起错。请 RISC-V 官方规范的可执行模型进场：sail_riscv_sim，独立实现、能吐退休序。用法四件：--sail-mem 实例.mem 取设计里的镜像；五根约定列 retire_*；逐条比 pc/rd/写回值，缺列拒绝降级；对齐靠一颗一拍延迟的观测寄存器。反证：摘掉 W 型后处理，golden 与 RTL 自比仍全等，sail 一条抓到 idx21。
DAY 3 天上光体，定节律 · 白虹立起来 4 集
"天上要有光体，可以分昼夜、作记号、定节令、日子、年岁。"—— 《创世记》 1:14

这一日立一个 flag，并把它的第一层节拍搭起来。第二日那颗核是真的——它排过序、三条通路逐拍对撞过——但五条差距每一条都指得到具体代码：一拍做完取指·运算·访存·写回（那条组合路径就是周期的下限）；im 1KB / dm 2KB、取指只切 pc.addr[9:2]；只有 M 态、没有陷阱通路；没有 timer 也没有外部中断线；访存只认双字一条路。这一日先立下“运行 Linux”的目标，并给终版处理器一个正式的名字——白虹（Whitebow）。本日落地的是教学流水与异常基础，完整能力在后续几日闭合。典出《战国策·魏策》"聂政刺韩傀，白虹贯日"：白色虹霓直冲太阳，本身就是光的折射现象，正合 Prism（棱镜）的立命之本；而刺客一剑破日的杀伐气，正合"用 Prism 写 CPU 是硬仗"。

验收口径也在这一日立起来，后面每一日都按它交卷。三层测试台：核内（tests/test_cpu.py——31 个用例、411 次断言，形态是"run 表的行内期望自判 + golden / RTL 双通路 + 变异反证"）、整机（tests/test_soc.py——镜像装载、交棒、控制台）、外设（uart 与宿主对端）。跑什么由 --image 决定，芯片一个字不改。

第 12 集
立 flag：缺的四样
先把"跑不了"和"跑得慢"分开：流水、cache、指令密度是后者；MMU、S / U 态、异常处理、必须的指令集扩展是前者。四样各点名 Linux 哪一步会踩空——S 态（ecall 的语义、护住内核、mret 的落点）、异常（缺页 / 时钟 / 系统调用都是正常路径，要 mtvec / mepc / mcause / mtval，还要冲掉比它年轻的指令）、MMU（没有页表就没有写时复制、没有约定地址、没有进程）。这四样谁也离不开谁：许可表里没有 opcode 0x73（SYSTEM：CSR 读写 + ecall + sfence.vma），Zicsr 是前三样的载体；A 与 D 同为硬门槛，M 与 C 不算。其余差距列成登记表各归各集。命名白虹。这一集不写新硬件。
第 13 集
五级流水线数据通路
examples/day3/pipe5.prism：第二日那颗核一行不改，中间插四颗段寄存器（stage_regs.prism 的 IfId / IdEx / ExMem / MemWb），把第 12 集量出的 111 级组合路径切成五段、最长一段 34 级。这一集 hold / kill 全接 0——先跑通，冒险留给下一集；段寄存器的三种命运（正常装载 / 整级保持 / 数据照装而 valid 清 0）在这里立起来。判据：pipe5_check 17 拍 × 6 列全等（golden 与 RTL 对撞）。
第 14 集
冒险：停顿、前递、冲刷
examples/day3/pipe5h.prism：裁决全收在一颗纯组合的 Hazard 里——hold_ifid 与 kill_idex 是一对（只做一半会把指令顶掉）；前递两路 EX/MEM→EX 与 MEM/WB→EX，EX/MEM 压 MEM/WB，load-use 递不了只能停一拍；分支在 EX 才定案，冲两级、固定 2 拍惩罚；valid 挡在访存口与写回口。段寄存器因此有 30 个字段。判据：pipe5h_check 12 拍 × 9 列全等 + 三发反证（拆前递 / 拆 hold / 拆 flush）。教学范围：这一片只解释停顿、前递与冲刷，不承担多拍除法的实现说明。
第 15 集
CSR 与特权级
先以 M/S 教学 CSR 说明号表、权限、WARL 与陷阱进退；再解释终版白虹的状态所有权。教学示例不是整机能力表；终版 M/S/U 转换见第 20 集，PMP 与 MMU 的消费路径见第五日。CSR 语义由读写期望、权限矩阵与陷阱事件流分别验证。
DAY 4 有生命的活物 · 跑起 OpenSBI 7 集
"地要生出活物来，各从其类。"—— 《创世记》 1:24
第 16 集
中断：CLINT 与 PLIC
examples/day4/clint.prism（msip 进 mip[3]、mtime 可读写、Sstc 的 stimecmp 比出 STIP）+ examples/day4/plic.prism（每源一位 gateway、claim 登记 in_service、threshold 只门控通知——照规范 §8）；优先级 MEI > MSI > MTI > STI。三根线怎么接进核在 examples/day4/intr_link.prism（判据 intr_link_check 5 拍 × 2 列全等）。中断通路打通。
第 17 集
指令集扩展：M · A · C
examples/day4/mul.prism（一条 64×64 乘法器 + "补什么/取哪半"做出 mul / mulh / mulhsu / mulhu 与 mulw）、examples/day4/amo.prism（LR/SC 预约与 AMO 读改写：判决与清除差一拍、rd 给写前旧值）、examples/day4/rvc.prism（象限分派展开器，参照编码由工具链汇编给出）。不改 OpenSBI 源码——官方默认构建的固件就要用 amo 与压缩指令（反汇编可数：amo 族 16 条 · 乘除族 34 条 · 压缩两万六千条），这一集把它们补齐。
第 18 集
把 CPU 装进 SoC
一颗 SoC = 一个 design：Whitebow + ROM + DDR + Uart8250 + CLINT + PLIC。地址图整个交给 MemoryMap——它收实例不收端口，译码、片选门控、读数据选择与不可缓存属性（dm_nc）都在它体内做完，顶层只剩中断路由那几根线。地址只有一套口径：字节物理地址，与 fw/sbi.dts 各节点的 reg 是同一批数；取指口 PA[39:2] 与数据口 PA[39:3] 先各自补零归一成 PA 再进窗口。命中判据是范围比较不是位选窗——位选窗会让高位别名进窗口。DDR 128MB 里是一张槽位表：OpenSBI、固件自己的运行区（scratch / 栈 / 堆，这一段不给任何镜像）、DTB、fw_dynamic_info、内核，每条窗口的终点正是下一条的起点。这一集之后，换程序就只剩换镜像这一件事。
第 19 集
uart8250：接上串口
一颗 IP 三层：UartTx / UartRx（8N1 引擎，分频 DIVISOR = CLOCK_FREQ / BAUD_RATE 是编译期常量、RX 在位中点采样）+ Uart8250Regs（8250 寄存器面）+ composer Uart8250。面长到多大由消费者决定：OpenSBI 只要 THR/RBR/LSR 就能出声；Linux 的 autoconfig() 三道判据（IER 存在性 / 回环 / FIFO 档位）逼出 IER、IIR/FCR、MCR/MSR 与 SCR；两个 16 深 FIFO 与字符超时由"背靠背突发 / 键盘敲进内核"逼出来；THRE 必须上中断线。寄存器号 = 字内字节偏移（64 位字 ⇒ 步长 8）。FE 是 sticky 的，读 LSR 才清——由 run 的行内期望逐拍抓住。引脚接宿主：host : { console = uart_8n1(tx = uart.tx_pin, rx = uart.rx_pin, divisor = 10) }，对端 --host console=stdio|pty|file:<前缀>；.tx 启动即清空、每解出一字节立刻落盘——百万拍长跑里唯一的实时进度。判据：until : console.tx.count >= 3，期望是"tx 内容与宿主喂进去的逐字节相同"。
第 20 集
模式切换与系统调用
终版白虹支持 M/S/U。ecall 按发起态产生 cause 8/9/11；mret 与 sret 分别读取 MPP/SPP 返回，委派决定陷阱进入哪一层。第 15 集只含 M/S 的代码是教学简化，不是白虹缺少 U 态的开发阶段。
第 21 集
换成跑得更快的 Verilator
RTL 长跑使用 Verilator 编译模型与统一运行器；host 存储经 DPI 访问仿真宿主，不属于可综合 DDR 控制器。四态验证与长跑各有用途，运行时间、模拟周期和真实硬件主频分开说明。
第 22 集
OpenSBI 起 banner 与交棒
ROM 本体自带一段 Boot stub（soc/ip/rom.prism）：算好 a1 = DTB 0x80100000、a2 = fw_dynamic_info 0x80108000（magic 0x4942534F、next_addr = 0x80200000、next_mode = 1），末条 jalr 跳 0x80000000——它就是这颗芯片上的"上一个 booting stage"，a0（hartid）不设，交给 OpenSBI 自己按复位 pc 推。固件 / DTB / 内核三份数据全写在 run 的 image 段，换哪一份都是 --image，芯片一个字不动。启动链由三条终版约束闭合：AMO 读改写的阶段顺序、DDR 槽位与固件运行区的隔离、CSR 号表对固件控制状态的覆盖。长跑 until : console.tx.count >= 16；banner 是百万拍级，所以常驻套件只把窗口封顶在 Boot stub 前 2000 拍，百万拍那一跑在套件之外手动做。第四日收在这里：机器能起 OpenSBI 了。
DAY 5 照着形象造人 · 更快、更守规矩 5 集
"使他们管理海里的鱼、空中的鸟、地上的牲畜。"—— 《创世记》 1:26

五集分别讲解：更快（取指、访存、分支各一条路），也更守规矩（地址翻译与内存保护）。

第 23 集
ICache：取指不再等存储器
指令缓存落地：28 拍 × 3 列逐拍认证（另失效扫描 37 拍）；自修改代码的扳机是 fence.i（失效路径按 B 落地）。
第 24 集
DCache：访存多拍，前递源的生命周期要重算
用一次完整访存解释接收、所有权、等待、交付和消费。消费者等待期间需要可靠的前递来源，提交必须恰一次；缓存策略、写回与设备旁路各自有契约，不能把“不忙”当作“这笔请求完成”。
第 25 集
分支预测：把两拍惩罚藏起来
BTB + BHT 按 PC 预测（IF 不译码）、误预测就是 src_br；附带五级观察路径的教学/诊断窗口，不作为终版性能成绩。
第 26 集
MMU 与 Sv39：虚拟地址第一次成立
TLB 快表、PTW 硬件走表、缺页号（12 / 13 / 15）；satp 的三个出口（mmu_en / root_ppn / asid）在这一集接上消费者。
第 27 集
PMP：S / U 能访问哪段物理内存
配置侧由 CSR 更新 cfg/addr，访问侧按物理地址、访问类型和有效特权判决。两侧共用同一份条目状态；取指、数据与页表遍历分别验证区域边界、权限和异常原因，不能只验寄存器回读就声称保护闭环。
DAY 6 安息前的最后一班岗 · 交棒内核，进入 shell 成稿 · 第 28–31 集
"神看着一切所造的都甚好。"—— 《创世记》 1:31

从 OpenSBI 交棒到 PID 1 打出提示符：补上浮点（F / D）与非对齐访存两件大硬件、把 initramfs 挂成根，最后收在 BusyBox 与那个 # 上。

第 28 集
FPU（F / D）：一半是算术，一半是特权
F/D 采用单一宽算术通路服务两种精度，非迭代算术分三段，除法与开方使用迭代单元。FS 是 Off/Initial/Clean/Dirty 四态，SD 派生、fflags 累积、NaN-boxing 与浮点上下文各自验证。终版 misa、设备树和真实能力一致；本集只是展开前文能力声明中的 F/D。
第 29 集
非对齐访存：一笔装不下，就拆两笔
同字内走车道、跨字不跨页拆两笔（MisPhase 两拍事务）、跨页与原子交 cause 4 / 6；判据：探针 20 根寄存器逐条对一份独立字节模型 + 四发反证（门控 / 跨字 / 页尾 / 拼接方向）各红自己那一族；内核 check_unaligned_access 的黑名单与 panic 栈照录在 fw/sbi.dts 注释——机器与内核的边界要如实标注。
第 30 集
挂根：initramfs 与它的三条软规矩
initramfs 进槽位表（0x800000 / 916,480 字节）、initrd-end 不能凑整；三条软规矩：rdinit= 不是 init=、镜像根自带 /dev/console 与 /dev/null、/linuxrc 是指向 busybox 的软链；地址事实的四份文本由 test_fw_layout_slots 逐条核对。
第 31 集
进入 shell：从“能打印”到“能对话”
终版启动链依次完成串口 platform device 注册、ttyS0 接管、PLIC 的 S-context 通知与 UART 收发中断。启动日志、提示符、字节回显与 shell 命令响应是不同验收层级，不能用“出现 #”替代命令往返。
DAY 7 安息 · 从五级顺序单发射到现代高性能核 7 集
"天地万物都造齐了。到第七日，神造物的工已经完毕，就在第七日歇了他一切的工，安息了。"—— 《创世记》 2:1–3

前六日建立同一白虹的 ISA、特权、存储与整机契约；第七日解释终版候选口径如何用重命名、ROB、完成窗口、按序提交、非阻塞访存与分层预测执行这些契约。主干 12 级、取指/译码 3 宽、重命名 4 宽、提交 3 宽。章节顺序是观察顺序，不是换一颗核或逐步补齐能力；性能以同负载、同口径验收。

第 32 集
差在五处：五级顺序单发射 vs 现代高性能核
用顺序教学核对照终版的乱序、多发射、深流水、存储层次与预测结构。IPC、零退休拍比例、miss 内独立年轻指令的完成数分开定义；完成不等于退休，局部窗口不代表完整工作负载性能。
第 33 集
乱序：把“位置即年龄”换成“tag 即年龄”
重命名分离架构名字与物理值，ROB 按程序序提交，发射队列按生产者就绪唤醒，访存队列管理顺序与副作用。物理寄存器不能因生产者刚退休就立即回收；最新提交映射必须保留，恢复与身份回绕各有明确约束。
第 34 集
多发射：从一拍一条到一拍三条
取指、译码、重命名、发射、完成与提交分别定义宽度；缓冲只吸收短期速率差，不能提高窄级的长期吞吐。接口适配应保持架构事件流，真正增加并行能力则重新测量周期与 IPC，不要求 IPC 恒定。浮点融合类指令还需要第三源操作数。
第 35 集
深流水：主干 12 级与同步读
解释同步读、段间载荷和前端缓冲如何协作，并分别核对 load-use、前递、重定向和维护时相。组合结构检查、路径延迟与真实 Fmax 是不同证据；不能把 schedule 中的时钟标注或门级数直接当作可实现主频。
第 36 集
非阻塞访存：等待数据时，独立指令继续执行
DCache、L2、行事务表与 AXI adapter 分别承担命中、后备、身份和传输职责；八地址项与两数据项不是同一个资源。SQ/WMB 保存已提交写，load 前递按年龄和字节掩码选择。主判据是 miss 内独立年轻指令完成、依赖消费者等待、老 load 完成前年轻指令不退休。
第 37 集
预测升级：四件套与返回地址栈
方向、目标、间接跳转和返回地址分别预测，RVC 的半字粒度与 tag 保证身份区分。提交更新的 RAS 不需要推测回滚，但可能滞后于前端；恢复简单不等于预测最准确。正确性看架构事件流，收益看误预测与同负载总周期。
第 38 集
CoreMark 跑分：性能如何验收
CoreMark 与 Dhrystone 用相同输入、镜像和计时口径比较有效工作成本。IPC、零退休周期、执行重叠和总周期分别记账；原始事件可重叠，归因分类必须互斥。跨负载表、未绑定原始记录的成绩和未经同口径核对的商业核对比不充当终版测量结论。

学习曲线

光（一门新语言 + 一颗 CPU + 一段跑起来的固件）
→ 空气与水（这一子集所需的原料：pc 下一步 / 记忆 / ALU 活动 / decoder 理解世界；组装成顶层后跑一段真程序——一台能执行程序的处理器）
→ 天上光体（立 flag：白虹——五级流水、冒险、异常与特权）
→ 有生命的活物（中断接进核、指令集扩展 M·A·C、soc.prism 连成一片芯片与一张地址图；串口、S 态交棒，OpenSBI 打出 banner）
→ 照着形象造人（cache、分支预测、MMU、PMP）
→ 安息前的最后一班岗（浮点与非对齐补齐、挂根 initramfs；PID 1 在 U 态打出 # ）
→ 第七日（安息：从五级顺序单发射到现代高性能核——乱序（重命名 4 宽 / 提交 3 宽）、12 级主干，同口径基准评测）

一次给光，七日造物——第一日四集是四张切片，让读者看完知道"这门语言能造芯片"；剩下的六日是把这片光逐层拆开、逐日重建。
