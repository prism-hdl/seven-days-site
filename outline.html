    25 集大纲
    七日创造

    一个软件工程师，七天，从"发明一门语言"开始，造出能跑操作系统的 RISC-V 处理器。第一日四集讲完工具箱全景——不抠细节，只让读者看见这门语言能造芯片；从第二日起，造物。

    ← 返回落地页 从第 1 集开始
    DAY 1 光 4 集 · 已写完
    "神说，要有光，就有了光。神看光是好的，就把光暗分开了。"—— 《创世记》 1:3–4

    黑暗不是没有工具——硬件开发有两条割裂的路：RTL（周期精确、可综合，但算法与微架构缠在一起），SystemC / TLM（事务级、快，但不可综合）。两条路描述同一个硬件、要各写一遍，行为等价靠人盯。HLS 只补了"算法 → RTL"这一半，输入还得是可综合子集，产不出用于架构探索的 TLM 快模型。

    Prism 的答案：一份源码，同时下降为 RTL + TLM + 独立 Python golden，三方 cosim 闭环逐拍对撞。名字（棱镜）就是这张图——一束算法折射出两道光谱，第三个棱面独立验收。

    第一日不逐条讲语法——四集把整门语言铺开一次，让读者先看全景，知道"这门东西真能做一颗 CPU"。

    EP 1
    一道裂缝：为什么要有 Prism
    RTL 与 TLM 两条路各写一遍的痛（结构层），加上"语言本身不像在想电路"（表达层）。Prism 的答案：一束光、三道棱面。最小示例是一颗加法器——它会在第 7 集改造成 ALU；20 分钟三下降全绿。
    EP 2
    分层与语法骨架
    module 只写"做什么"，@schedule 才补"怎么做"。这一集从一只盒子讲起（端口 / 线 / 状态），把语法面一次讲全：端口 in/out/both、类型、四种分支、on clock、fsm——一颗进程调度单元（进程五态 + 时间片）把骨架装起来。
    EP 3
    聚在一处：组装与抽象
    design 的装配规矩展开（connect / wire / expose + 顶层端口推导）；再把零件多起来之后的 interface（契约）/ composer（封装，展平透明）/ import（分文件）逐一展开。全篇按"遇到什么麻烦、于是有什么手段"的因果写法展开——第一日不出现整机。
    EP 4
    让光打出去：工具箱全开
    不写新代码：先重贴 mini_cpu.prism 全文；静态四件（check / typecheck / keywords / dump-ast）全量输出逐段解读；gen-rtl / gen-tlm 展示完整产物（154 行 SV + 230 行 SystemC）；run 三档各跑一遍、cosim 摆到同一张桌上对撞。工具这半边到此为止。
    DAY 2 空气与水 6 集 · 已写完
    "神说，诸水之间要有空气，将水分为上下。"—— 《创世记》 1:6

    一台 CPU 里流着两条水——数据（值）与控制（决定值什么时候被允许流过）。每一颗器官都在自己内部把这两条水分开一次：pc 分"当前值"与"下一步"，regfile 分"读写数据"与"写使能 / 地址"，ALU 分"操作数"与"选路"，decoder 干脆整颗就是一束控制位。这一天把最小 RV64I 处理器（64 位数据通路）的所有原料讲完——每颗各自能测；最后原料合体，跑一段冒泡排序：先有零件，再谈身体——然后让它做事。

    EP 5
    PC — 下一步
    reg + on clock，全部决策就在 load ? target : pc + 4 这一个三目里。顺行走 +4、跳走用 target——用 bne x2, x0, loop 那段真循环讲清：-8 来自 B 型立即数，不是 pc 自己有的数。宽度钉死 64，不留泛型。
    EP 6
    记忆：regfile / ram / im / dm
    寄存器堆 32 项 2 读 1 写、x0 由它自己保证恒零（读侧给 0 + 写侧丢弃）；字阵列异步读 + 同步写——单周期核必须这个形状。哈佛 = 同一份源码例化两次。
    EP 7
    ALU — 活动
    第一集那颗加法器在这里成年——十条路一张 match 表，写起来是表，长出来是十个并列运算加一个多路选择器。三条边界：不掩移位量、不产生标志位、不做多周期的事。
    EP 8
    decoder — 理解世界
    整颗纯组合表达式：字段切片、五种立即数格式、控制位分派。理解 = 把外界字符串翻译成内部动作，理解不了就说"我不懂"。
    EP 9
    cpu_top：一具身体
    四颗器官一行不改地从 examples/day2/ import 进来（唯一缺口是顶层要替分支补一列 alu_op_b）；im / dm 是同一颗 ram 的两个实例（W = u32 / W = i64）；程序写在 run 的 image 段；27 跑出 x1 = 15，另有三列各自见证分支没跳、W 后处理、LD/SD 往返。golden / RTL / SystemC 三条腿逐拍全等。
    EP 10
    跑一段冒泡排序
    芯片一行不改，cpu.prism 只多一个 run 块：image 把 32 条指令灌进 im、把 9,7,5,3,2,1 灌进 dm。417 拍排成 1,2,3,5,7,9；停机判据不是拍数，是程序自检通过后自己置起的完工位 x20——把比较方向改反，判据就永不成立。CPU 第一次做一件真事。
    DAY 3 （待重构） 待重构

    原第三日的内容（四颗合体、跑真程序）已并入第二日；本日待重新规划。

    DAY 4 天上光体，定节律 5 集 · 待写
    "天上要有光体，可以分昼夜、作记号、定节令、日子、年岁。"—— 《创世记》 1:14

    第二日那台 CPU 一颗组合逻辑走完全场，CPI = 1 但频率被最长组合路径卡死。提速只有流水——一旦流水，每一颗子模块要复制五份。手写五遍会崩；这就是 Composer 出场的时刻。

    EP 11
    Composer：一次声明、五段生成
    lower_composers 把可复用结构展开到流水每一级；段间寄存器位宽跟字段自动对齐。抽象在此刻才有意义——不是提前，是刚好。
    EP 12
    五级流水线数据通路
    IF / ID / EX / MEM / WB；段间寄存器；pipe5 落地方案；@schedule { pipeline : 5 stages }。
    EP 13
    数据冒险与前递 / 停顿
    RAW 路径、前递谓词、Load-Use 停顿检测；停顿靠 pc 与段间寄存器同步冻结——第 5 集那个被拿掉的 en 端口，在这里长回来。
    EP 14
    控制冒险与分支处理
    分支判断位置、跳转目标、flush、简单预测；误预测的代价与恢复。
    EP 15
    RV64I 扩展 + 整合验证
    32 → 64 位数据通路；LWU / LD / SD；寄存器堆泛型化；跑测试程序、对比 CPI。
    DAY 5 有生命的活物 5 集 · 待写
    "地要生出活物来，各从其类。"—— 《创世记》 1:24

    流水线跑起来的 CPU 只是更快的机器。让它"活"起来的是三件事：会疼（异常）、会躲（中断与 PMP）、会做事（跑真程序，并被一位不共享前端的"外人"逐拍盯着）。

    EP 16
    RV32M 乘除法
    mul / div 系列挂到执行单元一侧；fsm 管多周期握手（第 7 集留给日后的话题，在这里兑现）；独立 oracle 逐拍对撞。
    EP 17
    CSR 框架与异常处理
    M / S / U 模式；mstatus / mie / mtvec / mepc 等；WARL 掩码；非法指令、EBREAK、ECALL、访存未对齐；mcause / mtval / mret。CPU 会疼了。
    EP 18
    中断与 PMP
    软件 / 定时器 / 外部中断、使能与优先级；PMP 寄存器、地址匹配、权限检查。CPU 会躲了。
    EP 19
    模式切换与系统调用
    ecall / sret / wfi；U 态执行；M / S 切换；完整 RV64 跑带 syscall 的裸机程序、FPGA 上板。
    EP 20
    独立 ISS 作第四方 · 跑一段真程序
    独立实现与 Prism 前端零共享代码，封住"三方从同一棵 AST 下降、前端共性 bug 互查不出"的死角。CPU 会做事，且有人从旁边盯着它做。
    DAY 6 照着形象造人 4 集 · 待写
    "我们要照着我们的形象造人，使他们管理海里的鱼、空中的鸟、地上的牲畜。"—— 《创世记》 1:26

    到第五日为止，CPU 只会算数与响应中断——它还是个"孤独的生命"。第六日给它一个世界：总线、SRAM、BootROM、PLIC、UART。CPU 第一次"挂上外设、开始管理它们"。

    EP 21
    治理规则：总线 / 地址映射 / ABI / 链接脚本
    一套地址空间规划与解码；RISC-V ABI、gp / tp 初始化、.ld 布局——先约好规矩，再谈管理。
    EP 22
    挂上存储器：片上 SRAM 与 BootROM
    SRAM 控制器、数组初始化；BootROM 上电即跳——CPU 有了长期记忆。
    EP 23
    挂上外设：PLIC 与 UART
    平台级中断仲裁、多源；16550 风格 UART 收发状态机。
    EP 24
    SoC 顶层组装 · 从"能算"到"能管"
    把 CPU + SRAM + BootROM + PLIC + UART 一次连齐；cosim 全链逐拍跑通；跑一段 hello world，串口输出。
    DAY 7 安息 1 集 · 待写
    "天地万物都造齐了。到第七日，神造物的工已经完毕，就在第七日歇了他一切的工，安息了。"—— 《创世记》 2:1–3

    前六日都是"作者在改代码"。第七日是作者退场：一段不属于我们的固件（OpenSBI）在 Prism 造的 CPU 上自己起来——M 态跳 S 态、串口打出 banner；从此 CPU 跑的不是我们写的激励，是别人写的操作系统。

    EP 25
    OpenSBI 移植与最小 SoC 跑通
    编译 OpenSBI、固件加载到 SRAM / BootROM、cosim 校验上电 reset vector 与 mtvec 跳转；FPGA 上电、串口 banner 打出来。作者停手，机器自转。

    学习曲线

    光（一门新语言 + 一颗 CPU + 一段跑起来的固件）
    → 空气与水（所有原料：pc 下一步 / 记忆 / ALU 活动 / decoder 理解世界；合体后跑冒泡排序——一台会做事的处理器）
    → 天上光体（Composer 一次声明五段生成；流水线、冒险、RV64I）
    → 有生命的活物（会疼：异常；会躲：中断 + PMP；会做事：独立 ISS 四方对撞）
    → 照着形象造人（SoC：总线 / SRAM / BootROM / PLIC / UART）
    → 安息（OpenSBI 起来，作者退场，机器自转）

    一次给光，七日造物——第一日四集是四张切片，让读者看完知道"这门语言能造芯片"；剩下的六日是把这片光逐层拆开、重新长出来。
