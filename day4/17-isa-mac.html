        指令面长大
        M · A · C

        第 11 集判过：内核里第一件跑不起来的东西不是除法，是锁。这一集补三门扩展——M 管乘、A 管原子（锁的地基）、C 管压缩。三样各一颗真样例，判据一律是"与工具链给出的标准编码逐条对上"。

        "地要生出活物来，各从其类。" —— 《创世记》 1:24
        ← 第 16 集 · 中断：CLINT 与 PLIC 第 18 集 · soc.prism：一片真芯片（待写）→

        三门扩展，各缺一件东西

        M · 乘除

        乘法单拍就能出来；除法要占多拍——所以 M 在硬件上是两颗模块，只有一颗长在流水里。

        A · 原子

        spin_lock 就是一条 amoswap。没有它，临界区只能靠关中断凑，多任务与 SMP 直接封死。

        C · 压缩

        16 位编码的别名：硬件只做展开，不改数据通路——但取指窗口要能切半字。

        F · 浮点呢？

        它要自己的寄存器堆、自己的格式与舍入、还要处理内核里无条件出现的 fsd / fld——定在第六日 FPU 那一集。

        三份样例都在 examples/day4/：mul.prism / amo.prism / rvc.prism。每一份都先有一张手算表，再撞 RTL。

        M：一条乘法器，四种解释

        RV64M 的乘法有四个变体，差别只在两件事：两个操作数各自怎么解释、取积的哪一半。硬件上就是一条 64×64 乘法器加一个 mux——四种解释是用"喂之前补什么"实现的：

        prismexamples/day4/mul.prism · 一个形状，四种补法
            // 同一个形状：操作数先补满 128 位，符号性只体现在"补什么"
    wire a_s : i128 = {64{a[63]}, a}     // 有符号：补符号位
    wire b_s : i128 = {64{b[63]}, b}
    wire a_u : i128 = {64{0}, a}         // 无符号：补 0
    wire b_u : i128 = {64{0}, b}

    wire p_ss : i128 = a_s * b_s
    wire p_su : i128 = a_s * b_u
    wire p_uu : i128 = a_u * b_u

    wire lo_ss : i64 = p_ss[63:0]
    wire hi_ss : i64 = p_ss[127:64]
    wire hi_su : i64 = p_su[127:64]
    wire hi_uu : i64 = p_uu[127:64]

    // W 形态：低 32 位当有符号整数，再扩展回 64 位（符号扩展由类型声明负责）
    wire wraw : i32 = p_ss[31:0]
    wire wext : i64 = wraw

    wire wide : i64 = match op {
        0 => lo_ss,
        1 => hi_ss,
        2 => hi_su,
        _ => hi_uu,
    }
    r = is_word ? wext : wide

        高半那几行最能说明问题（表里的数都被工具链核过）：

        $ prism run examples/day4/mul.prism --debug （摘关键几行）
        a b op r -3 4 0 -12 ← mul：低半 -3 4 1 -1 ← mulh：-12 的高半是 -1 -3 4 2 -1 ← mulhsu：-3 有符号、4 无符号 -3 4 3 3 ← mulhu：-3 当无符号是 2^64-3 0x7FFFFFFFFFFFFFFF 2 1 0 ← mulh：2^64-2 的高半是 0 -2147483648 1 1 -1 ← mulh：0xFFFFFFFF80000000 的高半 0x100000000 2 0(以 W 算) 0 ← mulw：低 32 位截断后是 0

        同一个 a × b，四个答案——不是四条电路，是四个"怎么读它"。W 形态（mulw）再补一刀：只算低 32 位，然后按有符号扩展回 64 位——这条规矩第 7 集就立过（W 操作在顶层收口），这里照旧由类型声明负责。

        除法为什么不在这一颗里

        除法要一拍一拍地试商。它进来以后，EX 段会被占住几十拍——那套"占用与握手"的协议第 13 集已经打过样（Divider 的 start / busy / done）。所以 M 在流水里是两颗：乘法长在 EX 的组合通路上，除法是一颗被占用的多拍单元。

        A：锁的地基是"预约"

        原子扩展只有两条路：

        LR / SC（预约对）——LR 读出旧值并记下这个地址；SC 只在"预约还挂着、地址还是那个"时才写。中间只要这块地址被写过，预约就作废、SC 返回失败，软件重试。AMO（读改写一条）——一条指令里读完就写，中间不给任何人插队，而且旧值还要交给寄存器堆。

        prismexamples/day4/amo.prism · 预约与读改写
            reg r_rsv_addr  : u64 = 0
    reg r_rsv_valid : u1  = 0
    reg r_consume   : u1  = 0     // 上一拍发生过 SC：这一拍把预约用掉
                                  // （判决与清除不在同一拍做：清除延后一拍，
                                  //  SC 才能既看见预约、又把它用掉）

    wire is_lr : u1 = op == 0
    wire is_sc : u1 = op == 1

    // 一条指令里的"读改写"：先算新值
    wire amo_new : i64 = match op {
        2 => rs2,               // amoswap：写的是源操作数
        3 => rdata + rs2,       // amoadd
        4 => rdata & rs2,       // amoand
        5 => rdata | rs2,       // amoor
        _ => rdata,             // lr / sc 不走这里
    }

    // SC 成功与否：预约还挂着，而且地址没变过
    wire sc_ok : u1 = is_sc & r_rsv_valid & (r_rsv_addr == addr)

    on clock {
        // LR：记下这个地址，预约挂起
        if (is_lr) {
            r_rsv_addr'  = addr
            r_rsv_valid' = 1
        }
        // SC：无论成败，预约都会用掉——但清除延后一拍（见 r_consume）
        if (r_consume & !is_lr) {
            r_rsv_valid' = 0
        }
        r_consume' = is_sc
    }

    wdata = is_sc ? rs2 : amo_new
    do_wen = is_sc ? sc_ok : (op != 0)          // LR 不写；SC 看预约；AMO 一定写
    // AMO / LR 交回**写前**旧值——这是它和 store 的本质区别
    rd = sc_ok ? 0 : rdata

        写这一片时撞到一个真实的时序问题，值得单独说：判决与清除不能在同一拍做。SC 要"看见预约"才能判成功，可它同时又要"用掉预约"——如果清除在同一拍落地，判决读到的就是清完的值，SC 永远失败。真实硬件里这两件事本来就差一拍（判决在 EX，清在写回），所以样例里把清除延后一拍（r_consume），这也是它和 store 的另一个区别：store 不需要记住任何东西，SC 要记住"上一次是谁在读"。

        $ prism run examples/day4/amo.prism --debug
        op addr rs2 rdata wdata rd do_wen rsv LR 0x400 0 7 7 7 0 1 ← 读出旧值，预约挂上 SC 0x400 9 7 9 0 1 1 ← 预约在、地址对 → 成功 SC 0x400 9 9 9 9 0 0 ← 预约已用掉 → 失败 LR 0x400 0 9 9 9 0 1 ← 重新预约 SC 0x408 5 9 5 9 0 1 ← 地址不符 → 失败 SWAP 0x400 0x2A 9 0x2A 9 1 0 ← AMO：rd 给**写前**旧值 9 ADD 0x400 1 9 10 9 1 0 ← amoadd：写 10，rd 照样是 9

        最后两行是 AMO 与普通 store 的本质区别：store 只写，AMO 写的同时把旧值交回来。锁就是靠这个旧值判断"我拿到锁了没有"。

        C：压缩码是别名，不是魔法

        16 位编码里没有新语义——每条 c.xxx 都对应一条标准 32 位指令。硬件要做的只有一件事：展开，再交给原来的译码器。所以 RVC 不动数据通路，只在取指窗口与译码之间插一层查表。

        prismexamples/day4/rvc.prism · 象限分派与展开
            //   c.nop            →  addi x0, x0, 0
    wire is_c_nop  : u1 = (quad == 1) & (f3 == 0) & (rd == 0) & (imm6 == 0)
    wire is_c_addi : u1 = (quad == 1) & (f3 == 0) & (rd != 0)
    wire is_c_li   : u1 = (quad == 1) & (f3 == 2)
    wire q2_f4 : u1 = (quad == 2) & (f3 == 4) & (rd != 0) & (rs2 != 0)
    wire is_c_mv   : u1 = q2_f4 & (raw[12] == 0)
    wire is_c_add  : u1 = q2_f4 & (raw[12] == 1)
    wire is_c_j    : u1 = (quad == 1) & (f3 == 5)

    wire known : u1 = is_c_nop | is_c_addi | is_c_li | is_c_mv | is_c_add | is_c_j

    // opcode 字段：addi=0x13、add=0x33、jal=0x6f
    wire o_addi : u7 = 0x13
    wire o_add  : u7 = 0x33
    wire o_jal  : u7 = 0x6f

    // 逐条拼：
    //   addi  rd, rs1, imm  →  imm[11:0] | rs1 | funct3=0 | rd | opcode
    wire e_nop  : u32 = {{12{0}}, {5{0}}, {3{0}}, {5{0}}, o_addi}
    wire e_addi : u32 = {imm6_12, rd, {3{0}}, rd, o_addi}
    wire e_li   : u32 = {imm6_12, {5{0}}, {3{0}}, rd, o_addi}
    wire e_mv   : u32 = {{7{0}}, rs2, {5{0}}, {3{0}}, rd, o_add}
    wire e_add  : u32 = {{7{0}}, rs2, rd, {3{0}}, rd, o_add}
    wire e_j    : u32 = {imm11_20, {5{0}}, o_jal}

    // 六条谓词两两互斥（象限/funct3 各不相同），串成一条选择链即可
    wire pick_a : u32 = is_c_mv ? e_mv : e_j
    wire pick_b : u32 = is_c_add ? e_add : pick_a
    wire pick_c : u32 = is_c_li ? e_li : pick_b
    wire pick_d : u32 = is_c_addi ? e_addi : pick_c
    wire expanded : u32 = is_c_nop ? e_nop : pick_d
    // 不认识的：展开成 **0**（非法编码），不是 nop——"认不出"必须能喊出来
    instr = known ? expanded : 0
    illegal = known ? 0 : 1

        两条硬规矩在代码里都能看见：先按低两位分象限（quad），再按 funct3 细分；认不出来必须喊——展开成 0 并置 illegal，让第 15 集那条陷阱通路去处置，而不是当 nop 混过去。

        表里的数两边都不是手写的：压缩编码和它的展开形式都由 riscv64-elf-gcc 汇编出来再逐条对读——汇编器本身就是一次独立参照。

        $ riscv64-elf-gcc -march=rv64imc … && objdump -d （压缩 × 展开，成对读出）
        c.nop 0x0001 → nop 0x00000013 c.addi x5,1 0x0285 → addi x5,x5,1 0x00128293 c.li x5,10 0x42A9 → addi x5,x0,10 0x00A00293 c.mv x5,x6 0x829A → add x5,x0,x6 0x006002B3 c.add x5,x6 0x929A → add x5,x5,x6 0x006282B3

        写这一片时在最容易想当然的地方错了一次：CI 型的 6 位立即数不是连续一段——最高位在 bit12，低 5 位在 bits[6:2]。手写编码时按"连着读 6 位"去取，展开出来就全错。c.lui / 分支 / 跳转那几族各有各的拆法，这也是白虹那份展开器要用穷举对撞的原因：65536 个 16 位编码，一条条对，别靠眼看。

        压缩码还要求取指窗口能对齐

        指令变成 2 字节，就可能跨在两个 32 位字之间。第 13 集的取指窗口取两个字、按 pc[1] 选半字拼装——那一段就是为这一集准备的。没接 RVC 之前，pc 每步 +4；接上之后 +2 还是 +4 由这条指令自己决定。

        F 去了第六日

        浮点没有放进这一集，不是漏了——它已经定在第六日 FPU 那一集。它要占的地方比这一集任何一门扩展都大，至少带三件别人没有的东西：

        • 自己的一套寄存器：32 个浮点寄存器（fregfile），和整数寄存器堆并列。
        • 格式与舍入：单双精度共用一条宽通路，靠格式选择与 3 个舍入位分派；FS / SD 还要过 mstatus.FS 的门。
        • 一条硬事实：RV64 内核里 fsd / fld 是无条件出现的——广告了 FP 就得真会算，否则内核自己的访存先炸。

        第六日那一集要把 F / D 与 A · C 一起对账收尾，判据还是同一句：三条通路与独立参照逐拍全等。这一集先把 M · A · C 摆平——它们三个各自都能在 examples/day4/ 里跑起来、撞上 RTL。

        小结

        • M：四个变体 = 一条 64×64 乘法器 + "操作数补什么、取积哪半"；W 形态只算低 32 位再符号扩展；除法是另一颗多拍单元。
        • A：LR/SC 靠"预约"——记住地址、SC 才敢写；AMO 一条指令读改写，且把写前旧值交回来（锁靠它判断拿到没有）。
        • A 的时序：判决与清除差一拍——SC 要看见预约才能成功，不能在同拍把它清掉。
        • C：是别名不是新语义；象限分派 + 认不出就喊；立即数在编码里是拆碎的，别按连续位段读。
        • 三张表都撞了 RTL，逐拍全等；表里的数由工具链给出，不是手抄。
