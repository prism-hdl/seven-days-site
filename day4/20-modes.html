模式切换与系统调用
谁能跳到哪一态

第 15 集立下过一条边界：本核没有 U 态，sret 恒回 S。这一集把这条边界画全——M / S / U 三态到位：ecall 按当前态编 cause、mret 按 MPP 回、sret 按 SPP 回；哪条指令只属于哪一态，逐条画清楚。"用户态"这个概念，第一次在这台机器上成立。

ecall 不是跳转，是一次陷阱

先说一个容易想岔的地方：系统调用不是"跳到内核的某条指令"。用户态手里只有一条 ecall——它做的事是按当前态发起一次陷阱：硬件把现场存进 *epc / mcause / mtval，跳到 *tvec。去哪张 tvec、编什么 cause，全看"现在是哪一态"：

当前态ecall 的 cause谁会接
U 态8M 或 S（按委派掩码）
S 态9M 或 S——SBI 调用走的就是这一条
M 态11只有 M
ebreak（任何态）3调试断点，与 ecall 同一张表

同一张表里还有一类容易忘的条目：系统指令的特权门控——mret 只在 M 态合法，sret / sfence.vma 至少 S 态，不够格就是非法指令（cause 2），不是静默 no-op。门控漏在谁身上，谁就替低特权侧改了高特权状态：S 态一条 mret 能把 priv 拉回 M 并跳到 mepc。

prismwhitebow/pipe/trap.prism · 编码与特权门控
    // 异常优先级：illegal（含 CSR 特权门控并入）> ebreak > ecall（按当前 priv 编
    // 8/9/11）> 缺页/访问错 > load 未对齐 > store/AMO 未对齐。
    // 异常编码：2=illegal instr, 3=ebreak, 4=load addr misalign, 6=store addr misalign,
    //          7=store/AMO access fault（设备窗口上的 AMO）,
    //          8=user ecall, 9=supervisor ecall, 11=machine ecall
    // 中断 cause = (1 << 63) | interrupt_number（RISC-V 规范）
    wire mem_trap_cause : u64
    wire mem_priv_s_ecall : u1 = mem_is_ecall & (csr.priv == 1)
    wire mem_priv_m_ecall : u1 = mem_is_ecall & (csr.priv == 3)
    wire mem_priv_u_ecall : u1 = mem_is_ecall & (csr.priv == 0)

    // 特权门控（规范 §3.3.1 逐条要求）：MRET 只在 M 态合法；SRET / SFENCE.VMA 至少
    // S 态。不够格就是非法指令（cause 2），不是静默 no-op——门控漏在谁身上，谁就替
    // 低特权侧改了高特权状态：S 态一条 mret 能把 priv 拉回 M 并跳到 mepc。
    // 三条的放行条件写在一起，判决与下面三根 strobe 同源。
    wire mret_priv_ok   : u1 = csr.priv == 3
    wire sret_priv_ok   : u1 = csr.priv >= 1
    wire sfence_priv_ok : u1 = csr.priv >= 1
    wire mem_priv_bad   : u1 = (mem_is_mret & !mret_priv_ok) | (mem_is_sret & !sret_priv_ok) | (mem_is_sfence & !sfence_priv_ok)

一条 match，把"谁先报"钉死

同一个 MEM 提交拍上，可能同时成立好几条"出事了"。硬件只报一条——按一张固定的优先级表往下挑：中断 > 取指缺页(12) > 非法(2) > ebreak(3) > ecall(11/9/8) > 缺页/访问错 > load 未对齐(4) > store/AMO 未对齐(6)。写成一条从上往下匹配的 match，顺序本身就是要写明的规格：

prismwhitebow/pipe/trap.prism · cause 的裁决顺序
    mem_trap_cause = match {
        // 中断优先于异常：cause = (1 << 63) | interrupt_number
        (mem_valid & mem_interrupt_pending)                   => (1 << 63) | mem_interrupt_cause,
        (mem_valid & mem_if_pf)                               => 12,
        (mem_valid & (mem_is_illegal | csr.csr_illegal_priv | mem_priv_bad | (mem_is_fp & csr.fp_off))) => 2,
        (mem_valid & mem_is_ebreak)                           => 3,
        (mem_valid & mem_priv_m_ecall)                        => 11,
        (mem_valid & mem_priv_s_ecall)                        => 9,
        (mem_valid & mem_priv_u_ecall)                        => 8,
        (mem_valid & lsu_pf)                                  => lsu_pf_cause,
        // 设备窗口上的 AMO：access fault（store/AMO 类）。与缺页互斥（LSU 侧 af 带
        // !pf_hit 门控）：有 MMU 时先翻译，页面没映射先报缺页。
        (mem_valid & lsu_af)                                  => 7,
        (lsu_mis_load | (lsu_mis_atomic & mem_is_lr)) => 4,
        (lsu_mis_st | lsu_mis_atomic)                    => 6,
        _                            => 0,
    }

两个容易写反的位置值得点出来：取指缺页压过 illegal——这条指令根本没取到字，ID 拿的是废值，让它先报就成了 cause 2 + 指令字当 mtval，两样都错；未对齐排在最后——有 MMU 时先翻译、物理访问在后，一个既未对齐又缺页的访问按缺页报（规范允许二者择一）。

进与退的严格版：MPP / SPP 是唯一的路

第 15 集讲过的"存现场、改态"在 U 态落地之后要说得更精确：进陷阱时把"被中断的态"压进 MPP（进 M）或 SPP（进 S），把中断使能压进对应的 PIE 位并关掉当前使能；退陷阱从同一位弹回来。特权级只会沿着这两条路变化：

prismwhitebow/ext/csr.prism · 进 / mret / sret 的状态变换
    // ---- 异常进入 / mret / sret 的 mstatus 状态变换 ----
    // 位段：SIE(1)、MIE(3)、SPIE(5)、MPIE(7)、SPP(8)、MPP(12:11)
    //   mstatus mask：M 侧 0x1888，S 侧 0x122
    // trap → M：MPIE←MIE、MIE←0、MPP←priv；其余位保留（SIE/SPIE/SPP 不动）
    trap_mstatus_m = (r_mstatus & ~0x1888) | ((r_mstatus & 0x8) << 4) | (r_priv << 11)
    // trap → S：SPIE←SIE、SIE←0、SPP←被中断态；M 侧位段保留
    //   SPP 编码（规范「SPP is set to 0 if the trap originated from user mode, or 1
    //   otherwise」）：**非 U ⇒ 1**，不是"SPP=1 表 U"。所以判据是 `r_priv == 0`，别写成
    //   `r_priv == 1`——那条在被中断态是 M 时给 0，csr_check 的 trap→S 那两拍会抓它。
    //   写反这一位会让内核 entry.S 的 `bnez tp,_save_context`/`andi s0,s0,SR_SPP` 把每一次
    //   内核态陷阱都当成从用户态来：返回时 `csrw CSR_SCRATCH,tp` 把 sscratch 留成非 0，
    //   下一次陷阱就跳过 `REG_S sp, TASK_TI_KERNEL_SP(tp)`，pt_regs 落在陈旧的 kernel_sp 下方，
    //   盖掉还在用的栈帧（Linux 起跑时表现为 callee-saved 集体变旧值）。
    trap_mstatus_s = (r_mstatus & ~0x122) | ((r_mstatus & 0x2) << 4) | (r_priv == 0 ? 0 : 0x100)
    // mret：MIE←MPIE、MPIE←1、MPP←least-supported=U(0)（本核最低档现在是 U，所以掩掉即落 0）
    mret_mstatus = (r_mstatus & ~0x1888) | ((r_mstatus & 0x80) >> 4) | 0x80
    // sret：SIE←SPIE、SPIE←1、SPP←0 —— 规范同一条文的后半句就是"SPP is then set to 0"。
    // 返回态就是这一位：SPP=1⇒S、SPP=0⇒U。
    sret_mstatus = (r_mstatus & ~0x122) | ((r_mstatus & 0x20) >> 4) | 0x20

三处规范细节，全在这几行里：

  • trap→S 的 SPP 是"非 U ⇒ 1"，不是"SPP=1 表示从 U 来"。写反这一位的后果在 Linux 起跑时实测过一次：内核的返回路径把每一次内核态陷阱都当成从用户态来，pt_regs 落到陈旧的 kernel_sp 下方、盖掉还在用的栈帧——表现是 callee-saved 寄存器集体变旧值。
  • mret 把 MPP 复位成"最低支持档"（规范原文：least-privileged supported mode）。本核最低档现在是 U，所以返回之后 MPP 落 0——同一条规则在第 15 集（还没 U）时落的是 S。
  • sret 返回目标就是 SPP：SPP=1 ⇒ 回 S，SPP=0 ⇒ 回 U。

还有一个必须挡死的编码：MPP 的合法集是 {U(0), S(1), M(3)}，保留编码 2 要向上取到 3。为什么非挡不可？不挡的话软件能把 MPP 写成 2，mret 之后 priv=2——三条 ecall 判据（==0/==1/==3）一条都不成立，陷阱就此静默消失，指令照常退休。

prismwhitebow/ext/csr.prism · MPP 的 WARL
    //   3) MPP 的合法集是 {U(0), S(1), M(3)}：只有写保留编码 2 才向上取（bit12 落下位 bit11，
    //      2→3），0 与 1 原样落地。保留编码必须挡：软件能把 MPP 写成 2 的话，mret 之后
    //      priv=2 —— 三条 ecall 判据（==0/==1/==3）一条都不成立，陷入静默消失、指令照常退休。
    //      SPP 与 MPP 一样是软件可写的：硬件在 trap 入口写它、sret 清它，但**返回目标态就是
    //      这一位**，而 Linux 的返回路径把 pt_regs 里存的 sstatus 整字写回（entry.S 的
    //      csrw CSR_STATUS——这份构建里它就是 CSR_SSTATUS，SR_SPP=0x100）。把它掩成恒 0，
    //      等于每次内核态陷阱返回都掉进 U，紧接着取内核文本吃 cause 12，实测是同址反复 oops。
    // 两条写路（mstatus 整写 / sstatus 掩码合并）汇成一份下一拍值，WARL 只落一次。
    wire mstatus_wmask : u64 = 0x00000000000C79AA      // 本核可写位段（含 FS[14:13]）
    wire mstatus_ro    : u64 = 0x0000000A00000000      // SXL[35:34]=2、UXL[33:32]=2（只读）
    wire mstatus_sw   : u64 = is_mstatus ? csr_wdata : ((r_mstatus & ~sstatus_mask) | (csr_wdata & sstatus_mask))
    wire mstatus_warl : u64 = (mstatus_sw & mstatus_wmask) | mstatus_ro | ((mstatus_sw & (1 << 12)) >> 1)

委派：谁家门口的信

陷阱进 M 还是进 S，由两张掩码分工：medeleg 管异常、mideleg 管中断；命中掩码位且当前态 ≤ S，才走 S 侧。异常侧收全值（每一条异常都可以选择委派），中断侧只收 S 侧的三个源——mideleg 的写侧掩码是 0x222（SSIP(1) / STIP(5) / SEIP(9)），MSI(3) / MTI(7) / MEI(11) 按规范不可委派，写进来也落不回。

这就是"内核与固件分家"的那一刀：OpenSBI 跑在 M 态，把内核该自己管的缺页、定时器中断委派下去；内核在 S 态处理这些东西，不用每次都敲 M 态的门。而 S 态要碰固件（比如读时间、发核间中断），只有一条 ecall——cause 9，进 M 态，由 OpenSBI 的 trap handler 接活。这就是 SBI。

三态落地的那几拍

判据表在 ext/csr.prism 的 csr_check：100 拍、28 列、74 组行内期望。把 U 态前后那几拍摘出来（priv 列是当前特权态，csr_illegal_priv 是高侧号的第二重门）：

$ prism run whitebow/ext/csr.prism --run csr_check --debug （100 拍 × 28 列，摘 7 拍）
cycle mret sret trap_cause trap_to_s csr_illegal_priv priv 86 1 0 0 0 0 0 ← mret：MPP=U(0) ⇒ 真落 U 态 87 0 0 0 0 1 0 ← U 态读 mscratch（M 侧号）：第二重门拦下 88 0 0 0 0 1 0 ← U 态写 stimecmp：同样拦下 89 0 0 11 1 0 1 ← 一条 trap、委派放行、当前 U ⇒ 进 S 侧 91 0 1 0 0 0 0 ← sret：SPP=0 ⇒ 回 U（不是"恒回 S"了） 93 0 0 11 0 0 3 ← 同一发 trap、这次不委派 ⇒ 进 M 97 1 0 0 0 0 1 ← mret：MPP=S ⇒ 回 S # expect: 74/74 拍有断言 · 6 列 · 全等 ✅

对照第 15 集那张表看：那时 sret 出来 priv 恒落 1（S）；现在第 91 拍落的是 0（U）——同一条指令，多了一个可回的地方。U 态里摸 M 侧 / S 侧号，全被号表第二重门挡住（87 / 88 两拍）——低特权侧碰不到高特权状态，这一条不靠软件自觉，靠硬件拦截。

还差一块拼图：谁"消费"这些态

到这一集为止，态切换的机器全齐了——但地址翻译还没有。M / S 态都在跑物理地址；satp 号在表上、值存得下、也把三个出口（mmu_en / root_ppn / asid）引了出来，消费它们的 MMU 机构是第五日的事。眼下只把写侧的 WARL 钉住了：

prismwhitebow/ext/csr.prism · satp 的 MODE WARL
    // ---- satp 的 WARL：MODE[63:60] 只收 Bare(0) 与 Sv39(8) ----
    // 规范：写入不支持的 MODE 时整笔写没有效果，任何一位都不改（不是只掩 MODE 那四位，
    // 这点与 hgatp 的普通 WARL 相反）。内核探测档位靠 csrw 之后回读：Sv48/Sv57 落不下就
    // 降一档重试，所以"整笔 NOP"恰好是让它自己退回 Sv39 的那一下。
    // 不遮的后果比 trap 难查：Sv48 写进来后 [63:60]=9，mmu_sv39 判假 ⇒ 内核以为在翻译、
    // 我们一路直通。
    wire satp_mode_ok : u1  = csr_wdata[63:60] in [0, 8]
    wire satp_warl    : u64 = satp_mode_ok ? csr_wdata : r_satp

顺便把两条"这台机器的脾气"登记在案：wfi 现在译成 NOP——不睡，只是白等；计数器与三道门（mcounteren 的 CY/TM/IR、scounteren 第二道、mcountinhibit）已就位，谁读得到 time / cycle 由门说了算。

小结

  • ecall 按当前态编 cause（U=8 / S=9 / M=11）、ebreak 报 3；系统调用是一次陷阱，不是跳转。
  • 特权门控：mret 只 M、sret/sfence.vma ≥S；不够格 = 非法指令 cause 2，不静默。
  • 进陷阱压 MPP / SPP 与 PIE，退陷阱弹回来——特权级只沿 mret / sret 两条路变；MPP 合法集 {U, S, M}，保留编码 2 必须挡。
  • 委派：异常走 medeleg（收全值）、中断走 mideleg（只收 0x222）——内核与固件分家的那一刀。
  • 判据：csr_check 100 拍 × 28 列、74 组行内期望全等；U 态落地那几拍逐行摘在上面。
  • 没消费的登记在案：satp 只存不译（第五日 MMU）、wfi=NOP。
