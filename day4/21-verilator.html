换成跑得更快的 Verilator
第二后端：跑得起百万拍

下一集 OpenSBI 要在串口上打出 banner——那是一条两百多万拍的启动路径。用 golden 直跑，按本机实测的每拍成本要熬十个小时；用 iverilog，DDR 这一档它连语法都过不了。这一集换一条腿：SV 编成 C++ 模型、ctypes 直跑——这条腿不是"更快"，是"唯一能跑"。

"又造出各样飞鸟，各从其类。神看着是好的。" —— 《创世记》 1:21
← 第 20 集 · 模式切换与系统调用 第 22 集 · OpenSBI 起 banner 与交棒 →

默认那条腿，跑不到终点

默认的 RTL 通路是 iverilog + vvp：把生成的 SV 编成网表，交给解释执行的四态仿真器。几十拍、几千拍它都很好——问题出在"百万拍"这个词上。先把账摊开（本机实测，第 18 集那颗 SoC、同一条 sbi_boot_console 命令）：

腿跑 2,000 拍跑 2,351,426 拍（到 banner）每拍成本（边际）
golden 直跑33.5 s≈ 10 小时≈ 16 ms
verilator6.4 s（含模型加载）8.4 s≈ 0.85 µs

边际一列按两档的时间差除以拍数差算，固定成本（模型加载、编译产物装载）已扣掉。两个数量级以上的差距，来源不是"实现得好不好"——是执行模型：golden 是 Python 逐拍解释整棵 AST，verilator 是把整个设计编译成一份 C++ 源码再按 native 跑。差的不止速度，还有能力边界：--threads 这类"看起来能并行"的开关实测是负收益（下面代码里记着数）；能并行的只有编译期。

这条路怎么走的

  1. verilator --cc 把生成的 SV 翻成 C++（--top-module 指顶层，--savable 带上快照能力）；
  2. harness（一段 C++）把模型跑起来、把逐拍输出整段接回来；
  3. 两者编成一个动态库；
  4. ctypes.CDLL 加载，调一个 prism_vsim_run。

为什么绕"动态库"这一下，而不是直接编个可执行文件？编译器源码里这条注释回答得最干净（也是这台开发机上踩出来的）：

pythonfrontend/prism.py · 为什么是动态库
# 可选的第二仿真后端：verilator
#
# 为什么编【动态库】而不是用 `verilator --binary` 那个可执行文件：开发机上【新建的
# 二进制不允许直接 exec】（会被 SIGKILL，连 clang 新编一个空 main 都一样），而 dlopen
# 进一个已在跑的进程是允许的——TLM 通路一直是这么走的。
#
# 它是 2-state 后端：X/Z 一律折成 0/1。四态语义（X 写守卫、位运算逐位吸收、悬空
# 分辨）是 golden 侧刻意建出来的，verilator 看不见——所以它只做"这一跑不问 X"的
# 可选通路，默认永远是 iverilog。

顺带把这条腿的定位写清楚：它是 2-state 的——X/Z 一律折成 0/1。四态语义（X 写守卫、位运算逐位吸收、悬空分辨）是 golden 侧刻意建出来的，verilator 看不见；所以它只做"这一跑不问 X"的可选通路，默认永远是 iverilog。

DDR 那一档：iverilog 连语法都过不了

第 18 集说过，DDR 走 storage : ram = host——存储本体在仿真宿主的内存里。这一档生成的 RTL 里会有 import "DPI-C"（模型经它去读写宿主内存），而 iverilog 13.0 连这句都不 parse：

pythonfrontend/prism.py · host 档的门控
def _need_dpi_backend(cu, where: str, remedy: str) -> int:
    """host 档需要 DPI 后端的门控：非 verilator 一律当场报错（返回非 0 表示已判死）。

    iverilog 13.0 连 `import "DPI-C"` 都不 parse——module、package、`$unit` 三种作用域
    都 syntax error，实测。这里不静默退回片上阵列：那一退就把用户点名的存储档换成了
    另一档，跑的已经不是他写的那颗芯片。

    `remedy` 由调用方给——`run` 有 `--sim` 可换，`cosim` 子命令没有，它的出路是换命令。
    指错路的报错等于没报错。"""

注释里最后一句是关键：不静默退回片上阵列——那一退就把用户点名的存储档换成了另一档，跑的已经不是他写的那颗芯片。所以 host 档 + RTL 通路的组合里，verilator 不是"可选项"，它是唯一入口：--rtl --sim verilator 缺一不可。若要把四态语义留在默认通路上，那颗 ram 必须换回片上版再跑。

--time：把"跑多久"变成拍数

长跑的判据常常是"跑到出现某件事"（until : console.tx.count >= 16）。但探针、CI、看一眼就停的场合要的是"跑多久"——--time 按时长封顶：换算读 run 的 clock（100 MHz ⇒ 一拍 10 ns，1 µs = 100 拍），不硬编码。大小写与单位都有讲究（裸数字当场拒绝——"单位不是可猜的"）：

pythonfrontend/run_timing.py · 时长 → 拍数
def cycles_for_ns(time_ns: float, period_ns: float) -> int:
    """时长 → 拍数：向上取整（"至少跑到这个时长"），至少 1 拍。

    减 1e-9 是给整除情形留的浮点余量：1.05us/10ns 在浮点里是 105.00000000000001，
    不减会多跑一拍。"""
    return max(1, math.ceil(time_ns / period_ns - 1e-9))

最后那个 1e-9 的余量是实测暴露的一处隐患：1.05us / 10ns 在浮点里是 105.00000000000001，向上取整会多跑一拍。封顶信息打在收工行里——（until NEVER fired (cap 6000)） 读起来就是"窗口用完了，不是没跑"。

同一条路上还有快照能力：--snap-save / --snap-load 把"跑到哪儿了"存下来（模型状态 + 宿主内存两半），下次从那儿续跑。实测一次（同一个 banner 目标）：第 200,000 拍存盘——0.4 MB 模型 + 134 MB 内存（内存那头就是 128MB DDR 的驻留页）；--snap-load 续跑，收工行变成「从快照续跑：基线第 200000 拍，再跑 200000 拍」。百万拍的长跑不用每次从头来。

那几笔编译期的账

模型编一次、跑很多次——所以这一档的功夫一半花在编译上。编译器里记着四笔实测账：

pythonfrontend/prism.py · 编译期并行与线程开关
    # 并行编 .o 再链接：一次 clang++ 编全部是串行的（实测 7.6s），按核并行出目标
    # 文件再链接只要 3.4s。注意别去碰 verilator 的 `--threads`——那是仿真期多线程，
    # 在这类设计上实测是负收益（4 线程慢 1.7×、8 线程慢 2.7×）。
  • 编 .o 并行：一次 clang++ 编全部是串行的（7.6 s），按核并行出目标文件再链接 3.4 s。
  • 优化等级：-O0 跑 20,000 拍 1.92 s，-O2 0.15 s——13 倍，编译只多花 1.6 s。长跑的场景下，这笔账怎么算都该选 -O2。
  • 别碰 --threads：那是仿真期多线程，在这类设计上实测负收益（4 线程慢 1.7×、8 线程慢 2.7×）。
  • 快照能力不花钱：--savable 前后每拍 0.424 / 0.427 µs——无成本，直接带上。

还有一笔"选哪条腿"的账在 run_soc.sh 里记着：四态的 iverilog 比 verilator 约慢 26×——所以长跑默认 verilator，要四态语义显式换回去。

一处必须写进正文的隐患：run 的 RTL 通路没有硬门

gen-rtl 与 cosim 遇到"缺 @schedule、降不了 RTL"会当场报错退出；但 run --rtl 只打一条 [warn]，然后照常把表打完——"RTL tb 跑完"这几个字可以是假的。做长跑判据前先看一眼有没有这条 warn，或者把 RTL 腿换成 cosim 跑——硬门在那边。

小结

  • golden 是正确性的裁判，不是跑长跑的腿：本机实测每拍 ≈ 16 ms，235 万拍要十小时级。
  • verilator 路径：--cc 出 C++ 模型 + harness → 动态库 → ctypes 直跑（为什么必须是动态库：开发机上新建二进制不许 exec；dlopen 允许）。
  • 它是 2-state、可选、默认 iverilog；但 host 档（DDR）只有它能上——这条腿是准入，不是加速。
  • --time 按时长封顶（读 run 的 clock 换算，带浮点余量）；封顶会打在收工行里。--snap-save/--snap-load 让长跑能从半路续。
  • 编译期的账：并行 .o（7.6→3.4 s）、-O2（13×）、别开 --threads（负收益）、--savable 免费。
  • run --rtl 缺 @schedule 只 warn——假"跑完"的隐患，判据要用硬门那条路。

复现本集

bashreproduce
pip install prism-hdl
prism deps --install                  # verilator 也在可选安装清单里

# 短窗对照（同一个 SoC、同一条跑法）：
time prism run soc/soc.prism --run sbi_boot_console --host console=file:/tmp/g \
     --time 20us                      # golden：2000 拍
time prism run soc/soc.prism --run sbi_boot_console --host console=file:/tmp/v \
     --rtl --sim verilator --time 20us    # verilator：同一窗口

# 快照：存、续
prism run soc/soc.prism --run sbi_boot_console --host console=file:/tmp/s1 \
     --rtl --sim verilator --time 2ms --snap-save /tmp/at2ms.snap
prism run soc/soc.prism --run sbi_boot_console --host console=file:/tmp/s2 \
     --rtl --sim verilator --time 2ms --snap-load /tmp/at2ms.snap
