起 banner 与交棒
OpenSBI，二百三十五万拍

零件齐了（一片芯片）、嘴装上了（uart8250）、三态到位、腿也换好了。这一集把 OpenSBI 按槽位表装进 DDR、把内核摆在它身后——然后等。二百三十五万拍之后，串口上落下第一行字；八百六十万拍之后，它把话说全，把接力的棒交给内核。第四日到此收束：这台机器活了。

"有晚上，有早晨，是第四日。" —— 《创世记》 1:19

它得有个"上一级"

真实机器上，OpenSBI 不是第一个醒来的东西——它由上一级 bootloader 按 fw_dynamic 协议引导：寄存器里递三样东西——a0 是 hartid、a1 指向 DTB、a2 指向一个 48 字节的 struct fw_dynamic_info，然后跳进固件。

这颗芯片的"上一级"就在 ROM 里：本体自带的默认镜像就是一段 Boot stub（第 18 集说过的 ROM——"换固件只是换 image"，而它自带的这份"固件"其实是引导器）。它做三件事，全在 23 条指令里：

prismsoc/ip/rom.prism · Boot stub（ROM 的默认镜像）
    mem ram : [SIZE] u32 = [
        // Boot stub：构造正数物理地址（lui 会符号扩展，须 slli+srli 清高位），
        // 设 a1=DTB，再自己写 fw_dynamic_info 并把地址交给 a2，最后跳固件入口。
        // DTB  = DDR 基址 + 字节槽位 0x100000 = 0x80100000（槽位表见 soc/soc.prism 头部；
        //        这一段必须躲开固件自己的 scratch/栈/堆，它们从 _fw_end 往上长）
        0x801005B7,   //  0: lui   a1, 0x80100     a1 = 0xFFFFFFFF80100000
        0x02059593,   //  4: slli  a1, a1, 32      a1 = 0x8010000000000000
        0x0205D593,   //  8: srli  a1, a1, 32      a1 = 0x0000000080100000
        // info 结构体在 DDR 基址 + 字节槽位 0x108000 = 0x80108000，a2 指它
        0x80108637,   // 12: lui   a2, 0x80108     a2 = 0xFFFFFFFF80108000
        0x02061613,   // 16: slli  a2, a2, 32      a2 = 0x8010800000000000
        0x02065613,   // 20: srli  a2, a2, 32      a2 = 0x0000000080108000
        // struct fw_dynamic_info 六个字段（偏移 0/8/16/24/32/40，各 8 字节）逐个 sd 进
        // RAM——上一级 stage 该干的活，不做成静态镜像：magic、version、next_addr、
        // next_mode、options、boot_hart。字段序与取值对着 OpenSBI 的 include/sbi/
        // fw_dynamic.h：magic=0x4942534f('OSBI')，version≤2，next_mode 1=S 态。
        0x494252B7,   // 24: lui   t0, 0x49425     t0 = 0x49425000
        0x34F28293,   // 28: addi  t0, t0, 0x34F   t0 = 0x4942534F  magic
        0x00563023,   // 32: sd    t0, 0(a2)       info.magic
        0x00200313,   // 36: addi  t1, x0, 2       t1 = 2           version
        0x00663423,   // 40: sd    t1, 8(a2)       info.version
        0x802003B7,   // 44: lui   t2, 0x80200     t2 = 0xFFFFFFFF80200000
        0x02039393,   // 48: slli  t2, t2, 32      t2 = 0x8020000000000000
        0x0203D393,   // 52: srli  t2, t2, 32      t2 = 0x0000000080200000
        0x00763823,   // 56: sd    t2, 16(a2)      info.next_addr（交棒给 S 态的下一级）
        0x00100E13,   // 60: addi  t3, x0, 1       t3 = 1           NEXT_MODE_S
        0x01C63C23,   // 64: sd    t3, 24(a2)      info.next_mode
        0x02063023,   // 68: sd    x0, 32(a2)      info.options = 0
        0x02063423,   // 72: sd    x0, 40(a2)      info.boot_hart = 0
        // 固件入口 = 0x80000000
        0x800002B7,   // 76: lui   t0, 0x80000     t0 = 0xFFFFFFFF80000000
        0x02029293,   // 80: slli  t0, t0, 32      t0 = 0x8000000000000000
        0x0202D293,   // 84: srli  t0, t0, 32      t0 = 0x0000000080000000
        0x00028067    // 88: jalr  x0, 0(t0)       跳转到字节 0x80000000

三件事逐条对上：算 a1 = DTB 地址 0x80100000（lui 会符号扩展，所以每条地址都要 lui + slli + srli 三下拼出正数）；构造 a2 = info 结构体地址 0x80108000；六个字段逐个 sd 进 RAM，然后 jalr 跳 0x80000000——固件入口。a0（hartid）故意不设：单 hart 机器，让 OpenSBI 自己按复位 pc 推。

fw_dynamic_info：上一级留给固件的六张纸条

这 48 字节不是预装的镜像文件，是 stub 在运行时写进 DDR 的——真实机器上这个结构体同样由上一级 stage 现场构造。字段序与取值对着 OpenSBI 的 include/sbi/fw_dynamic.h：

偏移字段这台机器写的值含义
+0magic0x4942534F'OSBI'，校验"这真是给 OpenSBI 的"
+8version2结构体版本（≤2）
+16next_addr0x80200000交棒地址 = 内核装载点
+24next_mode11 = S 态——交棒后进监管态
+32options0无特殊选项
+40boot_hart0引导 hart

next_addr 与内核的装载位置是同一个数——槽位表里内核起点 0x200000（DDR 基址 +2MB，Image 头里的 text_offset 钉死的），stub 写的正是它。交棒址与装载址不许两处各写一遍，这是第 18 集那张槽位表的收口。

装车，按下电源

要装的是三份数据：固件、DTB、内核（外加 initramfs），全写在 run 的 image 段里（第 18 集引过）。开跑：

$ prism run soc/soc.prism --run sbi_boot_console --host console=file:/tmp/sbi --rtl --sim verilator
[run] sbi_boot_console: RTL tb 跑完（until true at cycle 2351426） $ xxd /tmp/sbi.tx 00000000: 0d0a 4f70 656e 5342 4920 7631 2e35 0d0a ..OpenSBI v1.5..

判据 until : console.tx.count >= 16：等前 16 个字节。等的时候能看的只有一个地方——PREFIX.tx。它启动即清空、每解出一字节立刻落盘：整条仿真流在百万拍期间全是空的，.tx 是唯一的实时进度（第 19 集那句话，到这一集成了命根子）。

十六进制那行值得盯两秒：0d0a 开头、0d0a 收尾——CRLF。OpenSBI 不知道你的终端是不是 Unix，它按串口的老规矩发回车换行。

这份报告里有几样东西值得对照前面几集读：Platform 段——whitebow-virt（DTB 里的名字）、aclint-mtimer @ 100000000Hz（第 16 集的 CLINT 与 100 MHz）、uart8250（第 19 集）；Domain0 段的三行交棒信息——Next Address : 0x80200000、Next Arg1 : 0x80100000、Next Mode : S-mode，与 Boot stub 写进 info 的那两个地址逐个对上；Boot HART 段——rv64imafdc（第 17 集补的 A 与 C 在 ISA 字符串里）、sstc,zicntr、PMP Count : 16、MIDELEG : 0x222（第 20 集那条"只收三个源"）、MEDELEG : 0xb109。

最后一行 Linux version 6.6.0 … 是内核自己打的——交棒之后，CPU 已经在跑 S 态的内核，第四日的旗子到此插上。它后面怎么把根文件系统挂起来、怎么开出第一个用户态进程，是第五日的正题。

三条真病因（这台机器上踩出来的）

现在看起来顺理成章的一跑，是踩着三个坑过来的。按时间排：

症状根因修法
串口 0 字节，死等AMO 同拍先写后读：amoswap 的读相位与写相位挤在同一拍，DPI 无先后保证，冷启动的自旋锁拿到写后值（抽签输掉）——第 17 集"判决与清除差一拍"的整机版读相位与写相位分两拍（A 扩展落地）
串口 0 字节，libfdt 报 -FDT_ERR_BADMAGICDTB 槽位压在固件自己的运行区：OpenSBI 的 scratch / 栈 / 堆从 _fw_end 往上长，栈一深就把 DTB 头踩了DTB / info 挪出生长区（0x100000 / 0x108000）——槽位是算出来的
固件挂在 mstatus_init缺 scounteren / mcountinhibit 号：OpenSBI 无条件写它们，号不在白名单就是非法指令 ⇒ sbi_trap_error ⇒ 挂死号进白名单（位段读零）——实测卡点：mtval = 0x1063d073，正是 csrw scounteren, 7

三条都属于同一类：机器功能其实都在，错在"对它做了什么"——所以判据不能只看"跑没跑起来"，要能点名到这一拍、这一条。第 16 集那句话在这儿兑现：CPU 会疼；这三条，全是它喊出来的疼。

判据怎么钉

  • 常驻套件不背百万拍：tests/test_soc.py 里的 test_sbi_boot 把窗口封在 2000 拍——开场退休序 = Boot stub 的前 12 条（pc 0..44）、第 0 拍 info_magic 还是 0、窗口内出现 0x4942534F、随后 pc 跳进 0x80000000 区。百万拍那一跑留给 ./run_soc.sh 手动做。
  • 反证：把 stub 里那句 sd 摘成 NOP 再跑，info_magic 判据必须红——写"info 是运行时构造的"这句话，得由判据兑现。
  • 槽位对账：test_fw_layout_slots 把槽位表与 fw/sbi.dts 里的 reg / initrd-end 逐项对平，外加"stub 写的 a1/a2 与 expose 下标×8 是同一批数"——两处各写一遍必然漂移，所以两处都对同一份期望。

小结

  • ROM 的默认镜像就是"上一级 stage"：23 条指令算 a1/a2、写 fw_dynamic_info 六个字段、跳 0x80000000。
  • 交棒三件套在报告里能直接读到：Next Address 0x80200000 / Next Arg1 0x80100000 / Next Mode S-mode——与 stub 写进 DDR 的值逐个对上。
  • 长跑判据只认 .tx：每字节立落盘，是百万拍里唯一的实时进度；第一条实跑 = 16 字节 @ 2,351,426 拍。
  • 完整报告 2600 字节 @ 9,713,905 拍，末行已经换成 Linux 自己的声音——交棒落地。
  • 三个坑（AMO、DTB 被栈踩、缺号）都留下"名点到拍"的实测：mtval = 0x1063d073 是最具代表性的那一个。
  • 第四日到此收束：会疼、会躲、会算、会锁、有一片芯片、会说话、分得清三态、跑得起百万拍、起得来 OpenSBI。这台机器活了。
"神看着是好的。" —— 《创世记》 1:21
