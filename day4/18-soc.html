把 CPU 装进 SoC
soc.prism：一颗 SoC = 一个 design

第 16 集把中断接进核，第 17 集把指令集补到 M · A · C——零件齐了。这一集把它们放进同一片硅：一颗 SoC = 一个 design。地址图整个交给 MemoryMap——它不是硬件部件，是一张按字节口径的地址表，DDR 里排一张槽位表。这一集之后，换程序就只剩换镜像这一件事。

部件齐了，还缺地址归属

已备好的部件：一颗五级流水的核（异常与中断已接入，指令集到了 M · A · C）、一颗 CLINT、一颗 PLIC。

放进芯片之前还缺三样：核要取指——得有人把指令喂到取指口；核要访存——得有一块可写的主存；对外要通信——得有一根出去的路。再加一样最不像零件的：谁来回答"地址 0x80000000 归谁"。

ROM · 取指

组合读的取指存储器，一个 32 位字 + 下一字（RVC 跨字指令一次看两个字）。本体自带的默认镜像是 Boot stub——第 22 集会讲它怎么把 a1/a2 交给 OpenSBI。

DDR · 主存

128MB、可写。仿真里本体落在宿主内存（storage : ram = host），不生成门阵列——这一档是后面百万拍长跑的地基。

Uart8250 · 串口

8250 寄存器面 + 8N1 收发，引脚接宿主。OpenSBI 的 banner、内核的 console 都从这一根线出去。

MemoryMap · 地址图

不是存储也不是外设——它是"谁在哪个地址"的唯一拥有者。译码、片选、读数据选择、不可缓存属性，全在它体内。

一样一样挂上去。整个芯片就是一个 design：

prismsoc/soc.prism · 一颗 SoC 的零件表
design WhitebowSoc {
    cpu  : Whitebow
    // 取指 ROM：深度按 OpenSBI 镜像给（100364 字）。本体自带的默认镜像是 Boot stub——
    // 算好 a1/a2 再跳 0x80000000；换固件写在下面各 run 的 image 段，这颗芯片一个字不动。
    rom  : ROM<SIZE = 100364>
    // 128MB（字宽 64 位：ld/sd 整字落得下）。host 档的形状与 sram 一条不差：组合读、
    // 同步写、越窗读 0、不读时给 0——差的是存储本体在仿真宿主的内存里，不生成门阵列。
    // 这一档只有 DPI 后端能跑：RTL 通路要 `--sim verilator`（iverilog 不认 import "DPI-C"）。
    dm   : DDR<SIZE = 0x1000000, W = u64, A = u27>   // 128MB = 0x1000000 字 × 8B
    // 串口用 10 Mbaud（10 拍/位）：仿真里判据是**字节内容**不是时间，可移位仍要占拍
    // ——100 kHz 下一个字节就要 1 万拍。8250 面照收固件写的分频寄存器（忽略）。
    // 分频只在这一处给，tx 与 rx 按同名代入，两侧写不出不同的波特率。
    uart : Uart8250<CLOCK_FREQ = 100000000, BAUD_RATE = 10000000>
    clint: CLINT
    plic : PLIC
    // ---- 统一地址映射：收实例，不收端口 ----
    // 译码、片选门控、读数据多路选择、不可缓存属性（dm_nc）全在 MemoryMap 体内，
    // 地址图因此只有一个拥有者；本 design 只剩下面 connect 那几行——中断路由加 dm_nc。
    memmap : MemoryMap(cpu=cpu, rom=rom, dm=dm, uart=uart, clint=clint, plic=plic)

注意 memmap 那一行例化——它收的不是端口，是实例：MemoryMap(cpu=cpu, rom=rom, dm=dm, uart=uart, clint=clint, plic=plic)。于是顶层只剩这么几根线：

prismsoc/soc.prism · 顶层只剩中断路由
    // PLIC 中断源：uart.interrupt 落在 source[1]（规范 §1.4 把 0 号留作"无中断"，
    // DT 里 serial 的 interrupts = <1> 与之同源）。左移一层在这里成 wire——connect
    // 的端点不能是表达式。
    wire src_uart : u32 = u32(uart.interrupt) << 1

    connect {
        src_uart -> plic.source

        // 中断链路：CLINT 供两根电平（mtip 与 msip）；mtime 的值进核，`time` CSR 读它，
        // S 态定时器的 pending 也在核内拿它跟 stimecmp 比（Sstc）。PLIC 双 context 的
        // 两根通知各归各：M 侧 meip、S 侧 seip（内核在 S 态走的是后者）。
        clint.mtip       -> cpu.mtip
        clint.msip_level -> cpu.msip
        clint.mtime_val  -> cpu.mtime_val
        plic.meip        -> cpu.meip
        plic.seip        -> cpu.seip

        // 不可缓存属性（设备窗口）
        memmap.dm_nc     -> cpu.dm_nc
    }

五根中断链路（CLINT 两根、PLIC 两根通知、mtime 值进核）、一根 PLIC 源（串口在 source[1]）、一根不可缓存属性。地址的事一根都看不见——全在里面。

地址图只有一个拥有者

老办法是这样的：每个设备一套"命中比较 + 片选门控 + 读数据多路选择"，全手写在顶层。问题不在写不出来，而在地址事实散成十几处——加一个从设备要动五处连线，改一段地址要满文件找。这台把整张图托给一颗 MemoryMap，而且是收实例、不收端口：

prismsoc/ip/memmap.prism · 窗口表与命中
composer MemoryMap(cpu : Whitebow, rom : ROM, dm : DDR, uart : Uart8250, clint : CLINT, plic : PLIC) {
    // ---- 输出：不可缓存属性（设备窗口=1）----
    out  dm_nc      : Signal<u1>    // UART/CLINT/PLIC = 1，DDR/SRAM = 0

    // ---- 译码前先把两条口的字补零成字节地址（口宽是数据通路事实，不进地址图）----
    wire im_pa : u40 = {cpu.im_addr, {2{0}}}    // 取指口 PA[39:2] → PA[39:0]
    wire dm_pa : u40 = {cpu.dm_addr, {3{0}}}    // 数据口 PA[39:3] → PA[39:0]

    // ---- 取指口的窗口（地址线 im_pa）----
    w_im_rom: AddrWindow<BASE = 0x00000000, SIZE = 0x100000>   // ROM   1MB（深度 100364 个 32 位字）
    w_im    : AddrWindow<BASE = 0x80000000, SIZE = 0x8000000>  // DDR   128MB

    // ---- 数据口的窗口（地址线 dm_pa）----
    w_clint : AddrWindow<BASE = 0x02000000, SIZE = 0x10000>    // CLINT 64KB
    w_plic  : AddrWindow<BASE = 0x0C000000, SIZE = 0x4000000>  // PLIC  64MB（riscv,plic0 字节图到 0x201004，窗口顶到 UART 前）
    w_uart  : AddrWindow<BASE = 0x10000000, SIZE = 0x2000>     // UART  窗口 8KB，面只用得上第一个字
    w_dm    : AddrWindow<BASE = 0x80000000, SIZE = 0x8000000>  // DDR   128MB——与 w_im 同一段地址、同一块存储

    // ---- 命中（窗口 hit 就是片选）----
    wire in_im_rom : u1 = w_im_rom.hit
    wire in_im     : u1 = w_im.hit
    wire in_dm     : u1 = w_dm.hit
    wire in_uart   : u1 = w_uart.hit
    wire in_clint  : u1 = w_clint.hit
    wire in_plic   : u1 = w_plic.hit

整张地址图就是上面那六条 AddrWindow：

段字节物理地址是什么
ROM0x0000_0000 – 0x000F_FFFF取指窗口 1MB（深度 100364 个 32 位字；越界由 ROM 自己读 0）
CLINT0x0200_0000 – 0x0200_FFFFmtime / mtimecmp / msip（第 16 集那颗）
PLIC0x0C00_0000 – 0x0FFF_FFFF64MB 窗口，riscv,plic0 字节图到 0x201004
UART0x1000_0000 – 0x1000_1FFF8250 面，寄存器号 = 字内字节偏移（下一集）
DDR0x8000_0000 – 0x87FF_FFFF128MB 主存
其余—读 0、写丢弃

两个细节值得停一下：

  • DDR 挂了两条窗口（w_im 与 w_dm），BASE/SIZE 一字不差。不是重复——取指口和数据口是两根各自独立的地址线，一根线一个比较器。两个实例数字相同，正因为它们是同一块存储的两个访问通路。
  • 窗口的 hit 就是片选。整套地址译码归纳起来就是六个 hit——命中之后的门控与读选择，在下一节。

地址只有一套口径

地址图里只写一种东西：字节物理地址。总线口一拍搬 4 字节还是 8 字节，是数据通路的事实，不是地址的事实——取指口给出 PA[39:2]、数据口给出 PA[39:3]，进窗口之前各自补零归一成 PA（补零不花逻辑）：

prismsoc/ip/addrmap.prism · 窗口比较器
module AddrWindow<BASE: int, SIZE: int> {
    // 收总线上的**字节**物理地址。两条口各自补零到 PA 之后，BASE/SIZE 不必再区分
    // "这是取指口径还是数据口径"——一块存储一段地址，写一处数就够两条口用。
    in  addr : Signal<u40>      // 字节物理地址 PA[39:0]
    out hit  : Signal<u1>       // 落在 [BASE, BASE+SIZE) 内
    out off  : Signal<u40>      // 命中时的窗口内字节偏移；不命中给 0

    hit = (addr >= BASE) & (addr < BASE + SIZE)
    off = hit ? (addr - BASE) : 0
}

于是同一段地址对两条口就是同两个数字——而这两个数字与 fw/sbi.dts 里各节点 reg 的数是同一批数。地址图只有一个来源，不许第二套数。

命中判据是范围比较（addr ≥ BASE 且 addr < BASE + SIZE），不是位选窗。位选窗只判低几位——一个 64KB 的窗口，紧接它后面那一块也会"命中"，高位地址别名直接进窗口。范围比较则窗外一律不命中。

还有一个写法问题：为什么是"一地址线一实例"，而不是一个带 N 路输出的译码器？因为片选是 N 根各自独立的线，而端口不能是数组、也没有束类型可传——N 当不了形参，固定 N 的译码器就把从设备个数烧进了模块里。实例化的写法让每颗从设备自带窗口：加一个从设备就是加一个实例，已有代码一行不动。

命中之后：读谁、写谁、谁不可缓存

prismsoc/ip/memmap.prism · 命中即门控
    // ---- 取指口：ROM 按 32 位字索引，DDR 按 64 位字索引——字节偏移各自折算 ----
    wire im_word     : u27 = cpu.im_addr[26:0]     // ROM 用：绝对 32 位字索引
    wire im_ddr_word : u27 = w_im.off[26:3]        // DDR 用：窗口内字节偏移 → 64 位字索引
    wire im_odd      : u1  = cpu.im_addr[0:0]      // 1 = 这条指令落在 64 位字的高半
    wire im_ren      : u1  = 1
    // 二选一：ROM 优先（低地址），窗外读 0
    wire im_rdata    : u32 = in_im_rom ? rom.rdata : (in_im ? (im_odd ? dm.im_rdata[63:32] : dm.im_rdata[31:0]) : 0)
    wire im_rdata_hi : u32 = in_im_rom ? rom.rdata_hi : (in_im ? (im_odd ? dm.im_rdata_hi[31:0] : dm.im_rdata[63:32]) : 0)

    // ---- 数据口：命中即门控，窗外读 0、写丢弃 ----
    wire dm_word : u27 = w_dm.off[26:3]        // 窗口内字节偏移 → 64 位字索引
    wire dm_abs27: u27 = cpu.dm_addr[26:0]     // clint/plic 内部仍看绝对字地址
    wire dm_ren  : u1  = cpu.dm_ren & in_dm
    wire dm_wen  : u1  = cpu.dm_wen & in_dm
    wire u_wr    : u1  = cpu.dm_wen & in_uart
    wire u_rd    : u1  = cpu.dm_ren & in_uart
    wire c_wr    : u1  = cpu.dm_wen & in_clint
    wire c_rd    : u1  = cpu.dm_ren & in_clint
    wire p_wr    : u1  = cpu.dm_wen & in_plic
    wire p_rd    : u1  = cpu.dm_ren & in_plic
    wire dm_rdata : u64 = in_dm ? dm.rdata : (in_uart ? uart.rd_data : (in_clint ? clint.rdata : (in_plic ? plic.rdata : 0)))
    wire _dm_nc   : u1  = in_uart | in_clint | in_plic
    dm_nc = _dm_nc

四件事，一件一件看：

  • 字索引各自折算：ROM 按 32 位字索引（取指口本身就是 32 位口径），DDR 按 64 位字索引（窗口内字节偏移右移 3）。im_odd 是取指口的最低位——1 表示这条指令落在 64 位字的高半，拼 RVC 跨字指令就靠它和 im_rdata_hi。
  • 命中即门控：dm_ren & in_dm、dm_wen & in_dm——窗外读 0、写丢弃；每个设备各拿自己的 wr/rd。
  • 读数据四选一：DDR → UART → CLINT → PLIC，都不命中给 0。
  • dm_nc：不可缓存属性。UART / CLINT / PLIC 这三个设备窗口给 1——设备寄存器的读有副作用（读走即消费），绝不能被缓存或合并。DDR 给 0。这一位现在只是接进核里存着；第五日 cache 落地时，它会变成一条真正拦访存的线。

DDR：128MB 主存，本体在仿真宿主

128MB 的真阵列在仿真里是个灾难：几十万比特的门、一张补零到满深度的 hex 侧车、每次 run 还重写一遍。这一档换了个放法——存储本体交给仿真宿主：

prismsoc/ip/ddr.prism · host 档后备
    mem ram : [SIZE] W

    // 数据口读
    rdata = (ren & (addr < SIZE)) ? ram[addr] : 0

    // 取指口读（组合，同拍出；越窗读 0，对齐 rom 行为）
    im_rdata    = (im_ren & (im_addr < SIZE)) ? ram[im_addr] : 0
    im_rdata_hi = (im_ren & ((im_addr + 1) < SIZE)) ? ram[im_addr + 1] : 0

    on clock {
        if (wen & (addr < SIZE)) {
            ram'[addr] = wdata
        }
    }
}

@schedule DDR {
    bitwidth  : { data:64 }
    pipeline  : 1 stage
    reset     : async_low
    clock     : 100 MHz, domain = single
    resource  : none
    latency   : 0 cycle
    storage   : ram = host, depth = SIZE, width = 64
}

形状与片上 SRAM 一条不差：组合读、同步写、越窗读 0、不读给 0——差的只是本体在哪。换来的代价是一张准入票：这一档在 RTL 侧生成 import "DPI-C"，而 iverilog 13.0 连这句都不 parse（module / package / $unit 三种作用域都是 syntax error）。所以 RTL 通路必须带 --sim verilator——这条腿不是"更快"，是"唯一能跑"（第 21 集细讲）。

也说清楚它不是什么：只作仿真后备，不可综合。片上真要大容量存储，要的是 BRAM / 缓存那一档，不是这一档。

DDR 里摆什么：一张槽位表

128MB 里放什么？币种是字节、零点就是 DDR 起点（0x80000000），与 MemoryMap 译出的窗口内偏移是同一个数。布局是一张槽位表——每条窗口的终点，正好是下一条槽位的起点：

偏移是什么窗口
+0x000000OpenSBI 固件0x048000（比文件 0x42878 宽出的尾巴补 0 = .bss/堆打底）
0x048000–0x0FFFFF固件自己的运行区（不给任何镜像）_fw_end 之上依次长 scratch / 栈 / 堆
+0x100000DTB0x008000（止于 info 槽位）
+0x108000fw_dynamic_info（不是镜像）48 字节，Boot stub 运行时写
0x108030–0x1FFFFF空着：解压 / 页表的生长区—
+0x200000内核 Image0x600000（6MB 槽位，止于 initrd）
+0x800000initramfs长度 = 文件长度（dts 的 initrd-end 由同一个数算）

中间那段"固件运行区"是实测暴露出来的教训：DTB 原先贴着固件尾巴（0x48000），可 OpenSBI 的 scratch / 栈 / 堆正是从 _fw_end 往上长的——栈一深就把 DTB 头踩了，libfdt 报 -FDT_ERR_BADMAGIC，串口一个字节都出不来。initrd 也挪过一次位：原先贴在内核尾巴上面只剩 10KB，换个稍大的 Image 就撞车。所以槽位是算出来的，不是抄来的。

装载位置写在源码里，换内容只是换文件：

prismsoc/soc.prism · 装载窗口 = 槽位表
run sbi_boot_console of WhitebowSoc {
    clock : 100 MHz
    image : {
        // 装载窗口就是上面那张槽位表：偏移零点 = DDR 起点（0x80000000），币种是字节，
        // 与 MemoryMap 译出的窗口内偏移同一个数。每条的终点正好是下一条的起点。
        // OpenSBI 原始固件（无 RVC）：0x048000 比文件（0x42878）宽出的尾巴补 0，
        // 那是它 .bss/堆的打底——写死字节数就是把这件事写在明面上。
        sbi : dm[0x000000:0x048000] = @load("../fw/fw_dynamic.bin"),
        // DTB（含 serial@10000000/cpus/memory/clint）：32KB 槽位，止于 info 槽 0x108000。
        // 起点必须在固件运行区（_fw_end 之上的 scratch/栈/堆）之外，见文件头那张表。
        dtb : dm[0x100000:0x008000] = @load("../fw/sbi.dtb"),
        // 内核起点 0x200000 = Image 头里的 text_offset（RAM 基址 +2MB），而 Boot stub
        // 写进 info.next_addr 的正是同一个数——交棒址与装载址是同一件事，不许两处各写
        // 一遍。槽位给到 6MB（文件 0x2FD6F8），止于 initrd 槽位。
        kernel : dm[0x200000:0x600000] = @load("../fw/Image"),
        // initramfs 根文件系统：起点 8MB（原先贴在内核尾巴上面只剩 10KB，换个稍大的
        // Image 就撞车），长度 = 文件长度——dts 的 initrd-end 必须由同一个数算出来
        rootfs : dm[0x800000:] = @load("../fw/initramfs.cpio")
    }
    host  : {
        console = uart_8n1(tx = uart.tx_pin, rx = uart.rx_pin, divisor = 10)
    }
    until : console.tx.count >= 16
    show  : { pcv, retire_valid, retire_pc, retire_rd, retire_data,
              console.rx.count, console.rx.last, console.tx.count, console.tx.last,
              info_magic, kimg_first, dm_addr_val }
}

--image sbi=…／dtb=…／kernel=… 换的只是数据——芯片的 RTL 一个字不动。

跑起来：先装得进读得对，再让它动

第一步是"装得进、读得对"：把官方固件灌进 ROM 窗口，抽四个字看。ROM 是组合读，第 1 拍就有值：

$ prism run soc/soc.prism --run image_check --debug
cycle img_first img_w1 img_w17 img_last 0 328755 361651 62127139 0 1 328755 361651 62127139 0

拿文件对一遍：328755 = 0x50433、361651 = 0x584B3、62127139 = 0x3B3FC23——正是 fw_dynamic.bin 的第 0 / 1 / 17 个字。尾字是 0：窗口 401456 字节比文件宽，文件之外补零——最后那个采样点就钉在补零口径上。

第二步：让芯片真的动起来。ROM 里换一份十行的回显固件（轮询 LSR 的 DR、读 RBR、轮询 THRE、写 THR，无限循环），宿主喂什么它回什么——这是"CPU 版回显对端"，与串口 IP 里那颗硬件替身同语义。实跑（RTL / verilator）：喂 3 个字节，413 拍全部原样回来：

$ prism run soc/soc.prism --run whitebow_soc_console --rtl --sim verilator （宿主出口 console=file:/tmp/soc/echo）
[run] whitebow_soc_console: RTL tb 跑完（until true at cycle 413） $ cat /tmp/soc/echo.tx abc

宿主怎么把字节变成引脚上的电平、8250 面为什么长那样——下一集。

这一片的边界

没有
MMU 翻译
satp 号在、值能存；翻译机构是第五日的事——在那之前这台机器一直跑物理地址。
没有
cache
取指与访存都直接打到存储器；dm_nc 这一位已经接进核里等着——第五日 cache 落地时它才有活干。
不是
可综合的 DDR
host 档只在仿真里成立；上板要换 BRAM / 外存控制器那一档，形状不变。
只有
单 hart
mhartid 恒 0，软中断这根线留给"未来的第二个 hart"。

小结

  • 一颗 SoC = 一个 design：核 + ROM + DDR + UART + CLINT + PLIC，再加一个不是零件的 MemoryMap。
  • 地址图只有一个拥有者：MemoryMap 收实例不收端口，译码、片选、读选择、不可缓存属性全在它体内——顶层只剩中断路由那几根线。
  • 地址只有一套口径：字节物理地址；取指口 / 数据口各自补零归一成 PA；命中是范围比较不是位选窗。
  • DDR 128MB 走 host 档：形状与片上存储器一致，本体在宿主内存里——代价是 RTL 通路必须 --sim verilator。
  • DDR 里是一张槽位表：每条窗口的终点就是下一条的起点；DTB 被栈踩过、initrd 挪过位——槽位是算出来的。
  • 判据两条都实跑过：image_check 四个字与固件文件逐字对得上（尾字是补零）；回显固件 413 拍把宿主喂的字节原样送回。
  • 换程序就只剩换镜像这一件事——--image 换的是数据，芯片一个字不动。
