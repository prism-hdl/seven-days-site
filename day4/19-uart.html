让芯片开口说话
uart8250：从一根线到一个字节

第 18 集里芯片已经能跑固件了——但你只能隔着一个 .tx 文件看它。这一集把线接出来：一颗 IP 三层——8N1 引擎（字节怎么变成线上的电平）、8250 寄存器面（让软件像开电脑串口一样用它）、一颗 composer 把两者连起来。接上宿主之后，OpenSBI 说的话就直接落在你的终端上。

一根线，一个字节：8N1

串口的全部协议就一句话：线空闲是高电平；要发一个字节，先拉低一拍宽的"起始位"打招呼，然后按最低位先出把 8 个数据位摆到线上，最后拉高一个"停止位"收尾。接收方看着起始位的下降沿起手，在每一位的中点采样——一帧 10 位：

段电平宽度
起始位01 位
数据位 0..7LSB 先出8 位
停止位11 位

"一位"有多宽由分频决定：DIVISOR = CLOCK_FREQ / BAUD_RATE，是个编译期整数常量。这台给 10 Mbaud：100 MHz ÷ 10 Mbaud = 10 拍一位、100 拍一帧。仿真里判据是字节内容不是时间——但可移位仍然要占拍，所以喂一个字节就是让机器实打实走 100 拍。

两端的名字先摆好：芯片侧是一颗 UartTx 加一颗 UartRx（两根引脚 tx_pin / rx_pin）；宿主侧是 Prism 的 uart_8n1 对端——它在仿真里扮演"另一块板子上的串口芯片"。

发：把字节摆成波形

发送器是一台四态小状态机：IDLE → START → DATA×8 → STOP → IDLE。每位的宽度由 baud_cnt 数到 DIVISOR 决定；计数只在 IDLE 归 1，帧与帧之间不留相位差。

prismsoc/ip/uart8250.prism · UartTx
    // 位内计到 DIVISOR 的下一拍换位；计数只在 IDLE 拍归 1，帧间不留相位差。
    fsm tx_ctrl {
        states : IDLE, START, DATA, STOP
        reset  : IDLE

        IDLE:  tx_en               -> START
        START: baud_cnt == DIVISOR -> DATA
        DATA:  baud_cnt == DIVISOR & bit_cnt == 7 -> STOP
        DATA:  baud_cnt == DIVISOR                -> DATA
        STOP:  baud_cnt == DIVISOR -> IDLE
    }

    tx_busy = tx_ctrl.is(IDLE) ? 0 : 1

    tx_pin = match {
        tx_ctrl.is(START) => 0,
        tx_ctrl.is(DATA)  => shift[0:0],
        _                 => 1,          // IDLE / STOP：空闲线就是停止位电平
    }

波形上一眼看明白（发 'A' = 0x41 = 0b01000001）：

$ prism run soc/ip/uart8250.prism --run uart_tx_check --debug （202 拍，摘关键拍）
cycle tx_tx_pin （tx_en / tx_busy 略） 0 0 ← 起手：起始位拉低 10 1 ← 数据位 0 = 1（0x41 的最低位） 20 0 ← 数据位 1 = 0 … 70 1 ← 数据位 6 = 1 80 0 ← 数据位 7 = 0 90 1 ← 停止位（空闲线就是停止位电平） 100 1 ← 回到 IDLE，tx_busy 落 101 0 ← 下一帧 'U' 的起始位（0x55）

判据是逐拍手算的 202 行：起始位占 0..9、数据位 k 占 10k..10k+9、停止位占 90..99——空档不留，每一拍都判。

收：在位的正中间看一眼

接收比发送难的地方全在"什么时候看"：起始沿可能在线上抖，位边界可能有偏差。这一颗的办法是——只在每一位的中点采样，而且中点已回高的"起始位"判为假起始，退回 IDLE 重新等沿：

prismsoc/ip/uart8250.prism · UartRx
    // 起始位中点仍为低才算真起始；中点已回高判为假起始，退回 IDLE 重新等沿。
    // 计数不在状态切换时清零，只在 IDLE 归 1——中点采样点因此严格相隔一位，
    // 8 个数据位的中点不会因换态而错位。
    fsm rx_ctrl {
        states : IDLE, START, DATA, STOP
        reset  : IDLE

        IDLE:  rx_pin == 0                        -> START
        START: baud_cnt == MIDPOINT & rx_pin == 1 -> IDLE
        START: baud_cnt == MIDPOINT               -> DATA
        DATA:  baud_cnt == MIDPOINT & bit_cnt == 7 -> STOP
        DATA:  baud_cnt == MIDPOINT                -> DATA
        STOP:  baud_cnt == MIDPOINT -> IDLE
    }

    on clock {
        baud_cnt' = rx_ctrl.is(IDLE) ? 1 : (baud_cnt == DIVISOR ? 1 : baud_cnt + 1)

        // 两个脉冲每拍先清零，采样命中时再拉高——保证恰好一拍宽
        valid' = 0
        error' = 0

        // 起始位中点确认：数据位序号从 0 起（假起始那条退回 IDLE，不在这里）
        if (rx_ctrl.is(START) & (baud_cnt == MIDPOINT) & (rx_pin == 0)) {
            bit_cnt' = 0
        }
        // 数据位中点采样：右移一位、新位插到最高位
        if (rx_ctrl.is(DATA) & (baud_cnt == MIDPOINT)) {
            shift'   = (shift >> 1) | (rx_pin << 7)
            bit_cnt' = bit_cnt + 1
        }
        // 停止位中点：收尾。停止位为高 = 正常帧，为低 = 帧错误
        if (rx_ctrl.is(STOP) & (baud_cnt == MIDPOINT)) {
            rdata' = shift
            valid' = rx_pin
            error' = rx_pin == 0 ? 1 : 0

两个容易忽略的细节：

  • 计数不在换态时清零，只在 IDLE 归 1——8 个数据位的中点因此严格相隔一位，不会因为换态错位。
  • 收尾两件事：停止位中点若为高，锁存字节并给一拍 rx_valid 脉冲；若为低，给一拍 rx_error（帧错误）。

实测表里两帧各摊一件事：第 95 拍收全 'A'（rx_valid=1）；第 195 拍第二帧停止位是低——rx_data 还是 0x55，但 rx_error=1，帧被判废。

$ prism run soc/ip/uart8250.prism --run uart_rx_check --debug （202 拍，摘关键拍）
cycle rx_rx_data rx_rx_valid rx_rx_error 95 65 1 0 ← 停止位中点：'A' 收全 195 85 0 1 ← 第二帧停止位为低：帧错误（0x55 判废）

8250 面：让软件像开电脑串口一样用它

引擎只有两根引脚，软件没法"摸"引脚。中间这层寄存器面把引擎包装成 8250 的样子——凡按 8250 驱动 console 的软件（OpenSBI 的 generic 平台、Linux 的 8250_of）都从这儿进：

prismsoc/ip/uart8250.prism · 三层装成一颗
composer Uart8250<CLOCK_FREQ: int, BAUD_RATE: int> {
    // ---- 总线侧（字内字节偏移 = 8250 寄存器号）----
    in  boff    : Signal<u3>
    in  wr_en   : Signal<u1>
    in  rd_en   : Signal<u1>
    in  wr_data : Signal<u64>
    out rd_data : Signal<u64>

    // ---- 引脚侧 ----
    out tx_pin  : Signal<u1>
    in  rx_pin  : Signal<u1>
    out interrupt : Signal<u1>      // 中断源线（有未读字节），供 PLIC 的某个 source

    regs : Uart8250Regs
    tx   : UartTx
    rx   : UartRx

    connect {
        boff          -> regs.boff
        wr_en         -> regs.wr_en
        rd_en         -> regs.rd_en
        wr_data       -> regs.wr_data
        regs.rd_data  -> rd_data
        regs.interrupt -> interrupt

        regs.tx_en    -> tx.tx_en
        regs.tx_data  -> tx.tx_data
        tx.tx_busy    -> regs.tx_busy
        rx.rx_data    -> regs.rx_data
        rx.rx_valid   -> regs.rx_valid
        rx.rx_error   -> regs.rx_error

        tx.tx_pin     -> tx_pin
        rx_pin        -> rx.rx_pin
    }
}

// =============================================================================

面的形状：总线是 64 位字寻址，寄存器号 = 8 字节字内的字节偏移（0..7）——正好就是 8250 的寄存器编号。核的 lbu/sb 按地址低 3 位取/放车道，所以面的字节必须落在 boff 车道上：

号读写这一面里是什么
0RBRTHR收：读走即消费；发：写进发送架（DLAB=1 时是 DLL）
1IERIER[3:0] = RDI / THRI / RLSI / MSI（DLAB=1 时是 DLM）
2IIRFCRIIR：档位 + 当前中断；FCR：FIFO 使能 / 触发级别 / 复位
3LCRLCR整字节存，[7] = DLAB
4MCRMCR[4:0] = DTR RTS OUT1 OUT2 LOOP
5LSR—DR(0) OE(1) FE(3) THRE(5) TEMT(6)
6MSR—[7:4] 输入、[3:0] 变化位（读一次清）
7SCRSCR纯回读的判别寄存器

面级验收台把引脚侧交给 stim 直接驱动（不拉真引擎，两层分开判）。读 LSR 那几拍，读回值落在 boff=5 车道（bit 40 起）：0x61 = DR|THRE|TEMT（有字节可读、发送架空、移位器也空）、0x21 = DR|THRE。写 THR（boff=0）那一拍，tx_en 当场拉起、tx_data 就是那个字节——面上的一次写，引擎那一侧就是"起一帧"。

两个 16 深的架子

真实的 16550A 在收/发两侧各有一个 16 字节 FIFO，这不是"顺手加的"——是消费者逼出来的（下一节说谁逼的）。面上的两个架长得一样：环形缓冲 + 读写指针 + 计数，推入在写 THR / 收帧完成那一拍，弹出在引擎空闲 / 读 RBR 那一拍：

prismsoc/ip/uart8250.prism · 两个架
    // 新字节优先：收到即算未读，读走那次消费让位给新字节
    on clock {
        // 推入：一帧收完就进架；架满（FIFO 关＝只有 1 格）则丢帧并置 OE——宿主背靠背喂
        // 字节时"同一位置丢一个"就是从这儿出去的。
        if (rx_valid & !rx_full) {
            rxq'[rx_wp] = rx_data
            rx_wp' = rx_wp + 1
            rx_n' = rx_n + 1
        }
        if (rx_valid & rx_full) {
            oe' = 1                 // 丢弃那一帧，只留一个 sticky 的 OE
        }
        // 弹出：读 RBR 消费架上第一个（读口给的是弹之前的值，见 rbr_b）
        if (rd_en & (boff == 0) & !dlab & (rx_n != 0)) {
            rx_rp' = rx_rp + 1
            rx_n' = rx_n - 1
        }
        // FCR[1]（RCVR FIFO 复位）：整架清空、指针归零
        if (wr_en & (boff == 2) & w_b[1]) {
            rx_n'  = 0
            rx_wp' = 0
            rx_rp' = 0
        }
        // 发送架推入：写 THR 且架未满就进架（FCR[0]=0 时深度 1；满了静默丢）
        if (tx_push) {
            txq'[tx_wp] = wr_data[7:0]
            tx_wp' = tx_wp + 1
        }
        // 发送架弹出：引擎空闲就从架头弹一个（tx_en/tx_data 就是这条弹出的组合出口）
        if (tx_pop) {
            tx_rp' = tx_rp + 1
        }
        // 同拍推弹（写 THR 恰好撞上取下一帧）计数净零：两条都不命中，tx_n 保持
        if (tx_push & !tx_pop) { tx_n' = tx_n + 1 }
        if (tx_pop & !tx_push) { tx_n' = tx_n - 1 }
  • THRE / TEMT 是 FIFO 口径：THRE = 架空（可以再来一笔），TEMT = 架空且移位器也空（整帧真的上过线了）。一次 LSR 判断连写十几笔的驱动，由架吸收——上一版"THRE = 引擎不忙"的单缓冲口径会让突发写隔一丢一。
  • 架满就丢，收侧留痕：收侧满架还来帧，丢那一帧并置 sticky 的 OE（读 LSR 清）；发侧满架只静默丢——TX 没有溢出位，这是 16550A 的口径。
  • FCR[1] / FCR[2] 复位：收侧整架清空、指针归零；发侧清架，但移位器里那一位正在线上传，撤不掉。

收侧还长了一路 16550A 的字符超时（IIR 0x0C）：架非空、且 4 个字符时间没有新活动（收/读/FCR 复位都算活动），就挂起一次 RDI 类中断。为什么非要它？内核（和多数 16550 驱动）会把 FCR 触发级别压到 8 字节——键盘敲几个字符永远够不到那条线，没有超时这一路，输入就永远进不了内核。实测（uart_to_check，先写 IER 开 RDI、FCR=0x81 开 FIFO）：收下 'A' 后 40 余拍，读 IIR 从 0xC1（无中断）变成 0xCC——0x0C 就是字符超时；读一次 IIR 又回到 0xC1。

消费者的账：面长到多大，由谁用决定

这一面里每一件看起来"多余"的东西，背后都有一笔具体的账：

① Linux 的 autoconfig() 三道判据（8250_port.c）——一道都糊不过去，少一道端口就是 PORT_UNKNOWN，console=ttyS0 注册不上，用户态开 /dev/console 得 ENODEV：

判据它做什么这台怎么答
IER 存在性写 0 读回必须 0；写 0x0F 读回必须 0x0FIER[3:0] 真存储，[7:4] 恒读 0
回环写 MCR=0x1A（LOOP|OUT2|RTS）后读 MSR，&0xF0 必须 = 0x90回环把 MCR 的四路输出按 16550A 的对法接进 MSR 输入
档位FCR 使能 FIFO 后读 IIR，&0xC0 必须 = 0xC0IIR bit[7:6] 由 fifo 位派生

② THRE 必须上中断线——内核 printk 走轮询没问题，但用户态 write(/dev/console) 走 tty 层：驱动把前 16 字节塞进 TX FIFO 就等 THRE 中断接力排尾巴。线里没有 THRE 这一路，write() 的尾部永远排不出去，进程就此卡住——实测里 mount 打一行错就能把 PID 1 挂住，要靠用户敲一个字符的 RX 中断让 ISR 顺带排水才解开。400 秒的静默就是这么来的。

prismsoc/ip/uart8250.prism · 中断线（节选）
    // IIR：档位两位 + 当前中断 ID。裁决顺序 RLSI > RDI > THRI > MSI 与 16550A 同；
    // 四位全不中就是"无挂起"（bit0=1）。MSI 的 ID 是 0，靠"有变化位"才算挂起。
    // 触发级别：FCR[7:6] 选 1/4/8/14；FIFO 关着＝有一个就报
    wire trig_n : u5 = fifo ? (trig == 0 ? 1 : trig == 1 ? 4 : trig == 2 ? 8 : 14) : 1
    wire iir_rls : u1 = r_ier[2] & err
    wire iir_rd  : u1 = r_ier[0] & (rx_n >= trig_n)
    wire iir_to  : u1 = r_ier[0] & rx_to          // 字符超时与 RDI 共用 IER[0]（16550A 同）
    wire iir_th  : u1 = r_ier[1] & thre     // THR 空（FIFO 口径）——与 16550A 的 THRE 中断同源
    wire iir_ms  : u1 = r_ier[3] & (msr_chg != 0)
    wire iir_id  : u64 = iir_rls ? 0x06 : iir_rd ? 0x04 : iir_to ? 0x0C : iir_th ? 0x02 : iir_ms ? 0x00 : 0x01
    wire iir_b   : u64 = (fifo ? 0xC0 : 0) | iir_id
    // THRE 必须上中断线：内核 printk 走轮询，但【用户态 write(/dev/console)】走 tty 层——
    // 驱动把前 16 字节塞进 TX FIFO 后就等 THRE 中断接力排尾巴。线里没有 iir_th，write()
    // 的尾部永远排不出去，忙实进程就此卡住（mount 打一行错都能把 PID 1 挂住；要靠用户
    // 敲一个字符的 RX 中断让 ISR 顺带排水才解开——实测 400 秒静默就是这么来的）。
    interrupt = iir_rls | iir_rd | iir_to | iir_th | iir_ms

③ 16 深度是实测出来的数：宿主背靠背连喂 26 字节（一帧 100 拍、与发侧同速），没有 16 深接收 FIFO 时架会被后来的帧覆盖——实测丢的是下标 16 那个字节；补上 FIFO 后 .tx 必须逐字等于喂进去的内容（--run soc_rx_burst 就是这条判据）。

④ 没建模的也写明白：DLL/DLM 存了只回读、不参与定时（分频只在例化点给一次，两侧写不出不同波特率）；非回环期 MSR[7:4] 恒给 DCD|DSR|CTS（"对端常在线"）；FCR[2] 撤不掉正在线上传的那一位。

接上宿主：让终端真的说话

最后一步是把两根引脚接到仿真宿主上——run 块里一行 host 绑定：

prismsoc/ip/uart8250.prism · 回显验收台
run uart_console_check of UartEchoTop {
    clock : 100 MHz
    host  : {
        console = uart_8n1(tx = tx.tx_pin, rx = rx.rx_pin, divisor = 10)
    }
    until : console.tx.count >= 3
    show  : { console.rx.count, console.rx.last, console.tx.count, console.tx.last }
}

// =============================================================================
// run uart_tx_check —— TX 串行波形逐拍判（期望按 8N1 时序手算，不从实现转录）
//   连发两帧：0x41('A') 与 0x55。tx_en 是单拍脉冲，落在第 0 与第 101 拍
//   （第 100 拍已回 IDLE，起手要等下一拍）。
//   帧自起手拍 r 起算：起始位占 r..r+9，数据位 k 占 r+10k..r+10k+9（LSB 先出），
//   停止位占 r+90..r+99，第 r+100 拍回 IDLE。期望列每拍都判，空档不留。
// =============================================================================

对端三种用法：console=file:<前缀>（非交互：字节写进 .rx、出口落在 .tx）、stdio（真人在终端里敲）、pty（挂个伪终端给别的程序）。.tx 启动即清空、每解出一字节立刻落盘——百万拍长跑里，它是唯一的实时进度。

实跑（golden 直跑）：宿主喂 xyz 三个字节，回显对端原样送回来，395 拍收工：

$ prism run soc/ip/uart8250.prism --run uart_console_check （--host console=file:/tmp/uart/echo）
[run] uart_console_check: golden 直跑完成（until true at cycle 395） $ cat /tmp/uart/echo.tx xyz

第 18 集里那颗整机版的回显固件（CPU 轮询 MMIO）与这里这颗硬件替身同语义——一个是"固件学着像串口芯片"，一个是"串口芯片自己"。真到跑 OpenSBI 的时候，两者换着当下游对端都行。

小结

  • 一颗 IP 三层：UartTx / UartRx（8N1 引擎，分频是编译期常量、RX 在位中点采样）+ Uart8250Regs（寄存器面）+ composer Uart8250（连起来，只露总线侧与两根引脚）。
  • 面的寄存器号 = 字内字节偏移（64 位字 ⇒ 步长 8），核的 lbu/sb 按地址低 3 位取放车道——两层之间只有"车道"这一个约定。
  • 两个 16 深 FIFO + 字符超时 + THRE 中断线——每一件都是被真实消费者逼出来的，不是"照着 16550A 抄全"。
  • Linux autoconfig() 三道判据（IER 存在性 / 回环 / 档位）全过，ttyS0 才注册得上；少一道，用户态连 /dev/console 都开不出来。
  • 接宿主三种对端（file / stdio / pty）；.tx 每字节立落盘——长跑的实时进度。
  • 判据两处实跑：帧波形逐拍判（202 拍全等）、回显 3 字节 395 拍原样往返。
