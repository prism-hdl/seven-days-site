    跑一段真程序
    冒泡排序

    第九集那颗 cpu_top 一行都不改——只把另一份镜像灌进去，让它把六个数排好，再让它自己验一遍。

    "有晚上，有早晨，是第二日。" —— 《创世记》 1:8
    ← 第 9 集 · 一具身体 第二日完 · 下一日 · 旱地与植物 →

    这一集不写新的芯片

    前九集造完的这颗单周期核，取指、译码、算绪、访存、写回都会做了，但它只跑过一件事：从 5 加到 1。这一集给它一段有结果的活儿——把 9, 7, 5, 3, 2, 1 排成升序。

    做法只有一行：在 cpu.prism 里再加一个 run 块。design 不动、器官不动、@schedule 不动。镜像是测试台事实——

    第九集
    cpu_check
    六条指令的累加循环，27 拍
    本集
    bubble_sort
    32 条指令的排序 + 自检，417 拍
    同一颗
    cpu_top
    换的是镜像，不是芯片

    那段程序

    冒泡排序不用乘除法：扫一遍相邻两格，逆序就换；有一趟一个都没换，就说明排好了。地址乘法用 slli（j*8——dm 一个字 8 字节），比较用 slt，跳转用 beq / bne / blt，取数放数用 ld / sd。全是第九集已经接通的路。

    机器码不是手算的：先写 .s 交给 llvm-mc 汇编，再用 llvm-objdump 反着打一遍，地址与编码对上才抄进镜像表——第三方汇编器做裁判，Prism 这边只负责跑它。

    三处值得停：

    • 只用 ld / sd。这台机器的 dm 一颗就是一个 64 位字，排序里搬的也就是一个字——不碰字访问、半字访问那条没建的路。
    • 地址靠移位。slli x28, x7, 3 把下标 j 变成字节地址。没有乘法器，也不该为了一个下标去要一个乘法器。
    • 末尾那八条是自检。排完之后再从头比一遍相邻两格，发现任何一次逆序就掉进 124 那格自跳——x20 永远不置起。置起 x20 的那条指令，是这段程序里唯一能被称为"报告"的东西。

    镜像写在测试台上

    程序与数组都进 run 块的 image 段：一个窗口给 im（指令），一个给 dm（数据）。[0:] 那个窗口只写起点，长度由值侧量出来——32 个字 × 4 字节 = 128 字节，六个 64 位数据字 = 48 字节。

    run bubble_sort of cpu_top { image : { prog : im[0:] = [ 0x00600293, // 0: addi x5, x0, 6 n = 6 0x00000313, // 4: addi x6, x0, 0 swapped = 0 0x00000393, // 8: addi x7, x0, 0 j = 0 0x00339e13, // 12: slli x28, x7, 3 &a[j] = j*8 0x00138e93, // 16: addi x29, x7, 1 j + 1 0x003e9f13, // 20: slli x30, x29, 3 &a[j+1] 0x000e3503, // 24: ld x10, 0(x28) a[j] 0x000f3583, // 28: ld x11, 0(x30) a[j+1] 0x00a5a633, // 32: slt x12, x11, x10 a[j+1] 比 a[j] 小？ 0x00060863, // 36: beq x12, x0, 16 没逆序 → 跳到 52 0x00be3023, // 40: sd x11, 0(x28) 换：小的进来 0x00af3023, // 44: sd x10, 0(x30) 换：大的出去 0x00130313, // 48: addi x6, x6, 1 swapped++ 0x00138393, // 52: addi x7, x7, 1 j++ 0xfff28693, // 56: addi x13, x5, -1 n - 1 0xfcd3c8e3, // 60: blt x7, x13, -52 j < n-1 → 回 12 0xfc0312e3, // 64: bne x6, x0, -60 这趟换过 → 回 4 再扫 0x00000393, // 68: addi x7, x0, 0 自检：j = 0 0xfff28693, // 72: addi x13, x5, -1 n - 1 0x00339e13, // 76: slli x28, x7, 3 &a[j] 0x00138e93, // 80: addi x29, x7, 1 j + 1 0x003e9f13, // 84: slli x30, x29, 3 &a[j+1] 0x000e3503, // 88: ld x10, 0(x28) a[j] 0x000f3583, // 92: ld x11, 0(x30) a[j+1] 0x00a5a633, // 96: slt x12, x11, x10 还有逆序？ 0x00061c63, // 100: bne x12, x0, 24 有 → 掉进 124 那格自跳，永不通 0x00138393, // 104: addi x7, x7, 1 j++ 0xfff28693, // 108: addi x13, x5, -1 n - 1 0xfcd3cee3, // 112: blt x7, x13, -36 六对没比完 → 回 76 0x00100a13, // 116: addi x20, x0, 1 完工标志：直到这里才置 1 0x0000006f, // 120: jal x0, 0 停机（自跳） 0x0000006f // 124: jal x0, 0 fail：自检没过就永远停在这 ] } until : x20 == 1 show : { pcv, x20, dm0, dm1, dm2, dm3, dm4, dm5 } }

    两句口径要记：偏移与字节数的单位是字节，零点是这块 mem 的起点；别名（prog / data）是命令行换镜像的把手——--image prog=<文件> 只换文件，落点与窗口仍是源码里的事实。

    几处值得看：

    • 拍 0 就已经是 9 7 5 3 2 1。装载发生在复位释放之后、第一个被采样的拍之前——第一拍看到的是灌完的数组。
    • 一次换位改两格，分两拍看见。拍 10 低格从 9 变 7、拍 11 高格才从 7 变 9；中间那一拍的数组是 7 7 5 …——两个 sd 之间本来就有一个半完成态，这不是 bug，是这两条指令本来就要分开落两个边沿。
    • 最后一次变化在拍 265（1 顶到最前），可判据要到拍 416 才成立。中间那一百多拍是"再扫一趟确认没换 + 六对自检"。排完比验完早，这中间的差就是判据的价值。

    这条判据会不会骗你

    把 32 那条比较的两个源操作数对调——slt x12, x11, x10（a[j+1] 比 a[j] 小？）写成 slt x12, x10, x11（编码 0x00b52633，同样由 llvm-mc 核对）。程序照常跑，数组照常动，x20 却再也不会置起：

    ▸ 注入后的输出
    [run] ❌ [run bubble_sort] until 判据在 10000 拍内从不成立——停机不可达 （报错退出而非无限跑；要有界看一眼就加 --time <时长>）

    判据要能失败才算判据。这里它失败的方式很干净：机器不停下来，工具就不替你假装跑完了。

    自检那八条的作用也不在"让排序更对"——带 swapped 标志的冒泡本身已经能排好；它的作用是让判据独立于排序过程：用同一批 ld / slt 从头部再比一遍，判的是结果，不是过程自称完成。报告的资格，来自它检查的东西不是它自己。

    一条腿要交代清楚：这一集的 run 用了 until 引用 expose 出来的 x20，TLM 后端目前在这条路上还生成不出合法代码（error: no member named 'read' in 'V4'）。所以这一段撞的是 golden 与 RTL 两条腿，SystemC 那条腿等后端补上再撞。

    小结

    • 同一颗 cpu_top，第二个 run 块换一份镜像——换程序不动芯片。
    • 只用这台已有的能力：双字访存、移位算地址、slt 比较、三条分支。没有为排序加一根线。
    • 417 拍把 9 7 5 3 2 1 排成 1 2 3 5 7 9，golden 与 RTL 逐拍逐列全等。
    • 停机判据是程序自己写出的完工位 x20；注入一发反向比较，它就从不成立——判据能失败，才算它在看。

    第二日到这一集收束。这台机器已经会做事了——它接下来要学的不是更多电路，是更快的节拍与会疼。
