ALU

pc 负责步进、记忆负责存储——但运算还缺一环。这一集造四颗里唯一没有时钟的器官：一段纯函数，给两个数和一条选路信号，立刻出结果。

四颗里唯一没有时钟的

第一集那颗加法器——sum = a + b，三个端口、一句数据流——在这一集被改造成 ALU：同一段组合逻辑，扩展出 op 选路与十条路。

回头看已经造好的两颗：pc 有 reg + on clock，regfile 有 mem + on clock。ALU 什么都没有——它是一段纯函数：给两个数和一条选路信号，立刻出结果，没有跨拍状态。

pc
有时钟
有跨拍状态（当前地址）
regfile / ram
有时钟
有跨拍状态（存的值）
ALU
无时钟
输入变，输出立刻变——没有"上一拍"

这不是省略。组合逻辑是硬件的"计算"本体：它不占节拍、不需要复位、没有初值。凡是能组合做完的事，就不该拖到下一拍。

十条路，一张表

prismalu.prism
module ALU {
    in  a      : Signal<i64>    // 操作数 1
    in  b      : Signal<i64>    // 操作数 2（调用方已做好移位量掩码）
    in  op     : Signal<u4>     // 运算选择 0..9
    out result : Signal<i64>

    result = match op {
        0 => a + b,              // ADD
        1 => a - b,              // SUB
        2 => a & b,              // AND
        3 => a | b,              // OR
        4 => a ^ b,              // XOR
        5 => a << b,             // SLL（逻辑左移，b 已掩码）
        6 => a >> b,             // SRA（算术右移，保号）
        7 => a < b,              // SLT（有符号比较）
        8 => i64(u(a) >> b),     // SRL：换无符号视角移，补 0
        9 => u(a) < u(b),        // SLTU（无符号比较）
        _ => 0,                  // 防御：op 越界给 0
    }
}

十条路，十个表达式。这条 match 编译下去就是十个并列的运算单元 + 一个多路选择器——写起来是表，综合出来是电路。

两处值得停下来看的地方
  • 第 6 条与第 8 条的区别：同一个 >>，操作数是有符号时就算术右移（补符号位），u(a) 换成无符号视角就逻辑右移（补 0）。-2 >> 33 = -1，u(-2) >> 33 = 2147483647——同一对输入，两种语义，全靠 op 选。
  • 第 8 条外面那层 i64(...)：无符号移完如果不换回有符号视角，整条 match 的类型会被带成无符号，第 6 条（算术右移）跟着变形。类型是跟着整个表达式走的，不是逐行看的。

还有一条：移位量不由 ALU 自己掩码。b 传进来之前，调用方已经取好低 6 位（0..63）。这件事归调用方，不是因为 ALU 宽度未知，而是因为"移量该读指令的哪几个位、超过 63 怎么办"属于这条指令的字段怎么解释——那是译码层的事实，塞进 ALU 就等于让运算单元去替译码做决定。

第 6、7 两行放在一起看：同样的 a=-2, b=33，只换了 op，结果从 -1 变成 2147483647。这不是"算错了"，这是两种不同的右移。符号性不是装饰，它决定电路怎么接。第 8 行则只有 64 位通路才给得出来：1 << 40 在 32 位机器上会把 40 当成 8（移量只有 5 位），这里 6 位移量原样生效。

ALU 不管的那些事

一颗模块的边界，往往比它的内容更能说明设计取向。ALU 有四件事刻意不管：

  • 它不掩移位量。b 传进来之前，调用方已经取好低 6 位。"移量读指令的哪几个位"是译码层的事实，不是运算层的事实。
  • 它不管 32 位域运算。RISC-V 的 W 型指令（addw / subw / sllw / srlw / sraw）走的还是上面这十条路——同一条加法、同一条移位，只是结果要截到 32 位再符号扩展回 64。这一手不加长 ALU 的表：32 位语义是这条指令的属性，不是这个运算的属性。于是 Decoder 多报一根 is_w_op，顶层拿到结果后按它做一次符号扩展——第九集组装顶层时那根线就在那里。
  • 它不产生标志位。没有 zero flag、carry flag、overflow flag。RISC-V 与 x86 在这里分道扬镳：x86 的 cmp 去写 EFLAGS，之后的分支读那一堆状态位；RISC-V 的 slt / beq 直接比两个寄存器——比较的结果要么落进一个寄存器，要么当场决定跳不跳，不在 CPU 里挂一个"全局状态寄存器"。这是精简指令集最典型的一刀。
  • 它不做多周期的事。除法要试商、要移位、要重复好几拍——那是另一颗模块的职责。ALU 保持纯组合，谁都能在任何一拍把它插进数据通路，不用担心"它正忙"。

最后一条的代价是：CPU 里要有一颗额外的多周期单元，以及一套"什么时候可以来取结果"的握手。那是第三日（第 14 集）的话题——流水线的停顿都有了，才谈得上容纳"停几拍"。

小结

  • ALU 是纯组合：没有时钟、没有状态、输入变输出立刻变。
  • 十条路写成一张 match 表——写起来是表，综合出来是十个并列运算 + 一个多路选择器。
  • 右移的两种语义（算术 / 逻辑）由符号性决定；i64(...) / u(...) 是显式的位模式重解释。
  • 移位量的掩码归调用方——那是"指令字段怎么读"的事，不属于运算。
  • W 型指令不加长这张表：Decoder 报一根 is_w_op，顶层按它把结果符号扩展回 64 位。
  • 算不完的事（除法）不塞进来：ALU 保持纯组合，多周期单元日后另立一件。
"事就这样成了。" —— 《创世记》 1:7
