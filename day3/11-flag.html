        从玩具到能跑 Linux

        第二日那颗核排过序、三条通路逐拍对撞过——它是真的。这一集不写一行新硬件，只做一件事：把它离"能跑 Linux"还差的东西一条条量出来，量不出来的那条就不许写进靶子。

        差距清单要能指到代码

        "造一颗能跑 Linux 的处理器"这句话本身没有价值——它太容易说，也太容易不兑现。要让它变成一件做得完的事，得先回答两个问题：差在哪，以及凭什么说差在这里。

        第二日那颗核的全部家当都在 examples/day2/cpu.prism 里：186 行，其中 design cpu_top 104 行。差距不需要想象，读它就行。这一集读出来的有五条：

        差距代码里的事实它挡在哪
        一拍做完所有事四颗部件各自的 @schedule 都写着 pipeline : 1 stage + latency : 1 cycle，而顶层 cpu.prism 里 on clock 出现 0 次——六段组合被同一拍串完那条组合路径的长度就是周期的下限——频率被它钉死，不是被"指令条数"钉死
        存储 1KB / 2KBim : ram<SIZE=256, W=u32, A=u8>、dm : ram<SIZE=256, W=i64, A=u8>装不下固件，更装不下内核。8 位地址是电路事实，改一行链接脚本没用
        只有 M 态没有 CSR，没有陷阱通路；顶层注释直写"这一台不做错误处理"特权级与异常是操作系统的入场券：交不进棒，也接不住 fault
        没有中断核端口里没有一根线留给 timer 或外部设备只能轮询。真实驱动、真实控制台都不接受轮询
        访存只有双字许可表里 0x03 => funct3 == 3、0x23 => funct3 == 3字节与半字是字符串、结构体、MMIO 的日常——固件第一件事就是读字节

        后四条都能直接数出来。第一条不行——"一拍做完所有事"到底有多重，得量。

        量之前：先把它变成门

        组合深度是门级的事，Prism 源码里没有门。所以第一步是走一遍已经在第一日讲完的路：gen-rtl 出 SystemVerilog，再交给 yosys。

        bashgen-rtl
        prism gen-rtl examples/day2/cpu.prism -o /tmp/day3/cpu.sv
grep '^module' /tmp/day3/cpu.sv
        $ grep '^module' /tmp/day3/cpu.sv
        module pc_rtl #( module regfile_rtl #( module alu_rtl #( module ram__im__rtl #( module ram__dm__rtl #( module decoder_rtl #( module cpu_top_top (

        546 行，七颗 module：六颗实例各自成一颗，顶层叫 cpu_top_top（yosys 的 hierarchy -top 要的是这个带 _top 的名字）。第二日讲"一颗 module 一只盒子"时说过：design 会展平成连线——现在连线也是门级素材了。

        两把会说谎的尺

        yosys 里量组合深度最顺手的是 ltp（最长拓扑路径）。它数的是路径上串了多少个单元。先拿它量整颗核：

        $ yosys -p "read_verilog -sv -formal cpu.sv; hierarchy -top cpu_top_top; proc; flatten; opt; techmap; opt; ltp -noff"
        Longest topological path in cpu_top_top (length=11): 0: \pc.pc [31] 1: $techmap$add$cpu.sv:525$357…replace_alu$93060.lcu.$and$…_Y … 11: $techmap$add$cpu.sv:528$360…replace_alu$93128.Y [63] ff: \pc.pc [63]

        11。一颗单周期 CPU 最长的那条路只有 11 级？可它自己肚子里那颗 ALU 单独量就有 33 级（下一节）。一把尺量出的数比被量对象的某个零件还小，那这把尺一定没在量你以为它在量的东西。看它给的路径就明白了：起点是 pc.pc 边上一根组合线，终点是 pc 那个触发器——它量到的只是 pc 自己那个加法器。

        原因写在 ltp 的帮助里：-noff 会排除触发器单元。于是路径不能从寄存器输出起步——而这一颗核里每一条真正要紧的路，起点都是寄存器。-noff 本意是"别把触发器本身算进深度"，实际效果是"把所有寄存器出发的路都掐了"。

        那就去掉 -noff 再量一次：

        $ …; techmap; opt; ltp （不带 -noff）
        Longest topological path in cpu_top_top (length=234): 0: \clk … 231: \pc.pc [62] (via $auto$ff.cc:337:slice$93321) 232: $techmap$add$cpu.sv:528$360…CO [62] … 234: \pc.pc [63] (via $auto$ff.cc:337:slice$93322)

        234，一个更像样的数——但看起点：\clk，而且第 231 步就穿过了一个触发器（pc.pc[62]）。它量的是"从时钟一路 walk 到下一拍"的路，跨了拍，不是拍内的组合深度。这个数字对频率没有任何意义。

        两把尺各自的死法

        带 -noff：11，比零件还小——因为它拒绝从寄存器输出起步。不带 -noff：234，从 clk 起、穿过触发器——因为它什么都肯走。一把"什么都能量出一个数"的尺，等于没量。判据得能失败：先问"什么情况下这个数会明显不对"，答不上来就别用它。这一集的答案是——分段量。

        分段量：一颗一颗来

        单周期这一拍里串起来的，恰好就是第二日一颗一颗造出来的那几颗盒子。它们各自是纯组合或近组合的（alu_rtl、decoder_rtl 里那个 always_ff 是空的），所以单独量它们时 ltp -noff 没有寄存器可掐——尺子又灵了。

        shexamples/day3/depth.sh · 量的那一段
        depth() {
  mod=$1; tm=$2
  p="proc; opt; ltp -noff"
  [ "$tm" = 1 ] && p="proc; opt; techmap; opt; ltp -noff"
  script="read_verilog -sv -formal $OUT/cpu.sv; hierarchy -top $mod; $p"
  yosys -l "$OUT/$mod.log" -p "$script" >/dev/null 2>&1
  grep -oE 'length=[0-9]+' "$OUT/$mod.log" | tail -1 | cut -d= -f2
}

printf '%-16s %-12s %-12s\n' 部件 不techmap techmap后
for m in pc_rtl regfile_rtl alu_rtl decoder_rtl ram__im__rtl ram__dm__rtl; do
  printf '%-16s %-12s %-12s\n' "$m" "$(depth "$m" 0)" "$(depth "$m" 1)"
done
        $ sh examples/day3/depth.sh
        RTL: /tmp/day3-depth/cpu.sv 546 行 部件 不techmap techmap后 pc_rtl 2 12 regfile_rtl 4 13 alu_rtl 11 33 decoder_rtl 18 21 ram__im__rtl 3 16 ram__dm__rtl 3 16 全核 ltp -noff : 11 ← 不承重：比 ALU 一段还短 全核 ltp（不带） : 234 ← 不承重：路径从 clk 起、穿过触发器

        两列都要看。不 techmap 那一列是骗小孩的：$add、$mul 这类粗粒度单元在图里就是一个点，于是 pc 的加法器是 2 级、256 选 1 的读阵列是 3 级——恰好把最该量的算术整段看不见。techmap 把加法器摊成进位链、把读阵列摊成 mux 树之后，pc 从 2 变 12，两颗 RAM 的读从 3 变 16。

        还有一句必须说清楚：单位是门级单元的个数，不是纳秒。本机没有 liberty 工艺库，报不出 GHz——门级深度只是频率的代理指标。它能比大小，不能换算成兆赫。

        把它串起来：111 与 34

        有了分段实测，"一拍做完所有事"第一次变成了一个数。按 cpu.prism 里的连线顺序，这一拍要走的是：

        把六段按连线顺序加起来：12 + 16 + 21 + 13 + 33 + 16 = 111 级。这是下界——顶层还有三处 mux 没算进去（分支借道 ALU 的 alu_f、W 型的 is_w_op ? ex_ext :、写回选择），它们只加不减。

        切成五级之后，每一段各自承担其中一段：IF ≈ 28、ID ≈ 34、EX ≈ 33、MEM ≈ 16、WB 个位数，最长的一段是 34。111 → 34：这就是"节拍换频率"的全部算术。

        它不承诺什么，也要说清楚：它不保证 Fmax 提升 3.3 倍——真实数字要综合进具体工艺库才知道，本机没有那个库。它保证的是一件更硬的事：这一拍的组合深度不再是六件事的和。谁想验证，跑一遍 depth.sh 就能拿到同一张表。

        便宜不是白拿的

        下五刀，就要多出四组段寄存器（IF/ID、ID/EX、EX/MEM、MEM/WB），还要处理"上一条还没写回、下一条就要读"这件事——前递、停顿、冲刷。第 12 集摆段寄存器，第 13 集对付冒险。流水线的吞吐是借来的，利息写在冒险那一集。

        另外四条差距：逐条点名

        这四条不用量，读源码就行。第一条：存储与地址。

        prismexamples/day2/cpu.prism · 六颗实例与取指口
        design cpu_top {
    // ==== 六颗实例 ====
    pc  : pc
    rf  : regfile
    ex  : alu
    im  : ram<SIZE = 256, W = u32, A = u8>    // 指令侧：32 位字，1KB
    dm  : ram<SIZE = 256, W = i64, A = u8>    // 数据侧：64 位字，2KB
    ctl : decoder

    // ==== 取指：pc → im（异步读，同拍出指令）====
    wire iaddr : u8 = pc.addr[9:2] -> im.addr      // 字节地址 → 字地址
    wire instr : u32 = im.rdata -> ctl.instr

        pc.addr 是 64 位的，可这颗核看得见的指令只有 addr[9:2] 那 8 位——256 个字，1KB。数据侧同理，2KB。第二日第 10 集那份 80 字节的 .text 能跑，是因为它小；OpenSBI 的 .text 是几百 KB 量级，装不进来不是"再等等"，是这颗芯片没有那块地。

        第二条：访存宽度。第 8 集那张许可表里，访存只占两行：

        prismexamples/day2/decoder.prism · 许可表里访存那两行
                0x33 => r_f7_ok,
        0x3b => r_f7_ok & (funct3 in [0, 1, 5]),
        0x13 => (funct3 in [0, 2, 3, 4, 6, 7]) | ((funct3 in [1, 5]) & sh_ok),
        0x1b => (funct3 == 0) | ((funct3 in [1, 5]) & sh_ok),
        0x03 => funct3 == 3,               // LD（这一颗 dm 就是 64 位字）
        0x23 => funct3 == 3,               // SD
        0x63 => funct3 in [0, 1, 4, 5, 6, 7],
        0x67 => funct3 == 0,

        funct3 == 3 一条判据把 lw / lh / lb 全挡在门外——不是忘了写，是那一颗 dm 一个元素就是 64 位，多出来的路没有对应电路。固件启动第一件事是逐字节拷字符串，这一步在这颗核上没有指令可发。

        第三条与第四条：特权与中断。顶层自己把话说死了：

        prismexamples/day2/cpu.prism · 这一台不做错误处理
            // ==== 这一台不做错误处理 ====
    // decoder 会举手报 is_illegal，但顶层不拿它当门：先让程序跑通，非法编码照样
    // 读、照样写回。把"不懂"变成一次异常跳转是第三日 CSR 与陷阱那一集的事。
    connect ctl.reg_wen -> rf.wen
    connect ctl.mem_wen -> dm.wen

        非法编码照样读、照样写回，机器不停——因为没有地方可以去：mtvec 没有、mcause 没有、陷阱通路没有。中断同理：核的端口表里一根 mtip / msip / meip 都没有，连"谁想打断我"这个问题都无处安放。

        靶子：这一日要交出什么

        五条差距翻过来，就是五件要造的东西。每一件都对应上面一条量得出或读得出的差距，没有一件是"顺手多做的"。

        对 111 级那一拍
        五级流水线
        pipe/ 五颗 composer + 四组段寄存器；把最长一段压到 34 级。第 12 集。
        对流水的代价
        冒险处置
        前递、停顿、冲刷、多拍单元。第 13 集。
        对"没有地方可以去"
        CSR 与特权级
        白名单号表、mstatus 的 WARL、trap 与 mret、中断采样。第 14 集。
        对"没有那块地"
        存储与地址图
        1KB / 2KB 换成 DDR 量级，地址从 8 位长成物理地址。第 17 集。
        对"没有指令可发"
        完整访存宽度与指令面
        字节 / 半字 / 双字，加上 M · A · C · F。第 16 集与第 19 集。
        白虹（Whitebow）

        这颗核从这一日起有一个正式的名字：白虹，英文 Whitebow。典出《战国策·魏策》"聂政刺韩傀，白虹贯日"——白色虹霓直冲太阳，本身就是光的折射现象，正合 Prism（棱镜）的立命之本；而刺客一剑破日的杀伐气，正合"用 Prism 写 CPU 是硬仗"。

        验收口径：三层测试台

        flag 立了，还得有"做完了"的定义。否则每一集都可以宣布自己完成了。这一日立的是三层，从里到外：

        最里层
        核内
        一颗器官、一条通路、一张号表——run 表的行内期望自判，golden 与 RTL 两条通路逐拍对撞，再加一发注入反证。便宜、秒级、每集都跑。
        中间层
        整机
        核 + 存储 + 地址图 + 镜像。判据不再看某根线，看退休序：pc / rd / 写回值逐条比。
        最外层
        外设
        芯片对上的世界：串口的 tx 内容与宿主喂进去的逐字节相同才算活着。到第 18 集才有这一层。

        还有一条从第二日就立着的规矩，它也是验收口径的一部分：换程序只换镜像，不换芯片。第 10 集已经兑现过一次——sort.c 重编、--image 一挂，cpu.prism 一个字没动。往后每一集都按这条交卷。

        小结

        • 五条差距，每条指得到具体代码：一拍做完所有事、1KB / 2KB 与 8 位地址、只有 M 态、没有中断、访存只有双字。
        • "一拍有多重"量出来了：六段串完至少 111 级；切成五段后最长一段 34 级。单位是门级单元个数，不是纳秒。
        • 量它之前先废了两把尺：全核 ltp -noff 报 11（比零件还小），不带 -noff 报 234（从 clk 起、穿过触发器）。能失败的判据才叫判据。
        • 靶子与验收口径都立在这条差距清单上——这一集没写一行新硬件，但后面每一集都得从这里领任务。
