        立 flag
        缺的三样

        第二日那颗核能排序、能跑真程序，三条通路逐拍对撞过。它跑不了 Linux——不是因为慢，是因为缺三样：MMU、S 态与 U 态、异常处理。这一集只把这三样讲清楚：少一样，Linux 的哪一步就落不下来。

        "天上要有光体，可以分昼夜、作记号、定节令、日子、年岁。" —— 《创世记》 1:14
        ← 第 11 集 · 第四方对撞：官方 sail 模型 第 13 集 · 五级流水线数据通路 →

        先分清"跑不了"和"跑得慢"

        把"造一颗能跑 Linux 的处理器"拆开，会发现里面混着两类完全不同的需求。一类是跑得快不快：流水线、cache、分支预测、指令密度。另一类是能不能跑：地址翻译、特权级、异常。第二类少一样，Linux 连第一条用户进程都起不来——再快也没用。

        第二日那颗核属于哪一类？把它的 design 摊开看，六颗实例、一百零四行连线：

        prismexamples/day2/cpu.prism · 六颗实例
        design CpuTop {
    // ==== 六颗实例 ====
    pc  : PC
    rf  : RegisterFile
    ex  : ALU
    im  : RAM<SIZE = 256, W = u32, A = u8>    // 指令侧：32 位字，1KB
    dm  : RAM<SIZE = 256, W = i64, A = u8>    // 数据侧：64 位字，2KB
    ctl : Decoder

    // ==== 取指：pc → im（异步读，同拍出指令）====
    wire iaddr : u8 = pc.addr[9:2] -> im.addr      // 字节地址 → 字地址
    wire instr : u32 = im.rdata -> ctl.instr

        这六颗里没有一颗管"这个地址属谁"，没有一颗管"这条指令有没有权限做这件事"，也没有一处接得住"出事了，去这里"。它缺的正好是第二类。这一集就把这三样一样一样点出来，每样都说清：Linux 的哪一步会踩空。

        第一缺：S 态与 U 态——机器分不清"谁在说话"

        RISC-V 的硬件特权级是 M / S / U 三层：M 给固件，S 给内核，U 给用户程序。第二日那颗核只有一层：没有 CSR，没有当前态这个概念。

        少这一层不是"权限粗一点"，而是三件事直接做不了：

        • 系统调用没有入口。用户程序用 ecall 请求内核——这条指令的含义是"我承认自己是低权限的一方，把控制权交给高权限的一方"。没有权限级别，ecall 就只是一条无意义的编码；没有 sepc / stvec，内核连"从哪儿回来的"都记不住。
        • 内核护不住自己。用户程序的一条 sd 就能写内核的数据段。Linux 的隔离不是软件纪律，是硬件在每次访存时做的判断。
        • 交棒没有落点。OpenSBI 跑在 M 态，把内核交给 S 态——这一脚靠 mret 读 mstatus.MPP 改态。没有 MPP，就没有"交出去"这个动作。

        这里要提前立一条诚实的规矩：本连载要造的那颗核，做到第五日也只有 M / S 两态——sret 恒回 S（源码注释直写"本核没有 U"）。U 态要等第 20 集把"谁能跳到哪一态"逐条画清楚才补上。所以这一集的话要说准：缺的不是"三层齐全"，缺的是"有层"。哪怕只加 M/S 两层，交棒与系统调用就已经能落了。

        第二缺：异常处理——Linux 的正常路径就是异常

        很多人把异常当成错误处理，其实 Linux 大量正常工作是靠异常完成的：

        Linux 的动作走的异常硬件要交出什么
        第一次碰栈、碰堆load / store 缺页（cause 13 / 15）出事的地址要能报出来（mtval / stval）
        时钟到点换进程中断（cause 带 bit63）：机器定时器 7、机器软件 3要有一根线打断正在跑的指令，并在精确的那一拍停下
        用户程序请求服务ecall（cause 8 / 9 / 11）按当前态报不同的号，内核才知道是谁在叫
        访问越界设备access fault（异常，bit63=0）：load 5 / store 7报地址，内核才能决定是杀进程还是补映射

        第二日那颗核连第一步都没有：Decoder 会把 is_illegal 拉高，顶层不拿这一位做门控。

        prismexamples/day2/cpu.prism · 这一台不做错误处理
            // ==== 这一台不做错误处理 ====
    // Decoder 会把 is_illegal 拉高，但顶层不拿这一位做门控：先让程序跑通，非法编码照样
    // 读、照样写回。把"不懂"变成一次异常跳转是第三日 CSR 与陷阱那一集的事。
    connect ctl.reg_wen -> rf.wen
    connect ctl.mem_wen -> dm.wen

        "没有地方可以去"是字面意思：没有 mtvec（去哪）、没有 mepc（从哪来）、没有 mcause（为什么）、没有 mtval（对哪个地址）。这四样凑不齐，缺页就只能变成死循环。

        还有一条最容易被低估：异常要冲掉比它年轻的指令。流水线里，出事那条指令在 MEM 定案时，前面已经有两条在飞。不冲，它们就会把一个"本该被杀掉的进程"的副作用写进存储器和寄存器堆。目标机器里这件事要冲到 EX、ID、IF 三级，这套冲刷逻辑第一次真正咬人，要等到第六日内核跑起来之后——那一发反证留到它自己的那一集。

        第三缺：MMU——没有虚拟地址，就没有"进程"这回事

        这颗核的地址是物理的、且只有一小块：取指只切 pc.addr[9:2] 那 8 位，1KB 指令、2KB 数据。而 Linux 的整个模型建立在"每个进程以为自己独占一整段地址"之上：

        • fork 与写时复制：父子共享同一份物理页，靠页表项的只读位与缺页异常才分家。没有页表，就没有"共享但看不见"这件事。
        • 加载一个 ELF：mmap 把代码、数据、栈、共享库摆在约定的虚拟地址上（0x…ffff… 那一带）。没有翻译，这些地址就是真地址，两个进程不可能都从同一个地址开始。
        • 内核自己：Linux 的线性映射区、vmalloc 区、设备 MMIO 的非缓存属性，全是页表属性（PTE 的 D/A/V 位与 PBMA）。
        • 保护：内核页对用户不可见，也是页表项的事，不是 S 态单独能做到的。

        RISC-V 这边对应的是 satp（模式 + 根页表号 + ASID）与 Sv39：39 位虚拟地址、三级页表、4KB 页。这颗核里 satp 连个影子都没有——它不是没接线，是没有任何东西可以被翻译。

        顺带把一件容易误会的事说清楚：加 MMU 不是加一张表。它至少带来三件新活——TLB（访存路径上先过一次快表，命中就不必走存储器里的页表）、PTW（硬件走页表，走不到就要报缺页，而缺页本身又是异常）、缺页要区分取指 / 读 / 写（cause 12 / 13 / 15，报的 mtval 也不同）。这三件在第五日各占一节。

        第四缺：几条指令根本发不出来

        前三样是机制，还有一样更底层：机制要靠指令去操作，而那些指令这颗核不认。第二日那颗核的许可表把 opcode 之外的字段也管住了，看一眼就知道缺了谁：

        prismexamples/day2/decoder.prism · 认不认这条编码
            // R 型族只认 funct7 = 0x00 / 0x20（0x01 是 M 扩展，这台不做）；
    // 立即数移位：shamt 占低 6 位，funct6 只许是 0x00（SLLI / SRLI）或
    // 0x10（bit 30 置起 = SRAI，仅 funct3=5）；
    // load / store 只认双字（LD/SD）；分支只认六个已定义编码。
    r_f7_ok  = funct7 in [0x00, 0x20]
    sh_ok    = (funct3 == 1) ? (funct6 == 0x00) : (funct6 in [0x00, 0x10])
    field_ok  = match opcode {
        0x33 => r_f7_ok,
        0x3b => r_f7_ok & (funct3 in [0, 1, 5]),
        0x13 => (funct3 in [0, 2, 3, 4, 6, 7]) | ((funct3 in [1, 5]) & sh_ok),
        0x1b => (funct3 == 0) | ((funct3 in [1, 5]) & sh_ok),
        0x03 => funct3 == 3,               // LD（这一颗 dm 就是 64 位字）
        0x23 => funct3 == 3,               // SD
        0x63 => funct3 in [0, 1, 4, 5, 6, 7],
        0x67 => funct3 == 0,
        0x37 => 1,
        0x17 => 1,
        0x6f => 1,
        _    => 0,
    }

        表里没有 0x73，它落进最后那条 _ => 0。这一族叫 SYSTEM，里面装着四类指令：CSR 读写（csrrw / csrrs / csrrc）、ecall 与 ebreak、wfi，还有 sfence.vma。

        没有 Zicsr，前面三样连一条指令都发不出来：mtvec 写不进去、mcause 读不出来、satp 根本开不了。所以它不是"再多支持一族"——它是其余三样的载体。而 sfence.vma 也在同一族里：改完页表要能告诉硬件"把翻译过的丢掉"，MMU 才算闭环。第四缺和第三缺，在编码上是同一个 opcode。

        剩下的按"缺了它 Linux 的哪一步落不下来"排：

        Linux 里谁在等要的指令 / 扩展缺了会怎样
        每一处临界区amoswap.w.aq（A）spin_lock 在 RISC-V 上就是一条原子交换。没有 A，锁只能靠关中断凑，多任务与 SMP 直接封死
        引用计数、无锁结构amoadd.d、lr.d / sc.d（A）同上：这是原子性，不是性能
        内核自己的浮点访存fsd / fld（D）不是"可选带上 FP"——RV64 的内核里这两条指令是无条件出现的（真机上实测过），没有 D 连启动路径都走不完
        时间源rdtime（Zicntr）+ mcounteren 放行读不到计数器，sched_clock 与 vDSO 只能一路问固件
        乘除mul / div（M）内核自带软除回退，所以严格说 M 不是门槛；但编译器只要看见带 M 的 target 就直接发指令，届时这台机器每次乘法都进一次陷阱
        不算门槛的那几样

        C（压缩码）省的是取指带宽与 I-cache 压力；Zba / Zbb（位运算）内核里有开关但可运行时退回；Zifencei（fence.i）要等 cache 装上才成为必需；Sstc（stimecmp）没有它 S 态定时器要走一次固件调用，慢而不是不能。这四样归"跑得更好"，登记在下一节，不占主线。

        这四样谁也离不开谁

        分开讲是为了点名，但做的时候分不开：缺页不是返回值，是一次异常；异常要分给内核还是固件，靠的就是特权级；而特权级那些状态，只能用 CSR 指令去读写。做 MMU 就必须做异常，做异常就必须做特权级，做特权级就必须先有 Zicsr。一环扣一环：

        MMU 出错
        就是一次异常
        缺页不是返回值，是陷阱：要报 cause、要报地址、要能回到那条指令重来一遍。
        异常要分去处
        就要有特权级
        委派给 S 态的（缺页、系统调用）走内核；留在 M 态的（固件自己）走 OpenSBI。没有层，就没有"委派"这个概念。
        特权级要能回
        就要有状态可存
        mstatus 的 MPP / SPP、*epc、*tvec——这是一堆跨段共享的状态，也就是 CSR 那一颗模块。
        前三样机制
        都要指令去操作
        写 mtvec、开 satp、失效 TLB，全落在同一个 opcode 0x73 里。所以 Zicsr 排在最前面做：它是其余三样的载体。

        所以第三日到第五日的顺序不是随便排的：先把节拍立起来（流水与冒险），再给核装上痛觉（CSR 与陷阱），最后把权限与翻译补齐（S 态、中断、MMU）。痛觉先于权限，是因为没有精确的陷阱点，权限做对了也没法验证。

        其余的差距：只列，不展开

        这些属于"跑得快不快 / 装不装得下"那一类（上一节末尾那四样扩展也算），各自有归属的集，这里只登记：

        差在哪这颗核的事实谁来补
        一拍做完所有事四颗部件各写 pipeline : 1 stage，顶层没有一颗段寄存器（on clock 出现 0 次）⇒ 取指到写回被 yosys 分段量出来是 111 级门，切成五段后最长一段 34 级EP 13 / 13
        装不下im 1KB、dm 2KB；OpenSBI 一个固件槽就是 0x48000（288KB）EP 17
        访存只有双字许可表里 0x03 => funct3 == 3、0x23 => funct3 == 3；lb / lh / lw 一律判非法EP 13 的 LSU
        压缩码与位运算没有 C（省取指带宽）、Zba / Zbb、Zifencei、Sstc——上一节已判定它们不是门槛EP 16 / 第五日
        没有中断源核端口里没有 mtip / msip / meip，也没有 mtimeEP 15
        每次访存都到主存没有 ICache / DCache——访存直接落到主存；目标机器上那两条 cache 也就是 256B 与 512B 的量级第五日条目
        跑不动长跑golden 逐拍解释，百万拍量级跑不完；也没有第四个独立裁判EP 20 / 21

        这一栏里唯一一处"数字"是 111 与 34。它怎么量出来的、为什么不能拿全核一个数当结论，全部收在 examples/day3/depth.sh 那二十行脚本里——跑一遍就有表，不必在这里读我的流水账。

        靶子与验收口径

        差距列完了，靶子就是它的反面。这一日之后要到手的：

        • 五级流水，段与段之间四组段寄存器，冒险由一处裁决（EP 13 / 13）。
        • CSR 与陷阱：号表、mstatus 的 WARL、mtvec / mepc / mcause / mtval、进与退（EP 15）。
        • S 态与系统调用、CLINT / PLIC 中断（EP 15、EP 19）。
        • MMU 与 Sv39、PMP（第五日）。
        • 指令面：Zicsr 随 CSR 一起落地，A 与 D 是硬门槛，M / C 是密度与性能；完整访存宽度、128MB 量级的存储与一张字节口径的地址图（EP 16、EP 17）。

        验收口径也在这一日立起来，后面每一日都按它交卷。三层测试台：核内（tests/test_cpu.py——31 个用例、411 次断言，形态是"run 表的行内期望自判 + golden / RTL 双通路 + 变异反证"）、整机（tests/test_soc.py——镜像装载、交棒、控制台）、外设（uart 与宿主对端）。跑什么由 --image 决定，芯片一个字不改——这条规矩第二日第 10 集已经兑现过一次。

        白虹（Whitebow）

        名字的由来

        这颗核从这一日起有一个正式的名字：白虹，英文 Whitebow。典出《战国策·魏策》"聂政刺韩傀，白虹贯日"——白色虹霓直冲太阳，本身就是光的折射现象，正合 Prism（棱镜）的立命之本；而刺客一剑破日的杀伐气，正合"用 Prism 写 CPU 是硬仗"。

        小结

        • "跑不了 Linux"和"跑得慢"是两件事。第二日那颗核属于前者。
        • 四样缺的：S / U 态（分不清谁在说话）、异常处理（缺页、时钟、系统调用都是 Linux 的正常路径）、MMU（没有虚拟地址就没有进程）、指令面（0x73 这一族不认：Zicsr 是前三样的载体；A 是锁；D 是内核无条件发的 fsd / fld）。
        • 这四样谁也离不开谁：缺页是一次异常 → 异常要分去处就要有特权级 → 特权级要能回就要有跨段共享的状态 → 而这些状态只能用 csrrw 这类指令去读写。做一样就得做四样。
        • 顺序因此定了：先节拍（流水、冒险），再痛觉（CSR 与陷阱——它顺带把 Zicsr 带进来），最后权限与翻译（S 态、中断、MMU 与 sfence.vma）。
        • 其余差距（流水、访存宽度、存储、cache、长跑、C 与 Zb*）各自有归属，登记在案，不抢主线。
