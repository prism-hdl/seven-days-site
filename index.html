为什么要有这门语言

硬件开发有两条割裂的路：RTL（Verilog / SystemVerilog / VHDL）周期精确、可综合，但算法与微架构缠在一起；SystemC / TLM 事务级、快数个数量级，但不可综合。两条路描述同一个硬件、要各写一遍——行为等价性没有编译器的保证。HLS 只补了"算法 → RTL"这一半，输入还得是可综合子集，产不出用于架构探索的 TLM 快模型。

还有一层更深的：对写了十年 Rust / TypeScript / Python 的人来说，Verilog 不像在想电路——没有类型、没有泛型、没有模式匹配，位宽靠数数、符号靠人脑记。

Prism 同时回应这两层：一份源码，同时下降为 RTL + TLM + 独立 Python golden，三方 cosim 闭环逐拍对撞；而语言本身类型驱动、显式时钟域、分层清晰。

结构层
一份源码三下降
同一份 .prism，编译器分别产出可综合 SV、SystemC/TLM、独立 Python 参考——差异即报错。
表达层
类型驱动
Signal<u32> 就是 32 位无符号；i1 只能取 {-1, 0}；截断永远显式。
验证层
行级期望
激励表行尾 [...] 直接写手算值——跑一次就是一次自判定。

快速上手

Prism 编译器已打包为 pip 包，装好后全局命令 prism 即可使用。cosim 对撞需要 iverilog——prism deps --install 会按操作系统补齐。

bash30 秒跑通第一个模块
pip install prism-hdl
prism deps --install               # 按操作系统补齐仿真依赖（iverilog / SystemC 等）

git clone https://github.com/prism-hdl/seven-days
cd seven-days

prism run examples/adder.prism --debug

输出会是一张逐拍的表，外加一条 # expect: 3/3 拍有断言 · 1 列 · 全等 ✅——那张表里的期望值是手写进源码的，不是事后补的。

一行代码都不信，直到它在两个后端上跑出同一个数。
prism run 出 Python 参考模型；prism cosim 把 SV 真仿真拉来逐拍对撞（iverilog）；--sim systemc 再拉上第三条通路。三条通路喂同一份激励，逐拍逐列对撞。
